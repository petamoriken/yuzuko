# Specification deviations

Intentional divergences from the web platform and WinterTC. When an implementation differs from a specification, add a row to the table for that area in the same change. An unimplemented API must not succeed as a no-op. Leave it absent, or throw `NotSupportedError`.

## Document and realm

| Area | Deviation |
| --- | --- |
| Document | There is no `document`, DOM tree, or `HTMLCanvasElement`. Drawing uses `OffscreenCanvas` |
| Contexts | `getContext("webgl")` and `getContext("webgl2")` return `null` |
| Namespaces | Web standards and WinterTC live on `globalThis`. Runtime-specific APIs live on `Yuzuko`. There is no global `Window` constructor |
| `console` | `console.table` prints like `log` and does not draw a grid. `dir` and `dirxml` print like `log`. `groupCollapsed` does not hide the following lines. Object text is the inspector in `docs/spec.md` |
| `Object.prototype.__proto__` | The Annex B accessor is deleted before user code runs, in the main realm, a dedicated worker, and an `AudioWorklet` processor realm. `{ __proto__: null }` in an object literal still sets [[Prototype]]. `Object.getPrototypeOf` and `Object.setPrototypeOf` still work. Reading or assigning `obj.__proto__` uses an own property when one exists, and an assignment creates one, so `Object.assign` of `JSON.parse('{"__proto__": null}')` leaves [[Prototype]] unchanged. There is no flag that restores the accessor |
| Idle callbacks | `requestIdleCallback`, `cancelIdleCallback`, and `IdleDeadline` are own properties of the main `globalThis`, not inherited from a `Window` prototype. Dedicated workers do not have them. There is no document, so a hidden window does not throttle idle periods. An idle period waits while the next timer, host task, or window frame is under 5ms away |
| `navigator.userAgent` | `Yuzuko/<version>` |
| High-resolution time | `performance.now()` and event `timeStamp` are not coarsened to 100 µs or 5 µs. This process is not a cross-origin browser context |
| Threads | A dedicated worker runs on its own thread and enters only its own V8 isolate. winit stays on the main thread. wgpu stays on the thread that created the device. Other background work posts completions to a task queue and does not call V8 |
| Permissions | Host read, write, net, env, run, and ffi access follows Permissions in `docs/spec.md`. The status is a plain `{ state }` object on `Yuzuko.permissions`. `yuzuko run` asks on a terminal when the grant is missing and `--no-prompt` is absent. `yuzuko repl` installs that sandbox and does not ask, and it does not read `yuzuko.json`. `yuzuko test` installs that sandbox and does not ask, and it does not read `yuzuko.json`. A packaged application with a `permissions` object does not ask, and an omitted name is denied. A packaged application that omits the key, and a process that never installs a policy, allows every check. A denied call throws `Yuzuko.errors.NotCapable`, an `Error` and not a `DOMException`. Operating-system permissions still apply, and a packaged application cannot modify its bundle. Signals, `args`, `cwd`, and `exit` are not checked. A JavaScript, TypeScript, or WebAssembly evaluation import is not a read check when every resolved form is that kind of file. Any other file is not read. An import with type text, bytes, or json requires read. A `file:` worker script and a `file:` `importScripts` load require read. A worker URL for `127.0.0.1`, `localhost`, or `web-platform.test` loads the entry-directory file for that path and requires the same read, including the canonical target of a symlink. A path check also includes the file the operating system opens when `..` follows a symlink, so a directory grant does not cover that file. `stat`, `lstat`, and `remove` name the directory entry and do not require the final symlink's target. `stat` still reports that target. `remove` with `recursive: true` is denied when a descendant is denied. The denial names the requested path, and an import rejection names the path the importer wrote. `data:` and `blob:` worker scripts are not a read check. Each redirect that `fetch`, `XMLHttpRequest`, or `importScripts` follows is checked again, and a denied hop throws `NotCapable`. `spawn` requires env access for the whole environment. A bare run rule matches only a bare command name, and only the executable that name had on `PATH` when the policy was installed. A command with no separator does not match a path rule. A path run rule matches the file the operating system would execute. A prompt answer and `revoke` for a command that contains a separator store the absolute path resolved when the answer is read, and a later check uses that stored path. `spawn` rejects an `LD_` or `DYLD_` variable unless `run` is granted as a whole. A rule for the collapsed path does not match when `..` follows a symlink and would run a different file. A grant of a symlink does not run a different target. A relative program is resolved from `options.cwd` when that option is set. `cwd` is checked before the operating system reports whether the directory exists. Optional surfaces are chosen when that app's runtime is built. The default build enables `fetch`, `fs`, `socket`, `udp`, `tcp`, `http`, `signal`, `child`, `ffi`, `window`, `accessibility`, `image`, `canvas`, `webgpu`, `audio`, and `codec`. `cargo build -p yuzuko --no-default-features` is the JavaScript runtime: `AbortController`, events, URL, encoding, `Blob`, streams, `FormData`, `crypto`, workers, and timers stay. The `Yuzuko` object stays, and the feature surfaces are absent on the main global and in a dedicated worker. `--no-default-features --features name` selects a subset. `fetch` and `socket` are independent. `image`, `canvas`, `webgpu`, `codec`, and `accessibility` enable `window`. `Yuzuko.autoUpdate` keeps its own feed client and checks the net permission before it connects |
| `Yuzuko.test` | Installed only for `yuzuko test`. Absent during `yuzuko run`. There is no op or resource sanitizer |
| `Yuzuko.build` | Present on the main realm and in a dedicated worker in every build, including `yuzuko run`, `yuzuko repl`, `yuzuko test`, and a packaged application. The object is frozen. `os` is `darwin` on macOS. `standalone` is `true` for a packaged application and `false` for `yuzuko run`, `yuzuko repl`, `yuzuko test`, and `yuzuko package`. An `AudioWorklet` processor context does not have `Yuzuko` |
| `Yuzuko.version` | Present on the main realm and in a dedicated worker in every build. The object is frozen. The own enumerable names are `yuzuko` and `v8`. There is no `typescript` field. `pid` and `ppid` are writable data properties captured when the realm starts |
| `Yuzuko.memoryUsage`, `Yuzuko.noColor`, `Yuzuko.refTimer`, `Yuzuko.unrefTimer` | These names are on `Yuzuko` in the main realm and in a dedicated worker in every build. There is no `Deno` global. `memoryUsage` returns a new object whose own enumerable names are `rss`, `heapTotal`, `heapUsed`, and `external`. `rss` is the process resident set. The heap figures are the isolate running the call, so a dedicated worker reports its own heap. `noColor` is the process-start `NO_COLOR` snapshot: a non-empty value is `true`, and an absent or empty value is `false`. `FORCE_COLOR` does not change it. A later `Yuzuko.env.set` or `Yuzuko.env.delete` of `NO_COLOR` does not change a later read. `refTimer` and `unrefTimer` take the number `setTimeout` or `setInterval` returned. Deno also accepts a `Timeout` object. An unknown id, a non-positive id, or a value that does not convert with ToInt32 does nothing and does not throw. An unreferenced timer does not keep the process alive, including one whose delay has already elapsed. It still runs when something else does, including a dedicated worker that has not closed. That worker's next wait includes the deadline. `clearTimeout` and `clearInterval` still cancel it. A new timer starts referenced |

## Window and input

| Area | Deviation |
| --- | --- |
| `matchMedia` | `Yuzuko.Window.matchMedia` follows this window's CSS size and `devicePixelRatio`. `media` is the query text passed in. `pointer` is `fine`. On macOS, `color-gamut` is `p3` when the main display can represent Display P3, otherwise `srgb`. `rec2020` does not match. `prefers-color-scheme` follows the window theme. `prefers-reduced-motion: reduce` follows Accessibility's Reduce Motion setting. `prefers-contrast` is `more` when Increase Contrast is on, and `no-preference` otherwise. `less` and `custom` do not match. On Windows, `prefers-reduced-motion: reduce` matches when Animation effects is off (`SPI_GETCLIENTAREAANIMATION`), `prefers-contrast` is `more` while a contrast theme is on (`HCF_HIGHCONTRASTON`), and before a window reports its theme the scheme is the apps mode (`AppsUseLightTheme`). There is no `forced-colors` feature. Windows and Linux report `srgb`. Linux reports `no-preference` for motion and contrast and the winit theme when a window exists. There is no `hover`, `any-pointer`, or `scripting` feature. Workers have no `matchMedia` |
| Windows | `new Yuzuko.Window(options)` extends `EventTarget`. `surface` is a `Yuzuko.WindowSurface`, not an `OffscreenCanvas`. An unrecognized `objectFit`, `imageRendering`, or `cursor` value is ignored, and those keywords are case-insensitive. `resizable` defaults to `false` and assigning it updates the live window. Startup creates no implicit window. `x` and `y` place the frame origin in CSS pixels; omitting both centers it on the primary monitor, or uses `0, 0` when no monitor exists. Setting only one of `x` or `y` uses `0` for the other. `screenX` and `screenY`, with aliases `screenLeft` and `screenTop`, and `innerX` and `innerY`, are the client origin. `outerX` and `outerY` are the frame origin. `moveTo` and `moveBy` move that frame. `resizeTo` and `resizeBy` change the client size, which is what CSSOM calls the viewport. `show`, `hide`, and `visible` control OS visibility and do not by themselves change occlusion `visibilityState`. `focus` focuses the window. `alwaysOnTop` can change after creation. `decorations` and `active` default to `true` and are creation-only. `active: false` skips the initial focus; it is not a separate non-activating panel. `visible` defaults to `true`. `maximized` defaults to `false` and is not fullscreen. `minWidth`, `minHeight`, `maxWidth`, and `maxHeight` are optional client-size limits. An omitted maximum edge is unset in script; when only one maximum is set, the OS limit for the other edge is 100000 CSS pixels. `resizeTo` and `resizeBy` clamp to those limits. `transparent` defaults to `false` and is creation-only. It asks the OS to composite alpha. macOS clears the window background. Windows uses Desktop Window Manager. Wayland and X11 need a compositor. Unpainted pixels are clear. A fitted bitmap's uncovered area is clear instead of black. The swapchain uses premultiplied alpha when the surface offers it. There is no `reload` |
| Frames | `requestAnimationFrame` on a `Yuzuko.Window` is per window. The main global has no `requestAnimationFrame`. A dedicated worker has `requestAnimationFrame` and `cancelAnimationFrame`; after those callbacks, each transferred window canvas is copied into the window that owns it. The rendering update presents that surface. Frames are not throttled while `visibilityState` is `"hidden"`. After the window is closed, `requestAnimationFrame` returns `0` and does not queue the callback. HTML returns a new handle and stores the callback. A dedicated worker's frame period is the slowest refresh rate among the open windows whose canvas that worker holds, or 60 Hz when it holds none. HTML uses the owner document's rendering opportunity. A reported monitor rate below 10 Hz or above 1000 Hz is treated as 60 Hz. A Canvas 2D change, a `bitmaprenderer` update, a bitmap copied from a worker frame, and a change to `objectFit` or `imageRendering` are presented on the next event-loop turn, including while the surface is hidden. That present does not queue an animation frame. HTML waits for a rendering opportunity and does not paint a hidden document |
| `visibilityState` | `WindowSurface.visibilityState` is `"visible"` or `"hidden"`. It follows winit occlusion, so a minimized or fully covered window is `"hidden"`. Focus loss does not change it. Platforms without `WindowEvent::Occluded` stay `"visible"` until the window closes. There is no `document.hidden` or `document.visibilityState` |
| Input | Pointer events and the mouse events derived from them target `WindowSurface` and propagate through `Window`. `stopPropagation` and `stopImmediatePropagation` follow that path. Key, IME, wheel, focus, blur, resize, and close target the `Window` only. `focus` and `blur` are `FocusEvent`s and do not bubble. `pointerId` is per window. `pointerrawupdate` is dispatched for each pointer move, including motion reported while the pointer is locked, before the `pointermove` for those samples. It bubbles and is not cancelable. `getCoalescedEvents()` on it returns one `pointerrawupdate`. There is no `onpointerrawupdate` event-handler attribute. There is no non-secure context, so the event is not suppressed. Upstream tests that need a document, an element tree, or `test_driver` stay ignored. `Touch`, `TouchList`, and `TouchEvent` can be constructed. A synthetic `TouchEvent` is not cancelable unless `cancelable` is true. The runtime does not dispatch a trusted touch event. Touch contact is a `PointerEvent` with `pointerType` `"touch"`. `layerX` and `layerY` match `offsetX` and `offsetY`. There is no stacking context. A host `wheel` event has `momentum` false. The runtime does not synthesize scroll inertia. `DragEvent` can be constructed and does not start an HTML drag-and-drop session. `navigator.maxTouchPoints` counts connected touch screens and does not count a trackpad. A touch screen that does not report a maximum counts as 1. Pointer Events returns 0 when that maximum is unknown |
| Size | `Window` `width` and `height` are device pixels and track the drawable. `clientWidth` and `clientHeight` are CSS pixels |
| IME | Disabled by default. `setImeAllowed` and `setCompositionCaret` are `Window` methods |
| Pointer lock | `requestPointerLock` and `exitPointerLock` belong to that surface, and so do the change events |
| Keyboard lock | `navigator.keyboard.lock` and `unlock` are on the main global when `window` is enabled. A dedicated worker does not have `keyboard` or `Keyboard`. There is no document, permission prompt, or secure-context gate. `lock` settles in the same turn and does not reject an earlier call with `AbortError`. Fullscreen is not required. Escape held for two seconds does not show an overlay and does not leave fullscreen. A code is accepted when this runtime can report it as `KeyboardEvent.code`. `getLayoutMap` and `layoutchange` are absent. A headless process stores the reservation and does not change operating-system shortcuts. macOS uses `PushSymbolicHotKeyMode(kHIHotKeyModeAllDisabled)` only when the list is empty or contains Escape, Tab, Space, MetaLeft, or MetaRight. Command-Tab and Command-Option-Escape stay with the system, and the mode does not change without assistive access. Windows uses a `WH_KEYBOARD_LL` hook that swallows a reserved key only while this process's window is foreground, then posts the key to that window. Ctrl+Alt+Delete is not visible to the hook. Linux calls `XGrabKeyboard` only for an empty list on X11. Wayland does not grab. Blur drops the inhibitor and keeps the reservation. Closing the focused window unlocks |
| Fullscreen | `requestFullscreen` and `exitFullscreen` belong to that surface |
| Title and cursor | The constructor `title` sets the initial OS window title. `WindowSurface.title` reads and writes it. `Window` has no `title` attribute. There is no `document`, so there is no `document.title`. The default is `"yuzuko"`. `cursor` is a `Window` attribute |
| Gamepad | `navigator.getGamepads()` and `gamepadconnected` / `gamepaddisconnected` are on `globalThis`. There is no secure-context gate, permissions policy, or document, so a disconnected document does not suppress the list and a hidden document does not stop haptics. An already-connected device is exposed without waiting for a button press. `touches` stays empty, `pose` is null, and `hand` is `""`. `effects` lists `"dual-rumble"` only when that device can play force feedback. `trigger-rumble` rejects `NotSupportedError`. `playEffect` rejects `InvalidStateError` when the gamepad is disconnected, before parameter checks. `duration` and `startDelay` use WebIDL `unsigned long long` conversion, and their sum is capped at 5000 ms. gilrs plays motors in 50 ms ticks; the promise settles on the capped timeline and then stops the effect. Disconnecting a gamepad stops a playing effect and resolves that promise with `"preempted"`. `reset` resolves `"complete"` while the gamepad is connected |
| Clipboard | `navigator.clipboard` `read` / `readText` / `write` / `writeText` require a pointer or key press on the focused `Window` within five seconds. There is no permission prompt and no secure-context gate. `ClipboardItem` accepts `text/plain` and `image/png` only. A malformed type string throws `TypeError`. Any other type throws `NotSupportedError`. Text is published to the OS pasteboard. `image/png` is stored as the written bytes and also published as an image when the PNG decodes. `copy`, `cut`, and `paste` are `ClipboardEvent`s on the focused surface for Ctrl/Cmd+C, X, and V. Host `copy` and `cut` carry an empty read/write `DataTransfer`. Host `paste` carries a read-only `DataTransfer` whose `text/plain` entry is the same cache as `readText`, including `""`, and is absent when that cache has no text. The paste store does not expose `text/html` or `image/png`. A cancelled host `copy` or `cut` publishes `text/plain` only, including `""`, and leaves the pasteboard unchanged when that entry is absent. Other `setData` formats stay on the event. A script-constructed `ClipboardEvent` does not write the pasteboard. `items`, `files`, `setDragImage`, `DataTransferItem`, and `DataTransferItemList` are absent. The store stays readable after the event. `ClipboardChangeEvent` fires for a successful `write` or `writeText`, and on macOS and Windows when the OS pasteboard changes. `types` lists `text/plain`, `text/html`, and `image/png` only, in that order. This runtime's `write` does not store `text/html`. On Windows a DIB is reported as `image/png`. `changeId` is the pasteboard sequence on macOS and Windows, and a process-local counter on Linux. Linux does not observe other applications' clipboard changes. A change while no window is focused is delivered once after the next `focus`. WPT files that need `test_driver`, a document, an iframe, a permission prompt, or a permissions policy fail as a file |
| Screen Wake Lock | `navigator.wakeLock` is on the main global when the `window` feature is enabled. A dedicated worker does not have `wakeLock` or `WakeLock`. There is no document, permission prompt, permissions policy, or secure-context gate. Hiding a window does not release a sentinel. Every sentinel shares one platform assertion. macOS uses `IOPMAssertionCreateWithName` with type `PreventUserIdleDisplaySleep` and name `Yuzuko`. Files that need a document or a permissions policy stay ignored or fail as recorded |
| Dialogs | `Yuzuko.Window.alert`, `confirm`, and `prompt` are native modal dialogs for that window. They are not global `alert`, `confirm`, or `prompt`, and there is no `<dialog>`. A headless process throws `NotSupportedError`. Button labels start as OK, Cancel, Open, Save, and Select. `Yuzuko.setDialogLabels` replaces the labels the runtime draws and does not open a dialog. A dedicated worker does not have it. macOS alert, confirm, and prompt use `ok` and `cancel`. The Windows prompt uses them. Linux alert, confirm, prompt, and the file chooser use the configured labels instead of GTK stock buttons. Windows alert and confirm stay on `MessageBox` in the operating-system language. macOS and Windows file and directory dialogs keep the system buttons. The message and the title are not translated. `prompt` returns `null` when cancelled and `""` when the field is cleared and accepted. Linux uses GTK 3 and does not parent the dialog to the winit window. `pickFiles` is the only file dialog. `mode` is `"open"`, `"save"`, or `"directory"`, and an omitted mode is `"open"`. It is synchronous and returns absolute paths, or `null` when cancelled or the selection is empty. `"open"` with `multiple: false`, `"save"`, and `"directory"` each return a one-element array. There is no `pickSaveFile` and no `pickDirectory`. The Linux chooser is unparented. A headless process throws `NotSupportedError`. `"directory"` can create a directory. macOS uses `NSOpenPanel` and selects directories only. Linux uses an unparented GTK 3 `SelectFolder` chooser. Windows uses `SHBrowseForFolder`, parented to the window, with `BIF_RETURNONLYFSDIRS | BIF_NEWDIALOGSTYLE | BIF_EDITBOX`, and sets the caption to the window title. There is no File System Access API. macOS applies the union of the extensions and does not show a separate choice for each `name`. A filter whose extensions contain `*` may sit beside other filters. Windows and Linux show that filter as its own choice. If any filter is `*` or `filters` is omitted, macOS allows every file |
| File drop | `filehover`, `filehovercancel`, and `filedrop` are dispatched on `Yuzuko.Window`. They do not bubble. The event does not carry a `DataTransfer`. There is no HTML drag-and-drop, and `filedrop` is not a `DragEvent`. `paths` are absolute and are not canonicalized. Consecutive files from one hover or one drop become one event. | Menu bar | `Yuzuko` is an `EventTarget`. `Yuzuko.Menu` and `Yuzuko.setMenu(menu)` install one application menu. ## Drawing

| Area | Deviation |
| --- | --- |
| Canvas 2D execution | `CanvasRenderingContext2D.lang` defaults to `"inherit"`. There is no document and no `<canvas>` element, so `"inherit"` and `""` both shape with an unknown language. `direction` defaults to `"inherit"` and, with no document, is shaped left to right. `small-caps` in the `font` shorthand is serialized and does not select small-cap glyphs. `cursive` and `fantasy` are stored in the family list and are not shaping families. A tag the text stack cannot parse is stored and shaped as unknown. The rasterizer paints sRGB unorm8. `Yuzuko.canvasRenderer` is `"gpu"` or `"cpu"`. `YUZUKO_CANVAS` can pin it. `getContext` and `ImageDataSettings` reject `"srgb-linear"` and `"display-p3-linear"` with `TypeError`. `display-p3` and `float16` stores keep `putImageData` and matching `drawImage` samples. An opaque axis-aligned solid `fillRect` on a float16 store is written in that store's color space at float16 precision, including encoded components outside 0..1. Other path, text, and gradient paints are converted from that sRGB unorm8 result. `imageSmoothingEnabled: false` samples nearest. `"low"` samples bilinear. `"medium"` samples bicubic. `"high"` prefilters a scaled `drawImage` with Lanczos-3 when the axis-aligned scale is outside about 2% of 1:1, then paints that bitmap bilinearly. That 1:1 case uses bilinear sampling for every quality. A pattern has no destination size when it is recorded, so `"medium"` and `"high"` both sample bicubic. A layer bitmap stays nearest. Float16 images and resample targets whose edge exceeds 8192 or whose area exceeds 8 million pixels fall back to bicubic. A list uses the first loaded family from that realm's `FontFaceSet` (`Yuzuko.fonts` on the main global, `self.fonts` in a worker), or else the first of `sans-serif`, `serif`, and `monospace`. A size that names only an unregistered family is stored and shaped as `sans-serif` |
| Presentation | wgpu 29 has no `SurfaceColorSpace`. The swapchain uses an explicit unorm8 format, preferring `Bgra8Unorm` or `Rgba8Unorm`. Display P3 and float16 canvases are quantized to that sRGB image. A float16 surface is not configured |
| WebGPU device | One process `wgpu::Device` is shared with Canvas 2D. The device is created with `timestamp-query`, wgpu timestamp writes inside encoders and passes, `depth-clip-control`, `depth32float-stencil8`, and wgpu external textures when the adapter supports each of them. Device creation retries with that timestamp set alone, then with no optional features, if a larger set fails. `requestDevice` rejects a feature the shared device does not have, and rejects `requiredLimits` the shared device cannot satisfy. Other optional features stay off. `destroy` loses that JavaScript device only. `GPUDevice.lost` resolves from `destroy`, not from garbage collection. `wgslLanguageFeatures` contains `readonly_and_readwrite_storage_textures`, `packed_4x8_integer_dot_product`, and `pointer_composite_access`. Published limits are the shared device's wgpu defaults, so `maxBindGroupsPlusVertexBuffers` can be below the WebGPU minimum. A downlevel adapter that cannot meet those defaults, such as the GL driver in WSLg with two color attachments, gets a device with the adapter's own limits, and those are published. An uncaptured error is dispatched as `uncapturederror` on every live JavaScript `GPUDevice`, because they share one wgpu device. An out-of-range copy can dispatch one event from the command encoder and another from `queue.submit`. When no wrapper is alive the error is printed |
| WebGPU canvas | `getCurrentTexture` returns the same `GPUTexture` until that surface's rendering update. An `OffscreenCanvas` that is not a window's `surface` has no frame, so the texture stays until `unconfigure`, resize, or disposal. Canvas textures also get `TEXTURE_BINDING`, `COPY_SRC`, and `RENDER_ATTACHMENT` so the present blit and readback can use them. `alphaMode` `"opaque"` and `"premultiplied"` are stored; presentation blits stored texels and does not composite. `display-p3` is accepted and `copyExternalImageToTexture` converts into `"srgb"` or `"display-p3"`, but the swapchain present is still unorm8 sRGB. `GPUCanvasContext.label` stays `""` |
| WebGPU copy | `copyExternalImageToTexture` uploads with `queue.writeTexture`. Matching unorm8 bytes upload directly. A float16 source, a color-space change, a sub-rectangle, or a `bgra8unorm` destination is converted on the CPU. `getMappedRange` returns a copy of the mapped bytes. `unmap` writes a write-only mapping back and detaches that `ArrayBuffer`. A mapping that sets both read and write is mapped for reading, and `unmap` writes it back with `queue.writeBuffer`, so that buffer also needs `COPY_DST`. `destroy` detaches without writing back |
