# Specification deviations

Intentional divergences from the web platform and WinterTC. When an implementation differs from a specification, add a row in the same change. An unimplemented API must not succeed as a no-op. Leave it absent, or throw `NotSupportedError`.

| Area | Deviation |
| --- | --- |
| Document | There is no `document`, DOM tree, or `HTMLCanvasElement`. Drawing uses `OffscreenCanvas` |
| Contexts | `getContext("webgl")` and `getContext("webgl2")` return `null` |
| Namespaces | Web standards and WinterTC live on `globalThis`. Runtime-specific APIs live on `Yuzuko`. There is no global `Window` constructor |
| `console` | `console.table` prints like `log` and does not draw a grid. `dir` and `dirxml` print like `log`. `groupCollapsed` does not hide the following lines. Object text is the inspector in `docs/spec.md` |
| `Object.prototype.__proto__` | The Annex B accessor is deleted before user code runs, in the main realm, a dedicated worker, and an `AudioWorklet` processor realm. `{ __proto__: null }` in an object literal still sets [[Prototype]]. `Object.getPrototypeOf` and `Object.setPrototypeOf` still work. Reading or assigning `obj.__proto__` uses an own property when one exists, and an assignment creates one, so `Object.assign` of `JSON.parse('{"__proto__": null}')` leaves [[Prototype]] unchanged. There is no flag that restores the accessor |
| `matchMedia` | `Yuzuko.Window.matchMedia` follows this window's CSS size and `devicePixelRatio`. `media` is the query text passed in. `pointer` is `fine`. On macOS, `color-gamut` is `p3` when the main display can represent Display P3, otherwise `srgb`. `rec2020` does not match. `prefers-color-scheme` follows the window theme. `prefers-reduced-motion: reduce` follows Accessibility's Reduce Motion setting. `prefers-contrast` is `more` when Increase Contrast is on, and `no-preference` otherwise. `less` and `custom` do not match. On Windows, `prefers-reduced-motion: reduce` matches when Animation effects is off (`SPI_GETCLIENTAREAANIMATION`), `prefers-contrast` is `more` while a contrast theme is on (`HCF_HIGHCONTRASTON`), and before a window reports its theme the scheme is the apps mode (`AppsUseLightTheme`). There is no `forced-colors` feature. Windows and Linux report `srgb`. Linux reports `no-preference` for motion and contrast and the winit theme when a window exists. There is no `hover`, `any-pointer`, or `scripting` feature. Workers have no `matchMedia` |
| Windows | `new Yuzuko.Window(options)` extends `EventTarget`. `surface` is a `Yuzuko.WindowSurface`, not an `OffscreenCanvas`. Its bitmap does not follow later resizes. `transferControlToOffscreen()` hands an `OffscreenCanvas` to a worker; the surface itself cannot be transferred. `objectFit` is `none`, `contain`, `cover`, `fill`, or `scale-down` (default `scale-down`); the window outside that rectangle is black. `imageRendering` is `auto` (default), `smooth`, `crisp-edges`, or `pixelated`. `auto` and `smooth` are bilinear. `crisp-edges` is nearest-neighbor. `pixelated` uses nearest-neighbor to the nearest integer scale, then bilinear to the final size. An unrecognized `objectFit`, `imageRendering`, or `cursor` value is ignored, and those keywords are case-insensitive. `resizable` defaults to `false` and assigning it updates the live window. Startup creates no implicit window. `x` and `y` place the frame origin in CSS pixels; omitting both centers it on the primary monitor, or uses `0, 0` when no monitor exists. Setting only one of `x` or `y` uses `0` for the other. `screenX` and `screenY`, with aliases `screenLeft` and `screenTop`, and `innerX` and `innerY`, are the client origin. `outerX` and `outerY` are the frame origin. `moveTo` and `moveBy` move that frame. `resizeTo` and `resizeBy` change the client size, which is what CSSOM calls the viewport. `show`, `hide`, and `visible` control OS visibility and do not by themselves change occlusion `visibilityState`. `focus` focuses the window. `alwaysOnTop` can change after creation. `decorations` and `active` default to `true` and are creation-only. `active: false` skips the initial focus; it is not a separate non-activating panel. `visible` defaults to `true`. `maximized` defaults to `false` and is not fullscreen. `minWidth`, `minHeight`, `maxWidth`, and `maxHeight` are optional client-size limits. An omitted maximum edge is unset in script; when only one maximum is set, the OS limit for the other edge is 100000 CSS pixels. `resizeTo` and `resizeBy` clamp to those limits. `transparent` defaults to `false` and is creation-only. It asks the OS to composite alpha. macOS clears the window background. Windows uses Desktop Window Manager. Wayland and X11 need a compositor. Unpainted pixels are clear. A fitted bitmap's uncovered area is clear instead of black. The swapchain uses premultiplied alpha when the surface offers it. There is no `reload` |
| Frames | `requestAnimationFrame` on a `Yuzuko.Window` is per window. The main global has no `requestAnimationFrame`. A dedicated worker has `requestAnimationFrame` and `cancelAnimationFrame`; after those callbacks, each transferred window canvas is copied into the window that owns it. The rendering update presents that surface. Frames are not throttled while `visibilityState` is `"hidden"`. After the window is closed, `requestAnimationFrame` returns `0` and does not queue the callback. HTML returns a new handle and stores the callback. A dedicated worker's frame period is the slowest refresh rate among the open windows whose canvas that worker holds, or 60 Hz when it holds none. HTML uses the owner document's rendering opportunity. A reported monitor rate below 10 Hz or above 1000 Hz is treated as 60 Hz. A Canvas 2D change, a `bitmaprenderer` update, a bitmap copied from a worker frame, and a change to `objectFit` or `imageRendering` are presented on the next event-loop turn, including while the surface is hidden. That present does not queue an animation frame. HTML waits for a rendering opportunity and does not paint a hidden document |
| Idle callbacks | `requestIdleCallback`, `cancelIdleCallback`, and `IdleDeadline` are own properties of the main `globalThis`, not inherited from a `Window` prototype. Dedicated workers do not have them. There is no document, so a hidden window does not throttle idle periods. An idle period waits while the next timer, host task, or window frame is under 5ms away |
| `EventSource` | `withCredentials` is stored and does not change the request. There is no cookie jar and no CORS check. A scheme other than `http` or `https` throws `SyntaxError` |
| `WebSocket` | `extensions` stays empty. There is no permessage-deflate. `wss:` trusts the webpki root set, so the WPT server certificate fails. The second constructor argument follows the open `WebSocketInit` dictionary proposal: a string, a sequence, or `{ protocols, targetAddressSpace }`. `targetAddressSpace` must match the connected address exactly (`loopback`, `local`, or `public`). `WebSocketStream` uses that connection as streams. Binary chunks are `Uint8Array` values, not `Blob`s. An `AbortSignal` aborts only the handshake. A handshake failure rejects both `opened` and `closed`, and those rejections are marked handled so a caller that observes only one of them does not also get an unhandled rejection |
| `WebTransport` | `WebTransport` is on `globalThis` in the main realm and in a dedicated worker. It is not an `EventTarget`. The URL must be `https` and must not have a fragment. A failed handshake rejects `ready` and `closed`, and those rejections are marked handled. `closed` resolves `{ closeCode, reason }`. `datagrams` is a plain `{ readable, writable }`. `createBidirectionalStream` resolves `{ readable, writable }`. `createUnidirectionalStream` resolves a `WritableStream`. Incoming streams are `ReadableStream`s of those values. Streams are `ReadableStream` and `WritableStream`, not `WebTransportReceiveStream` or `WebTransportSendStream`. Any `datagramsReadableType` other than `"bytes"` throws `TypeError`. A non-empty `protocols` list throws `NotSupportedError`. An empty list is accepted. A `Headers` object throws `NotSupportedError`, including an empty one. A non-empty header sequence or record throws `NotSupportedError`. An empty sequence or record is accepted. `serverCertificateHashes` replaces the webpki roots when the list is non-empty, including when every algorithm is unknown. Unknown hash algorithms are ignored. `allowPooling: true` with a non-empty hash list throws `NotSupportedError`. Pooling is otherwise ignored. `requireUnreliable` rejects `ready` and `closed` when the session cannot carry datagrams. The 14-day certificate limit and the RSA prohibition are not enforced. `congestionControl` is `default`, `throughput`, or `low-latency`. `reliability` is `pending`, then `supports-unreliable` or `reliable-only`. `getStats`, `exportKeyingMaterial`, `createSendGroup`, `draining`, `responseHeaders`, `protocol`, `supportsReliableOnly`, and the `anticipatedConcurrentIncomingUnidirectionalStreams` and `anticipatedConcurrentIncomingBidirectionalStreams` attributes are absent. An anticipated incoming-stream hint must be `null` or an integer from 0 through 65535. Any other value throws `TypeError`. An in-range hint is ignored. Incoming streams are accepted immediately and queued without a high-water mark. `createBidirectionalStream` and `createUnidirectionalStream` wait for flow-control credit. `sendOrder` and `waitUntilAvailable` are ignored. A non-null `sendGroup` throws `NotSupportedError`. Sessions are not pooled with each other or with fetch HTTP/3. An open stream errors with `WebTransportError` whose `source` is `session` when the session ends |
| `visibilityState` | `WindowSurface.visibilityState` is `"visible"` or `"hidden"`. It follows winit occlusion, so a minimized or fully covered window is `"hidden"`. Focus loss does not change it. Platforms without `WindowEvent::Occluded` stay `"visible"` until the window closes. There is no `document.hidden` or `document.visibilityState` |
| Input | Pointer events and the mouse events derived from them target `WindowSurface` and propagate through `Window`. `stopPropagation` and `stopImmediatePropagation` follow that path. Key, IME, wheel, focus, blur, resize, and close target the `Window` only. `focus` and `blur` are `FocusEvent`s and do not bubble. `pointerId` is per window. `pointerrawupdate` is dispatched for each pointer move, including motion reported while the pointer is locked, before the `pointermove` for those samples. It bubbles and is not cancelable. `getCoalescedEvents()` on it returns one `pointerrawupdate`. There is no `onpointerrawupdate` event-handler attribute. There is no non-secure context, so the event is not suppressed. Upstream tests that need a document, an element tree, or `test_driver` stay ignored |
| Size | `Window` `width` and `height` are device pixels and track the drawable. `clientWidth` and `clientHeight` are CSS pixels |
| IME | Disabled by default. `setImeAllowed` and `setCompositionCaret` are `Window` methods |
| Pointer lock | `requestPointerLock` and `exitPointerLock` belong to that surface, and so do the change events |
| Keyboard lock | `navigator.keyboard.lock` and `unlock` are on the main global when `window` is enabled. A dedicated worker does not have `keyboard` or `Keyboard`. There is no document, permission prompt, or secure-context gate. `lock` settles in the same turn and does not reject an earlier call with `AbortError`. Fullscreen is not required. Escape held for two seconds does not show an overlay and does not leave fullscreen. A code is accepted when this runtime can report it as `KeyboardEvent.code`. `getLayoutMap` and `layoutchange` are absent. A headless process stores the reservation and does not change operating-system shortcuts. macOS uses `PushSymbolicHotKeyMode(kHIHotKeyModeAllDisabled)` only when the list is empty or contains Escape, Tab, Space, MetaLeft, or MetaRight. Command-Tab and Command-Option-Escape stay with the system, and the mode does not change without assistive access. Windows uses a `WH_KEYBOARD_LL` hook that swallows a reserved key only while this process's window is foreground, then posts the key to that window. Ctrl+Alt+Delete is not visible to the hook. Linux calls `XGrabKeyboard` only for an empty list on X11. Wayland does not grab. Blur drops the inhibitor and keeps the reservation. Closing the focused window unlocks |
| Fullscreen | `requestFullscreen` and `exitFullscreen` belong to that surface |
| Title and cursor | The constructor `title` sets the initial OS window title. `WindowSurface.title` reads and writes it. `Window` has no `title` attribute. There is no `document`, so there is no `document.title`. The default is `"yuzuko"`. `cursor` is a `Window` attribute |
| Canvas 2D execution | `CanvasRenderingContext2D.lang` defaults to `"inherit"`. There is no document and no `<canvas>` element, so `"inherit"` and `""` both shape with an unknown language. The text stack applies the primary language subtag of a BCP 47 tag; a tag it cannot parse is stored and shaped as unknown. vello paints sRGB unorm8. `Yuzuko.canvasRenderer` is `"gpu"` or `"cpu"`. `YUZUKO_CANVAS` can pin it. `display-p3` and `float16` stores keep `putImageData` and matching `drawImage` samples. Path, text, and gradient paints are converted from that sRGB unorm8 result. `imageSmoothingEnabled: false` or `imageSmoothingQuality: "low"` samples nearest; `"medium"` and `"high"` sample linearly. A list uses the first loaded family from that realm's `FontFaceSet` (`Yuzuko.fonts` on the main global, `self.fonts` in a worker), or else the first of `sans-serif`, `serif`, and `monospace`. A size that names only an unregistered family is stored and shaped as `sans-serif` |
| Presentation | wgpu 29 has no `SurfaceColorSpace`. The swapchain uses an explicit unorm8 format, preferring `Bgra8Unorm` or `Rgba8Unorm`. Display P3 and float16 canvases are quantized to that sRGB image. A float16 surface is not configured |
| WebGPU device | One process `wgpu::Device` is shared with Canvas 2D. The device is created with `timestamp-query`, `depth-clip-control`, `depth32float-stencil8`, and wgpu external textures when the adapter supports each of them. Device creation retries with `timestamp-query` alone, then with no optional features, if a larger set fails. `requestDevice` rejects a feature the shared device does not have, and rejects `requiredLimits` the shared device cannot satisfy. Other optional features stay off. `destroy` loses that JavaScript device only. `GPUDevice.lost` resolves from `destroy`, not from garbage collection. `wgslLanguageFeatures` is empty. Published limits are the shared device's wgpu defaults, so `maxBindGroupsPlusVertexBuffers` can be below the WebGPU minimum. A downlevel adapter that cannot meet those defaults, such as the GL driver in WSLg with two color attachments, gets a device with the adapter's own limits, and those are published. Uncaptured errors are printed and are not dispatched as `uncapturederror` |
| WebGPU canvas | `getCurrentTexture` returns the same `GPUTexture` until that surface's rendering update. An `OffscreenCanvas` that is not a window's `surface` has no frame, so the texture stays until `unconfigure`, resize, or disposal. Canvas textures also get `TEXTURE_BINDING`, `COPY_SRC`, and `RENDER_ATTACHMENT` so the present blit and readback can use them. `alphaMode` `"opaque"` and `"premultiplied"` are stored; presentation blits stored texels and does not composite. `display-p3` is accepted and `copyExternalImageToTexture` converts into `"srgb"` or `"display-p3"`, but the swapchain present is still unorm8 sRGB. `GPUCanvasContext.label` stays `""` |
| WebGPU copy | `copyExternalImageToTexture` uploads with `queue.writeTexture`. Matching unorm8 bytes upload directly. A float16 source, a color-space change, a sub-rectangle, or a `bgra8unorm` destination is converted on the CPU. `getMappedRange` returns a copy, and `unmap` does not detach that `ArrayBuffer` |
| WebGPU subset | Blend state and alpha to coverage are applied. `unclippedDepth: true` requires `depth-clip-control` and otherwise throws `NotSupportedError`. `depth32float-stencil8` works when that feature is enabled and otherwise throws `NotSupportedError`. `externalTexture` and `importExternalTexture` copy a `VideoFrame` into an RGBA external texture when the process device supports wgpu external textures, and otherwise throw `NotSupportedError`. There is no `HTMLVideoElement`. A `src1` blend factor throws `NotSupportedError` without `dual-source-blending`. Multisample `count` is 1 or 4, and a color attachment may set `resolveTarget`. Storage texture `access` may be `read-only`, `read-write`, or `atomic`; an access the format does not allow is a validation error. `setViewport` and `setScissorRect` are on the render pass. Debug markers, and those two calls on a render bundle encoder, stay absent. `GPUQuerySet.destroy` marks the set destroyed, and a later `resolveQuerySet` records a validation error. wgpu 29 has no query-set destroy, so that resolve is recorded out of range. `writeTimestamp` stays absent. `createComputePipelineAsync` settles on the calling thread. A `"timestamp"` query set throws `NotSupportedError` when `timestamp-query` is not enabled. The binding is handwritten rather than generated |
| Gamepad | `navigator.getGamepads()` and `gamepadconnected` / `gamepaddisconnected` are on `globalThis`. There is no secure-context gate, permissions policy, or document, so a disconnected document does not suppress the list and a hidden document does not stop haptics. An already-connected device is exposed without waiting for a button press. `touches` stays empty, `pose` is null, and `hand` is `""`. `effects` lists `"dual-rumble"` only when that device can play force feedback. `trigger-rumble` rejects `NotSupportedError`. `playEffect` rejects `InvalidStateError` when the gamepad is disconnected, before parameter checks. `duration` and `startDelay` use WebIDL `unsigned long long` conversion, and their sum is capped at 5000 ms. gilrs plays motors in 50 ms ticks; the promise settles on the capped timeline and then stops the effect. Disconnecting a gamepad stops a playing effect and resolves that promise with `"preempted"`. `reset` resolves `"complete"` while the gamepad is connected |
| Images | `createImageBitmap` uses the first frame of an animated image. `ImageDecoder` returns each frame of an animated PNG, WebP, or JPEG XL, with `timestamp` and `duration` in microseconds, and does not advance those frames. Stored color spaces are `"srgb"` and `"display-p3"`. Any other source profile is converted to sRGB. Sample formats are unorm8 and float16. Limits are a longer edge of 16384 and 100 million pixels. `resizeQuality` `"pixelated"` and `"low"` are nearest-neighbor. `"medium"` and `"high"` use a triangle filter. `premultiplyAlpha: "default"` leaves samples unpremultiplied. JPEG XL orientation is applied by the decoder before `flipY` |
| `colorSpaceConversion` | `"none"` keeps an sRGB or Display P3 source in that space. `"default"` stores sRGB |
| JPEG XL encoding | `convertToBlob` supports PNG, JPEG, and WebP. WebP encoding is lossless, so `quality` does not change the bytes |
| Canvas 2D | Outside level A in `docs/spec.md`, `createConicGradient` throws `NotSupportedError`. A recognized `globalCompositeOperation`, including `clear` and the blend modes, is stored with the canvas state and restored by `save`, `restore`, `reset`, and `endLayer`. Painting uses `source-over`. `shadowBlur`, `shadowColor`, `shadowOffsetX`, and `shadowOffsetY` are stored the same way. Invalid values are ignored. Entering a layer resets those shadow attributes and the composite operation. Shadows are not painted. `filter` is parsed and stored and is not painted. `calc()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, and `color-mix()` do not parse. A `beginLayer` filter string that does not parse throws `TypeError`; the tentative layer tests treat some of those strings as omitted. A filter dictionary throws `TypeError` because `CanvasFilter` is absent. `getActualBoundingBox` uses unhinted outline bounds at the font's default variation, not rasterized ink. A shaper cluster that covers more than one grapheme stays one cluster. The classic `actualBoundingBox*` getters remain advance approximations |
| Fonts | `sans-serif`, `serif`, and `monospace` always work. `FontFace` is on `globalThis`. On the main global the `FontFaceSet` is `Yuzuko.fonts` and `globalThis.fonts` is absent. On a dedicated worker, `self.fonts` and `globalThis.fonts` are that worker's `FontFaceSet`. A face added to one set is not visible in the other. A face that has finished `load()` and is in that realm's set can be named from the Canvas 2D `font` property. `add` returns the set. `forEach`, `keys`, `values`, `entries`, and `@@iterator` walk insertion order and skip a face removed before it is reached. `check`, `load`, `ready`, and the `loading`, `loadingdone`, and `loadingerror` events are absent. There is no `document`. CSS `@font-face` is not implemented. A WOFF2 `glyf` or `loca` preprocessing transform is rejected. WPT files that need a document or a stylesheet are ignored |
| Clipboard | `navigator.clipboard` `read` / `readText` / `write` / `writeText` require a pointer or key press on the focused `Window` within five seconds. There is no permission prompt and no secure-context gate. `ClipboardItem` accepts `text/plain` and `image/png` only. A malformed type string throws `TypeError`. Any other type throws `NotSupportedError`. Text is published to the OS pasteboard. `image/png` is stored as the written bytes and also published as an image when the PNG decodes. `copy`, `cut`, and `paste` are `ClipboardEvent`s on the focused surface for Ctrl/Cmd+C, X, and V. `clipboardData` is null. `ClipboardChangeEvent` fires for a successful `write` or `writeText`, and on macOS and Windows when the OS pasteboard changes. `types` lists `text/plain`, `text/html`, and `image/png` only, in that order. This runtime's `write` does not store `text/html`. On Windows a DIB is reported as `image/png`. `changeId` is the pasteboard sequence on macOS and Windows, and a process-local counter on Linux. Linux does not observe other applications' clipboard changes. A change while no window is focused is delivered once after the next `focus`. WPT files that need `test_driver`, a document, an iframe, a permission prompt, or a permissions policy fail as a file |
| Screen Wake Lock | `navigator.wakeLock` is on the main global when the `window` feature is enabled. A dedicated worker does not have `wakeLock` or `WakeLock`. There is no document, permission prompt, permissions policy, or secure-context gate. Hiding a window does not release a sentinel. Every sentinel shares one platform assertion. macOS uses `IOPMAssertionCreateWithName` with type `PreventUserIdleDisplaySleep` and name `Yuzuko`. Windows uses `SetThreadExecutionState` with `ES_CONTINUOUS \| ES_DISPLAY_REQUIRED`, restored to `ES_CONTINUOUS` when the last sentinel releases. Linux spawns `systemd-inhibit --what=idle:sleep --who=Yuzuko --why=screen wake lock --mode=block sleep infinity` and kills that child on the last release. A sentinel that is never released keeps the assertion until the realm shuts down. `test_driver.set_permission` throws, so upstream files that call it fail. `wakelock-insecure-context.any.js` expects the constructor to be absent. `wakelock-screen-type-on-worker.https.worker.js` expects `NotAllowedError` from `navigator.wakeLock.request("screen")`. Files that need a document or a permissions policy stay ignored or fail as recorded |
| Dialogs | `Yuzuko.Window.alert`, `confirm`, and `prompt` are native modal dialogs for that window. They are not global `alert`, `confirm`, or `prompt`, and there is no `<dialog>`. | Menu bar | `Yuzuko` is an `EventTarget`. `Yuzuko.Menu` and `Yuzuko.setMenu(menu)` install one application menu. | Tray and dock | `Yuzuko.Tray` is a status item. `bounds` uses the main screen scale when one exists, and is `null` when the icon rectangle is unavailable, including the Linux AppIndicator backend. `setTooltip` throws `NotSupportedError` on Linux. `template: true` throws `NotSupportedError` except on macOS. WebCodecs are present when it includes `codec`. Each of those names is absent otherwise.  WPT that needs those, or a document, stays ignored or a named expected failure |
| Web Audio | `AudioContext` and `OfflineAudioContext` are on `globalThis`. There is no `Window` and no secure-context gate, so `audioWorklet` is available in this realm.
