# Specification deviations

Intentional divergences from the web platform and WinterTC. When an implementation differs from a specification, add a row in the same change. An unimplemented API must not succeed as a no-op. Leave it absent, or throw `NotSupportedError`.

| Area | Deviation |
| --- | --- |
| Document | There is no `document`, DOM tree, or `HTMLCanvasElement`. Drawing uses `OffscreenCanvas` |
| Contexts | `getContext("webgl")` and `getContext("webgl2")` return `null` |
| Namespaces | Web standards and WinterTC live on `globalThis`. Runtime-specific APIs live on `Yuzuko`. There is no global `Window` constructor |
| `matchMedia` | `Yuzuko.Window.matchMedia` follows this window's CSS size and `devicePixelRatio`. `media` is the query text passed in. `pointer` is `fine`. On macOS, `color-gamut` is `p3` when the main display can represent Display P3, otherwise `srgb`. `rec2020` does not match. `prefers-color-scheme` follows the window theme. `prefers-reduced-motion: reduce` follows Accessibility's Reduce Motion setting. `prefers-contrast` is `more` when Increase Contrast is on, and `no-preference` otherwise. `less` and `custom` do not match. On Windows, `prefers-reduced-motion: reduce` matches when Animation effects is off (`SPI_GETCLIENTAREAANIMATION`), `prefers-contrast` is `more` while a contrast theme is on (`HCF_HIGHCONTRASTON`), and before a window reports its theme the scheme is the apps mode (`AppsUseLightTheme`). There is no `forced-colors` feature. Windows and Linux report `srgb`. Linux reports `no-preference` for motion and contrast and the winit theme when a window exists. There is no `hover`, `any-pointer`, or `scripting` feature. Workers have no `matchMedia` |
| Windows | `new Yuzuko.Window(options)` extends `EventTarget`. `surface` is a `Yuzuko.WindowSurface`, not an `OffscreenCanvas`. Its bitmap does not follow later resizes. `transferControlToOffscreen()` hands an `OffscreenCanvas` to a worker; the surface itself cannot be transferred. `objectFit` is `none`, `contain`, `cover`, `fill`, or `scale-down` (default `scale-down`); the window outside that rectangle is black. `imageRendering` is `auto` (default), `smooth`, `crisp-edges`, or `pixelated`. `auto` and `smooth` are bilinear. `crisp-edges` is nearest-neighbor. `pixelated` uses nearest-neighbor to the nearest integer scale, then bilinear to the final size. An unrecognized `objectFit`, `imageRendering`, or `cursor` value is ignored, and those keywords are case-insensitive. `resizable` defaults to `false` and assigning it updates the live window. Startup creates no implicit window. `x` and `y` place the frame origin in CSS pixels; omitting both centers it on the primary monitor, or uses `0, 0` when no monitor exists. Setting only one of `x` or `y` uses `0` for the other. `screenX` and `screenY`, with aliases `screenLeft` and `screenTop`, and `innerX` and `innerY`, are the client origin. `outerX` and `outerY` are the frame origin. `moveTo` and `moveBy` move that frame. `resizeTo` and `resizeBy` change the client size, which is what CSSOM calls the viewport. `show`, `hide`, and `visible` control OS visibility and do not by themselves change occlusion `visibilityState`. `focus` focuses the window. `alwaysOnTop` can change after creation. `decorations` and `active` default to `true` and are creation-only. `active: false` skips the initial focus; it is not a separate non-activating panel. `visible` defaults to `true`. `maximized` defaults to `false` and is not fullscreen. `minWidth`, `minHeight`, `maxWidth`, and `maxHeight` are optional client-size limits. An omitted maximum edge is unset in script; when only one maximum is set, the OS limit for the other edge is 100000 CSS pixels. `resizeTo` and `resizeBy` clamp to those limits. `transparent` defaults to `false` and is creation-only. It asks the OS to composite alpha. macOS clears the window background. Windows uses Desktop Window Manager. Wayland and X11 need a compositor. Unpainted pixels are clear. A fitted bitmap's uncovered area is clear instead of black. The swapchain uses premultiplied alpha when the surface offers it. There is no `reload` |
| Frames | `requestAnimationFrame` on a `Yuzuko.Window` is per window. The main global has no `requestAnimationFrame`. A dedicated worker has `requestAnimationFrame` and `cancelAnimationFrame`; after those callbacks, each transferred window canvas is copied into the window that owns it. The rendering update presents that surface. Frames are not throttled while `visibilityState` is `"hidden"` |
| Idle callbacks | `requestIdleCallback`, `cancelIdleCallback`, and `IdleDeadline` are own properties of the main `globalThis`, not inherited from a `Window` prototype. Dedicated workers do not have them. There is no document, so a hidden window does not throttle idle periods. An idle period waits while the next timer, host task, or window frame is under 5ms away |
| `EventSource` | `withCredentials` is stored and does not change the request. There is no cookie jar and no CORS check. A scheme other than `http` or `https` throws `SyntaxError` |
| `WebSocket` | `extensions` stays empty. There is no permessage-deflate. `wss:` trusts the webpki root set, so the WPT server certificate fails. The second constructor argument follows the open `WebSocketInit` dictionary proposal: a string, a sequence, or `{ protocols, targetAddressSpace }`. `targetAddressSpace` must match the connected address exactly (`loopback`, `local`, or `public`). `WebSocketStream` uses that connection as streams. Binary chunks are `Uint8Array` values, not `Blob`s. An `AbortSignal` aborts only the handshake. A handshake failure rejects both `opened` and `closed`, and those rejections are marked handled so a caller that observes only one of them does not also get an unhandled rejection |
| `visibilityState` | `WindowSurface.visibilityState` is `"visible"` or `"hidden"`. It follows winit occlusion, so a minimized or fully covered window is `"hidden"`. Focus loss does not change it. Platforms without `WindowEvent::Occluded` stay `"visible"` until the window closes. There is no `document.hidden` or `document.visibilityState` |
| Input | Pointer events and the mouse events derived from them target `WindowSurface` and propagate through `Window`. `stopPropagation` and `stopImmediatePropagation` follow that path. Key, IME, wheel, focus, blur, resize, and close target the `Window` only. `focus` and `blur` are `FocusEvent`s and do not bubble. `pointerId` is per window |
| Size | `Window` `width` and `height` are device pixels and track the drawable. `clientWidth` and `clientHeight` are CSS pixels |
| IME | Disabled by default. `setImeAllowed` and `setCompositionCaret` are `Window` methods |
| Pointer lock | `requestPointerLock` and `exitPointerLock` belong to that surface, and so do the change events |
| Fullscreen | `requestFullscreen` and `exitFullscreen` belong to that surface |
| Title and cursor | The constructor `title` sets the initial OS window title. `WindowSurface.title` reads and writes it. `Window` has no `title` attribute. There is no `document`, so there is no `document.title`. The default is `"yuzuko"`. `cursor` is a `Window` attribute |
| Canvas 2D execution | `CanvasRenderingContext2D.lang` defaults to `"inherit"`. There is no document and no `<canvas>` element, so `"inherit"` and `""` both shape with an unknown language. The text stack applies the primary language subtag of a BCP 47 tag; a tag it cannot parse is stored and shaped as unknown. vello paints sRGB unorm8. `Yuzuko.canvasRenderer` is `"gpu"` or `"cpu"`. `YUZUKO_CANVAS` can pin it. `display-p3` and `float16` stores keep `putImageData` and matching `drawImage` samples. Path, text, and gradient paints are converted from that sRGB unorm8 result. `imageSmoothingEnabled: false` or `imageSmoothingQuality: "low"` samples nearest; `"medium"` and `"high"` sample linearly. A list uses the first loaded family from that realm's `FontFaceSet` (`Yuzuko.fonts` on the main global, `self.fonts` in a worker), or else the first of `sans-serif`, `serif`, and `monospace`. A size that names only an unregistered family is stored and shaped as `sans-serif` |
| Presentation | wgpu 29 has no `SurfaceColorSpace`. The swapchain uses an explicit unorm8 format, preferring `Bgra8Unorm` or `Rgba8Unorm`. Display P3 and float16 canvases are quantized to that sRGB image. A float16 surface is not configured |
| WebGPU device | One process `wgpu::Device` is shared with Canvas 2D and is created with no optional features. `requestDevice` rejects a non-empty `requiredFeatures` list, and rejects `requiredLimits` the shared device cannot satisfy. `destroy` loses that JavaScript device only. `GPUDevice.lost` resolves from `destroy`, not from garbage collection. `label` reads back as `""`. `wgslLanguageFeatures` is empty. Published limits are the shared device's wgpu defaults, so `maxBindGroupsPlusVertexBuffers` can be below the WebGPU minimum. A downlevel adapter that cannot meet those defaults, such as the GL driver in WSLg with two color attachments, gets a device with the adapter's own limits, and those are published. Uncaptured errors are printed and are not dispatched as `uncapturederror` |
| WebGPU canvas | `getCurrentTexture` returns the same `GPUTexture` until that surface's rendering update. An `OffscreenCanvas` that is not a window's `surface` has no frame, so the texture stays until `unconfigure`, resize, or disposal. Canvas textures also get `TEXTURE_BINDING`, `COPY_SRC`, and `RENDER_ATTACHMENT` so the present blit and readback can use them. `alphaMode` `"opaque"` and `"premultiplied"` are stored; presentation blits stored texels and does not composite. `display-p3` is accepted and `copyExternalImageToTexture` converts into `"srgb"` or `"display-p3"`, but the swapchain present is still unorm8 sRGB |
| WebGPU copy | `copyExternalImageToTexture` uploads with `queue.writeTexture`. Matching unorm8 bytes upload directly. A float16 source, a color-space change, a sub-rectangle, or a `bgra8unorm` destination is converted on the CPU. `getMappedRange` returns a copy, and `unmap` does not detach that `ArrayBuffer` |
| WebGPU subset | Render bundles, compute pipelines, compute passes, occlusion queries, timestamp queries, and a depth-stencil attachment throw `NotSupportedError`. The binding is handwritten rather than generated |
| Gamepad | `navigator.getGamepads()` and `gamepadconnected` / `gamepaddisconnected` are on `globalThis`. There is no secure-context gate, permissions policy, or document, so a disconnected document does not suppress the list. An already-connected device is exposed without waiting for a button press. `touches` stays empty, `pose` is null, and `hand` is `""`. `playEffect` and `pulse` reject `NotSupportedError`. `reset` resolves `"complete"` while the gamepad is connected |
| Images | Animated images contribute the first frame. Stored color spaces are `"srgb"` and `"display-p3"`. Any other source profile is converted to sRGB. Sample formats are unorm8 and float16. Limits are a longer edge of 16384 and 100 million pixels. `resizeQuality` `"pixelated"` and `"low"` are nearest-neighbor. `"medium"` and `"high"` use a triangle filter. `premultiplyAlpha: "default"` leaves samples unpremultiplied. JPEG XL orientation is applied by the decoder before `flipY` |
| `colorSpaceConversion` | `"none"` keeps an sRGB or Display P3 source in that space. `"default"` stores sRGB |
| JPEG XL encoding | `convertToBlob` supports PNG, JPEG, and WebP. WebP encoding is lossless, so `quality` does not change the bytes |
| Canvas 2D | Outside level A in `docs/spec.md`, `createConicGradient` throws `NotSupportedError`. A recognized `globalCompositeOperation`, including `clear` and the blend modes, is stored with the canvas state and restored by `save`, `restore`, `reset`, and `endLayer`. Painting uses `source-over`. `shadowBlur`, `shadowColor`, `shadowOffsetX`, and `shadowOffsetY` are stored the same way. Invalid values are ignored. Entering a layer resets those shadow attributes and the composite operation. Shadows are not painted. `filter` is parsed and stored and is not painted. `calc()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, and `color-mix()` do not parse. A `beginLayer` filter string that does not parse throws `TypeError`; the tentative layer tests treat some of those strings as omitted. A filter dictionary throws `TypeError` because `CanvasFilter` is absent. `getActualBoundingBox` uses unhinted outline bounds at the font's default variation, not rasterized ink. A shaper cluster that covers more than one grapheme stays one cluster. The classic `actualBoundingBox*` getters remain advance approximations |
| Fonts | `sans-serif`, `serif`, and `monospace` always work. `FontFace` is on `globalThis`. On the main global the `FontFaceSet` is `Yuzuko.fonts` and `globalThis.fonts` is absent. On a dedicated worker, `self.fonts` and `globalThis.fonts` are that worker's `FontFaceSet`. A face added to one set is not visible in the other. A face that has finished `load()` and is in that realm's set can be named from the Canvas 2D `font` property. There is no `document`. CSS `@font-face` is not implemented. A WOFF2 `glyf` or `loca` preprocessing transform is rejected. WPT files that need a document or a stylesheet are ignored |
| Clipboard | `navigator.clipboard` `read` / `readText` / `write` / `writeText` require a pointer or key press on the focused `Window` within five seconds. There is no permission prompt and no secure-context gate. `ClipboardItem` accepts `text/plain` and `image/png` only. A malformed type string throws `TypeError`. Any other type throws `NotSupportedError`. Text is published to the OS pasteboard. `image/png` is stored as the written bytes and also published as an image when the PNG decodes. `copy`, `cut`, and `paste` are `ClipboardEvent`s on the focused surface for Ctrl/Cmd+C, X, and V. `clipboardData` is null. `ClipboardChangeEvent` is absent. WPT files that need `test_driver`, a document, an iframe, a permission prompt, or a permissions policy fail as a file |
| Dialogs | `Yuzuko.Window.alert`, `confirm`, and `prompt` are native modal dialogs for that window. They are not global `alert`, `confirm`, or `prompt`, and there is no `<dialog>`. A headless process throws `NotSupportedError`. Buttons are OK and Cancel. `prompt` returns `null` when cancelled and `""` when the field is cleared and accepted. Linux uses GTK 3 and does not parent the dialog to the winit window. There is no file-picker dialog |
| Menu bar | `Yuzuko` is an `EventTarget`. `Yuzuko.Menu` and `Yuzuko.setMenu(menu)` install one application menu. A selection dispatches `menuclick` on `Yuzuko` and the event's `action` is that item's string. On macOS the menu is the app menu. On Windows the same menu is attached to the focused window with `muda`. On Linux, winit does not expose a GTK window, so `setMenu` throws `NotSupportedError`. There is no context menu |
| Tray and dock | `Yuzuko.Tray` is a status item. `bounds` uses the main screen scale when one exists, and is `null` when the icon rectangle is unavailable, including the Linux AppIndicator backend. `setTooltip` throws `NotSupportedError` on Linux. `template: true` throws `NotSupportedError` except on macOS. Replacing or clearing a tray menu throws `NotSupportedError` on Linux. `Yuzuko.dock.setBadge`, `setVisible`, and `setMenu` are macOS Dock operations and throw `NotSupportedError` on Windows and Linux. `bounce()` uses `NSApp.requestUserAttention` on macOS. On Windows and Linux it requests attention for an open window and throws `NotSupportedError` when none is open. `reopen` is delivered only on macOS. There is no WebView tray panel |
| Workers | Dedicated workers only. `new Worker(url)` and `{ type: "module" }` start a dedicated-worker global (`self === globalThis`) with the WinterTC subset, `postMessage`, `onmessage`, `importScripts`, `navigator`, `location`, `close`, `onerror`, `btoa`, `atob`, and the timers. There is no `Yuzuko.Window`, no `document`, and no `SharedWorker`. Classic worker scripts and `importScripts` run. The application entry stays an ES module. `postMessage` carries values `structuredClone` can carry, including a transferred `ArrayBuffer` and a `MessagePort`. The worker keeps running while the owner is busy. `self.fonts` and `globalThis.fonts` are that worker's `FontFaceSet`. The main realm keeps `Yuzuko.fonts` and has no `globalThis.fonts`. In a worker, `DOMMatrix` and `DOMMatrixReadOnly` have no Window stringifier, no CSS-string constructor, and no `setMatrixValue`. On the main global the stringifier stays `"matrix(1, 0, 0, 1, 0, 0)"` for an identity matrix. `WebKitCSSMatrix` is absent in both realms. An `OffscreenCanvas` can be transferred into a worker and a `"2d"` context can draw; the sender is detached. A `Yuzuko.Window` cannot be transferred. A WebGPU device stays on the thread that created it; using it or transferring it from another thread fails. Shared workers, service workers, worklets, `.sub.` substitution, and a document stay out. IndexedDB and `BroadcastChannel` stay absent. `WebSocket`, `WebSocketStream`, and `EventSource` are available. WPT that needs those, or a document, stays ignored or a named expected failure |
| Web Audio | `AudioContext` and `OfflineAudioContext` are on `globalThis`. There is no `Window` and no secure-context gate, so `audioWorklet` is available in this realm. WAV, FLAC, MP3, and Ogg Vorbis are decoded in pure Rust. No audio output device is opened, and a rendered `AudioBuffer` is the signal. Realtime `renderSizeHint: "hardware"` is visible at construction. On macOS it is the default output device's current Core Audio buffer size in frames when that size is inside 1 through floor(6 × sampleRate), and 128 when the query fails. Windows and Linux use 128. It is not 0, and no playback stream is opened. Offline `"hardware"` is 128. `baseLatency` is `renderQuantumSize / sampleRate`. There is no autoplay gate, so a new `AudioContext` starts `"running"`. `AudioParam` automation (`setValueAtTime`, ramps, curves, `cancelScheduledValues`, and `cancelAndHoldAtTime`) throws `NotSupportedError`. WPT files that need a document, an HTML media element, a `MediaStream`, a permissions policy, or a node type outside this surface (Analyser, Biquad, Convolver, Delay, DynamicsCompressor, IIR, Panner, StereoPanner, WaveShaper, ChannelMerger, ChannelSplitter, MediaElement and MediaStream sources, ScriptProcessor), plus `AudioListener`, `sinkId`, `AudioPlaybackStats`, `getOutputTimestamp`, and the `AudioParam` automation directory, are ignored |
| WebCodecs | `VideoDecoder`, `EncodedVideoChunk`, `VideoFrame`, `AudioDecoder`, `EncodedAudioChunk`, and `AudioData` are on `globalThis`. There is no `HTMLVideoElement`, and the runtime does not demux a container or advance frames. H.264 (`avc1`, `avc3`) and AAC (`mp4a`) are the only codecs. Both are selected on every target triple, not only through a macOS decoder. H.264 is hardware-only: VideoToolbox on Darwin with `kVTVideoDecoderSpecification_RequireHardwareAcceleratedVideoDecoder`, the Media Foundation H.264 transform with a Direct3D 11 device manager (DXVA) on Windows, and VA-API on Linux. The Linux path parses the `avcC` and slice header, submits `VAPictureParameterBufferH264`, an IQ matrix, and slice buffers through `vaBeginPicture` / `vaRenderPicture` / `vaEndPicture`, then maps the surface with `vaDeriveImage` or `vaGetImage`. The Windows path requires the `H264_VLD_NOFGT` decoder profile on a Direct3D 11 device, rewrites the `avcC` and each length-prefixed sample as Annex B with the parameter sets before each IDR, and locks each DXGI output sample into a `Raster`. A sample that is not a DXGI surface means the transform fell back to software, and that decode fails with `NotSupportedError`. A missing decoder, a rejected config, or a sample that cannot be locked fails the decode. There is no software H.264 decoder, including when `hardwareAcceleration` is `"prefer-software"`. Picture output is verified with VideoToolbox on a Mac and with DXVA on Windows 11 (NVIDIA). The VA-API path was not executed: WSL exposes no VA-API device. Where no hardware H.264 decoder exists, the picture tests are ignored. AAC uses Symphonia on elementary packets. `vp8`, `vp09`, `av01`, `opus`, `vorbis`, and every other codec string throw `NotSupportedError`. `decodeAudioData` is unchanged. `VideoEncoder` and `AudioEncoder` are absent. `ImageDecoder` decodes `image/png`, `image/jpeg`, `image/webp`, and `image/jxl` only. An unsupported type does not throw from the constructor; `completed`, `tracks.ready`, and `decode()` reject `NotSupportedError`. Animated images still contribute the first frame, so `animated` is false, `frameCount` is 1, and `repetitionCount` is 0. `desiredWidth`, `desiredHeight`, and `preferAnimation` are ignored. A truncated buffer that cannot be decoded rejects `completed` and `tracks.ready` with `EncodingError` instead of publishing partial track metadata. `ReadableStream` bytes are pulled with `getReader()`. `colorSpaceConversion` follows `createImageBitmap`. A `VideoFrame` cannot be transferred to a worker. `VideoColorSpace` is absent, so `webcodecs/image-decoder.https.any.js` stops while the script is evaluated. ImageDecoder tests that need a document, an iframe, or a canvas stay ignored. Animated JPEG XL still fails because only the first frame is decoded |
| REPL | `yuzuko repl` evaluates each chunk as a classic script, not an ES module. A static `import` or `export` is a syntax error. A top-level `let`, `const`, `class`, `function`, or `var` binding is copied onto the global object so the next chunk can read it, and a later declaration of the same name replaces that property. Top-level `await` runs inside an async function, and the printed value is the value that function returns. Dynamic `import()` resolves relative to the current directory. On a Unix terminal and a Windows console the event loop runs while the editor waits for a key, so timers and open windows keep going. A Windows pipe is read a line at a time, so the loop does not run until that line arrives. A zero-delay timer that schedules itself again runs once for the chunk that found it already due, so the prompt is not held for that chain. On a Unix terminal and a Windows console the editor follows the Node.js readline emacs bindings for character and word motion, line start and end, history, and Ctrl-U, Ctrl-K, and Ctrl-Y. A console host without virtual terminal input falls back to reading a line at a time without those keys |
| Packaging and updates | `yuzuko package` reads `yuzuko.json` or `yuzuko.jsonc`. The checked bundle is an ad-hoc-signed macOS `.app` for `aarch64-apple-darwin`. Windows output is a directory that stores the identifier in `AppUserModelID` and copies the `.ico`. Its executable is the runtime with the PE subsystem set to GUI and the `.ico` written in as its `RT_GROUP_ICON` 1 resource with the Windows resource API, so a double click opens no console, and it sets that AppUserModelID and the `.ico` window icon at launch. Linux output is a directory whose `<identifier>.desktop` is the application id with `StartupWMClass`, and that copies the PNG. Its windows carry the identifier as `WM_CLASS` and `app_id` and the widest PNG as the window icon; Wayland compositors ignore a client window icon. Both layouts were launched on Windows 11 and on Ubuntu 20.04 in WSL. Neither is installed into the Start menu or an applications directory. There is no Authenticode signature, notarization, `.dmg`, `.msi`, `.deb`, `.rpm`, or `.AppImage`. There is no `exports`, `backend`, `deepLinks`, or `errorReporting` key. The entry is the path given to `yuzuko package`. Window options stay on `new Yuzuko.Window()`. `release.baseUrl` is stored at package time and `yuzuko package` does not fetch it. `Yuzuko.updater` is installed only on the main global of a packaged entry. `yuzuko run`, `yuzuko repl`, and dedicated workers do not have it. `check()` and `download()` are explicit. There is no `apply()`, and the running process is not replaced. A successful update replaces the `app/` tree and the manifest `version` and `entry` on the next launch. It does not replace the executable, `Info.plist`, icons, or `yuzuko.update-key`, and it does not refresh the macOS ad-hoc signature. Loopback `http:` was executed on this Mac. `https:` uses rustls and the webpki roots and was not exercised against a successful server here. Windows and Linux directory bundles receive the same trust-anchor file and the same apply code, and the loopback update test passes on Windows 11 and on Ubuntu 20.04 in WSL. |
| Fetch posture | The runtime uses the unrestricted fetch posture from the WinterTC fetch workstream. Forbidden request headers, forbidden response headers, forbidden methods, CORS, `no-cors`, and request `mode` / `credentials` / `referrer` / `referrerPolicy` / `destination` / `keepalive` / navigation flags are not enforced. Those `Request` getters are absent. `cache` defaults to `"no-store"`. A non-empty `integrity` throws `NotSupportedError`. `redirect: "manual"` returns the redirect response with its status and headers. `Response.type` for `fetch` and `new Response()` is `"default"`. `file:` stays under the entry directory and is not read until the body is pulled. A `Blob` keeps shared chunks or a file span and does not concatenate them until `text()`, `arrayBuffer()`, `bytes()`, or a blob URL snapshot |
| `navigator.userAgent` | `Yuzuko/<version>` |
| High-resolution time | `performance.now()` and event `timeStamp` are not coarsened to 100 µs or 5 µs. This process is not a cross-origin browser context |
| SubtleCrypto algorithms | ML-KEM, the hybrid KEMs, ML-DSA, SLH-DSA, AES-OCB, ChaCha20-Poly1305, SHA-3, SHAKE, KMAC, and Argon2 throw `NotSupportedError`, including the `SubtleCrypto` methods those suites add. Ed448 and X448 are implemented |
| WebAssembly surface | This V8 build has no `WebAssembly.Function`, no `type()` on `Global`, `Memory`, `Table`, or `Tag`, and no `minimum` on memory or table descriptors. Those members stay absent. `compileStreaming` and `instantiateStreaming` do not reject a `no-cors` response: `Response.type` stays `"default"` under the fetch posture, so the body can be read |
| Wasm ESM `v128` | A `v128` global export is `undefined` after evaluation. A JavaScript source-text module cannot leave that binding in the temporal dead zone |
| Modules | The application entry and its imports are ES modules. There is no CommonJS evaluation. A dedicated worker may run a classic script and `importScripts`, and may also be `{ type: "module" }`. TypeScript is erased with oxc and is not typechecked. `.tsx` and JSX do not load. `node:` does not resolve. `import source` is implemented for `.wasm` only |
| Threads | A dedicated worker runs on its own thread and enters only its own V8 isolate. winit stays on the main thread. wgpu stays on the thread that created the device. Other background work posts completions to a task queue and does not call V8 |
| Permissions | No prompts. A local app may use the network and `file:` URLs under the entry directory |
| `Yuzuko.test` | Installed only for `yuzuko test`, together with `Yuzuko.build.os`. Absent during `yuzuko run`. There is no op or resource sanitizer |

Record observed per-OS differences, such as `keydown` ordering around IME, below.

| OS | Observed | Chosen behavior |
| --- | --- | --- |
| Windows | A console delivers a character outside the Basic Multilingual Plane as Alt key-up records, one per surrogate, instead of key-down records | The REPL editor also reads text from an Alt key-up record |
| Windows | The only H.264 Media Foundation transform on Windows 11 is the Microsoft decoder, which decodes in software unless it is given a Direct3D 11 device. It ignores the `avcC` sequence header and wants Annex B input | The decoder gets a Direct3D 11 device manager, only DXGI output samples are accepted, and each IDR carries its SPS and PPS in band |
| Windows | `std::fs::canonicalize` returns `\\?\C:\...`, while a `file:` URL converts back to `C:\...` | Canonical paths drop the verbatim prefix before the `file:` sandbox compares them |
| Windows | gilrs joins its input thread when it drops, and a thread-local destructor at exit runs after Windows has ended that thread | The gamepad context lives for the process |
| Linux | A closed pipe polls as `POLLHUP` without `POLLIN` while lines remain in the `Stdin` buffer | The REPL treats `POLLHUP` as readable and stops at the read that returns EOF |
| Linux (WSLg) | The GL adapter offers two color attachments, below wgpu's default limits. lavapipe in Mesa 21 advertises `VK_EXT_debug_utils` without its label functions | The device takes the adapter's limits, Canvas 2D uses the CPU renderer on such a device, and debug labels are off unless `WGPU_DEBUG` is set |
| Linux (WSLg) | There is no VA-API device and no StatusNotifier host | H.264 `configure` throws `NotSupportedError`. A tray icon is created but is not shown |
