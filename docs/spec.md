# Yuzuko

Desktop JavaScript runtime built on rusty_v8. It has no WebView and no HTML document. Scripts draw their own pixels and present them in native windows.

The default Cargo features include every surface below. Build features lists the JavaScript runtime that remains when no feature is enabled.

[overview.md](overview.md) introduces those surfaces by feature. This file is the product spec. The implementation contract is `AGENTS.md` at the repository root. Intentional divergences from the web platform live in [deviations.md](deviations.md).

## Product

`yuzuko run game.ts` or `yuzuko run game.js` evaluates an ES module in V8. TypeScript is erased by oxc before V8 parses it. Startup does not open a window. Each `new Yuzuko.Window()` opens one native window.

Standard APIs live on `globalThis`. APIs that are in neither the web platform nor WinterTC live on `Yuzuko`. There is no global `Window` constructor.

The runtime provides:

- Multiple `Yuzuko.Window` objects. Each is an input `EventTarget`. Its `surface` is the `Yuzuko.WindowSurface` presented on screen.
- Pointer, wheel, keyboard, and IME composition events delivered to that surface. IME is off by default.
- `createImageBitmap` for JPEG, PNG, WebP, JPEG XL, GIF, BMP, and AVIF.
- Canvas 2D on the GPU through vello_gpu when the environment can use it, and on the CPU through vello_cpu otherwise. WebGPU uses the process wgpu device.
- Presenting that surface when its Canvas 2D or `bitmaprenderer` contents change, and at the end of a due `requestAnimationFrame` callback.
- The WinterTC Minimum Common API (the ECMA-429 2025 snapshot; the draft is dated 31 July 2026), as specified below.
- ECMA-402 `Intl` with the full ICU locale data linked into this V8 build.
- Dedicated workers in every build. Web Audio when the runtime is built with `audio`. H.264, AV1, AAC, Opus, and Vorbis decoding when it is built with `codec`. Packaging and automatic updates are part of the CLI.
- `Yuzuko` file-system methods when the runtime is built with the `fs` feature.

## Platforms

The supported targets are:

| Triple | OS | Architecture |
| --- | --- | --- |
| `aarch64-apple-darwin` | macOS | arm64 |
| `x86_64-apple-darwin` | macOS | Intel |
| `x86_64-pc-windows-msvc` | Windows | x86_64 |
| `aarch64-unknown-linux-gnu` | Linux | arm64 |
| `x86_64-unknown-linux-gnu` | Linux | x86_64 |

Window, GPU, and input code uses winit and wgpu so every target stays reachable. A shared feature is not implemented behind `target_os = "macos"` alone. An OS-specific gap, such as an IME or Display P3 surface difference, is a row in `docs/deviations.md` with the OS name.

## Out of scope

Do not add these as a side effect. Update this section before adding one.

- WebView, CEF, an HTML parser, CSS, a DOM tree, `document`, `HTMLCanvasElement`, and navigation
- WebGL and WebGL2. `getContext("webgl")` and `getContext("webgl2")` return `null`
- Node compatibility, an npm client, `node:` builtins, CommonJS evaluation, and JSX or TSX. TypeScript runs by type erasure, not by type checking
- A dependency on `deno` or `deno_core`.
- `navigator.permissions`, and prompts for clipboard, geolocation, notifications, and midi. Host read, write, net, env, run, and ffi access is specified in Permissions. Which optional surfaces are present is chosen when the runtime is built. See Build features
- WebRTC and WebXR
- `HTMLVideoElement` and a media presentation clock
- CSS `@font-face`

A dedicated worker has them. An AudioWorklet processor context does not receive the `Yuzuko` object.

`Yuzuko.errors` is an object of classes: `NotFound`, `PermissionDenied`, `ConnectionRefused`, `ConnectionReset`, `ConnectionAborted`, `NotConnected`, `AddrInUse`, `AddrNotAvailable`, `BrokenPipe`, `AlreadyExists`, `InvalidData`, `TimedOut`, `Interrupted`, `WriteZero`, `WouldBlock`, `UnexpectedEof`, `BadResource`, `Http`, `Busy`, `NotSupported`, `FilesystemLoop`, `IsADirectory`, `NetworkUnreachable`, `NotADirectory`, and `NotCapable`. Each extends `Error`. `name` is the class name. The constructor passes the message and the optional options object to `Error`, which uses that object for `cause`. An omitted or `undefined` message is `""`. The thrown value is the constructor captured when the realm started. Replacing a property later does not change it. `instanceof` that class and `instanceof Error` are both true. An operating-system failure may set `code` to the errno name Deno uses for that error, such as `ENOENT`. A value constructed with `new` does not set `code`. `NotCapable` is described in Permissions. File-system failures use these classes as described in File system. Socket and HTTP failures use them as described in Socket errors.

`globalThis` is the execution realm and inherits from `EventTarget`. `self === globalThis`, and assigning to `self` leaves that binding unchanged. `onerror` and `onunhandledrejection` are delivered here. A throw inside `queueMicrotask` is reported with `reportError` on that realm: the `error` event's `error` is the thrown value. During `yuzuko test` that throw fails the test. Pointer and key events are not.

`navigator.hardwareConcurrency` is present on the main global and in a dedicated worker in every build. It is the number of logical processors available to the process, and it is at least 1. When the operating system does not report a count, the value is 1.

`Yuzuko.canvasRenderer` is `"gpu"` or `"cpu"`. It is chosen once at process startup and does not change. `"gpu"` is vello_gpu and `"cpu"` is vello_cpu. `YUZUKO_CANVAS=cpu` or `YUZUKO_CANVAS=gpu` overrides the choice. A GPU request that fails to produce a device, or whose renderer cannot be created, selects `"cpu"`.

## Process

`Yuzuko.args`, `Yuzuko.env`, `Yuzuko.cwd`, `Yuzuko.chdir`, `Yuzuko.exit`, `Yuzuko.execPath`, `Yuzuko.pid`, `Yuzuko.ppid`, `Yuzuko.version`, `Yuzuko.memoryUsage`, `Yuzuko.noColor`, `Yuzuko.refTimer`, and `Yuzuko.unrefTimer` belong to every build. The main realm and a dedicated worker each receive them when that realm starts. `env` and `chdir` follow Permissions. `args`, `cwd`, `exit`, `execPath`, `pid`, `ppid`, `version`, `memoryUsage`, `noColor`, `refTimer`, and `unrefTimer` do not.

`Yuzuko.args` is a frozen array of strings. The property on `Yuzuko` is writable. Assigning it in one realm leaves the other realm's array unchanged. `push` and other mutations of the array throw `TypeError`. `yuzuko run` records the tokens after the entry, described in CLI. `yuzuko repl` and `yuzuko test` record an empty array. Their flags and paths are not script arguments. A packaged executable records the arguments it was given, except every token whose text starts with `-psn_`. macOS may insert those tokens in any position. A packaged entry cannot receive an argument that starts with `-psn_`. A dedicated worker receives the same strings this process recorded at launch.

`Yuzuko.env.get(name)` returns the stored string, or `undefined` when `name` is absent. `set(name, value)` stores a string. `get`, `has`, and `toObject` may run while a host lookup is inside `getaddrinfo`. Host lookups may overlap one another and those reads. `set` and `delete` wait until those reads and lookups finish, and they do not run at the same time as each other or as `chdir`. `delete(name)` removes `name`, and removing a name that is absent succeeds. `has(name)` returns a boolean. `toObject()` returns a plain object snapshot of the environment at that call. Later `set` and `delete` calls leave the object unchanged. `toObject` uses the spelling the operating system stores. The methods do not read `this`. Extra arguments are ignored. `get`, `delete`, and `has` have length 1. `set` has length 2. `toObject` has length 0.

`name` and `value` must be string primitives. Another type does not run `ToString`. A name that is not a string throws `TypeError` with `The name must be a string.` An empty name throws `The name must not be empty.` A name that contains `=` or NUL throws `The name must not contain `=` or NUL.` A value that is not a string throws `The value must be a string.` A value that contains NUL throws `The value must not contain NUL.` On Windows a lookup ignores ASCII case, and `set` of a name that differs only by that case updates the existing variable. On the other targets the name is case-sensitive. Bytes that are not UTF-8 become U+FFFD. The environment is process-wide. A change in one realm is visible to a later read in every realm.

`Yuzuko.cwd()` returns the process current directory as an absolute path. The string has no trailing separator except for a root. A component that is not UTF-8 uses U+FFFD for those bytes. When the operating system cannot report the directory, the call throws `DOMException` `OperationError` with `The current directory could not be read.` `cwd` has length 0. `cwd` may run during a host lookup.

`Yuzuko.chdir(directory)` sets that directory for the process. `chdir` waits for a host lookup, for `cwd`, and for `set` or `delete`, and those wait for `chdir`. `directory` is a string or a `file:` URL. A relative string is joined to the current directory before the read check, and that absolute path is the directory the call sets. An empty string names the current directory and succeeds without asking the operating system to change it. The directory may be inside a packaged bundle. The call does not modify the bundle. A path that is not a string or a file URL throws `TypeError` with `The path must be a string or a file URL.` Another URL scheme throws `The URL scheme must be file.` An unusable URL throws `The URL is invalid.` A `file:` URL that is not a path throws `The file URL is invalid.` A path that contains NUL throws `The path must not contain NUL.` A missing path throws `DOMException` `NotFoundError` with `The directory was not found.` A path that exists and is not a directory throws `InvalidStateError` with `The path is not a directory.` When the operating system denies the change, the call throws `NotAllowedError` with `The directory could not be changed.` Any other failure throws `OperationError` with the same message. Those messages do not include operating-system text. `chdir` has length 1. File-system paths are relative to this directory. See File system.

`Yuzuko.build` is a frozen object installed with that object in every build. The main realm and a dedicated worker each receive it when that realm starts. `yuzuko run`, `yuzuko repl`, `yuzuko test`, and a packaged application report the same target. `standalone` is `true` when this process is a packaged application and `false` for `yuzuko run`, `yuzuko repl`, `yuzuko test`, and `yuzuko package`. A dedicated worker reports that same value. An AudioWorklet processor context does not receive the `Yuzuko` object. The property on `Yuzuko` is writable. Assigning it in one realm leaves the other realm's object unchanged. Assigning a field leaves the value unchanged. In strict mode that assignment throws `TypeError`. A classic script continues with the field unchanged. Reading `Yuzuko.build` does not require a permission.

`target` is the Rust target triple of this binary: `aarch64-apple-darwin`, `x86_64-apple-darwin`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-gnu`, or `x86_64-pc-windows-msvc`. `arch` is `x86_64` or `aarch64`. `os` is `darwin`, `linux`, or `windows`. `darwin` is macOS. `vendor` is `apple` on macOS, `unknown` on Linux, and `pc` on Windows. `env` is `gnu` on Linux and `msvc` on Windows. On macOS the triple has no environment component, so `env` is `undefined` and the property is still present. `standalone` is `true` for a packaged application and `false` otherwise. The own enumerable names are `target`, `arch`, `os`, `vendor`, `env`, and `standalone`, in that order.

`Yuzuko.execPath()` returns the absolute path of the running executable. The path is canonicalized when the operating system can, including for a packaged binary. It is not the directory from which the process was launched. When the path cannot be read, the call throws `DOMException` `OperationError` with `The executable path could not be read.` `execPath` has length 0. Extra arguments are ignored. It does not require a permission. A dedicated worker returns the same path.

`Yuzuko.pid` is this process id. `Yuzuko.ppid` is the parent process id. Both are numbers captured when the realm starts. They are writable data properties. Assigning one in a realm does not change the other realm or the process. A dedicated worker reports the same process id and the same parent. That parent is the process that started this one. On Windows, when the parent cannot be read, installing the realm throws `DOMException` `OperationError` with `The parent process could not be read.` On the other targets that read does not throw. Neither property requires a permission.

`Yuzuko.version` is a frozen object. The property on `Yuzuko` is writable. Assigning it in one realm leaves the other realm's object unchanged. Assigning a field leaves the value unchanged. In strict mode that assignment throws `TypeError`. The own enumerable names are `yuzuko` and `v8`, in that order. Both values are non-empty strings. `yuzuko` is this runtime's package version. `v8` is the V8 version this binary was built with. There is no `typescript` field. Reading `Yuzuko.version` does not require a permission. A dedicated worker receives the same strings.

`Yuzuko.memoryUsage()` returns a new plain object of byte counts for this call. The own enumerable names are `rss`, `heapTotal`, `heapUsed`, and `external`, in that order. Each value is a finite number and is at least 0. `rss` is the process resident set size. When the operating system cannot report it, `rss` is 0. `heapTotal`, `heapUsed`, and `external` are the V8 heap statistics of the isolate that is running the call, so a dedicated worker reports that worker's heap and the same process `rss`. A later call reads the figures again. Holding a large `ArrayBuffer` increases `heapUsed` or `external`. `memoryUsage` has length 0. Extra arguments are ignored. Calling it with `new` throws. It does not require a permission.

`Yuzuko.noColor` is a boolean captured when the process starts, before user code runs. It is `true` when `NO_COLOR` is set to a non-empty value at that moment, and `false` when the variable is absent or empty. `FORCE_COLOR` does not change it. `Yuzuko.env.set` and `Yuzuko.env.delete` of `NO_COLOR` do not change a later read. The property is writable. Assigning it in one realm does not change the other realm or the captured boolean. A dedicated worker receives the same boolean. Reading it does not require a permission, including env access. The REPL color policy in CLI still reads the live environment. It is a separate choice.

`Yuzuko.refTimer(id)` and `Yuzuko.unrefTimer(id)` take the number returned by `setTimeout` or `setInterval`. Both have length 1. Extra arguments are ignored. Calling either with `new` throws. The id is converted with ToInt32. A value that does not convert, a non-positive id, or an id that is not a pending timer does nothing and does not throw. A timer starts referenced. A referenced timer keeps the process alive until it runs or is cleared. `unrefTimer` marks that id so the timer does not keep the process alive. When every pending timer is unreferenced and nothing else keeps the process alive, the process exits without running those callbacks, including a callback whose delay has already elapsed. The callback still runs when the event loop stays alive for another reason, and the event loop's next wait still includes that deadline. A dedicated worker that has not closed stays up to receive messages, so an unreferenced timer there still runs, and that worker's next wait includes the deadline. `refTimer` marks the id referenced again. A call during that timer's callback applies to the interval scheduled after the callback returns. `clearTimeout` and `clearInterval` still cancel an unreferenced timer. Host timers stay referenced. A dedicated worker has both functions. Neither requires a permission.

`Yuzuko.exit(code)` ends the process with status `code` and does not return. An omitted or `undefined` code is 0. `-0` is 0. The code is a number primitive from 0 through 255 whose fractional part is 0. A boolean, a string, `null`, a `Number` object, `NaN`, a non-integer, or a number outside that range throws `TypeError` with `The exit code must be an integer from 0 through 255.` and the process stays alive. The function does not apply `ToNumber`. `exit` has length 0. Extra arguments are ignored. `try` / `catch` does not observe a call that ends the process, and later statements in that turn do not run. The first call chooses the status. A later call keeps it. Open windows, trays, playing audio contexts, timers, workers, jobs, and pending promises do not keep the process alive after the call. A call from a dedicated worker ends the whole process, including the main realm, and does not dispatch an error event for that worker. During `yuzuko test` the run stops with that status and the summary line is not printed. During `yuzuko repl` the session ends with that status and does not print a completion value or an exception stack. A timer can call `exit` while a terminal, a Windows console, or a Unix pipe is waiting for input. A Windows pipe blocks until the next line, so a timer's `exit` during that read waits until the line arrives.

## Permissions

`Yuzuko.permissions` is installed with `Yuzuko` in every build, on the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have it. The object is one policy for the process. A dedicated worker uses the same grants as the main realm.

The names are `read`, `write`, `net`, `env`, `run`, and `ffi`. A process that has not installed a policy allows every check. `yuzuko run` installs a policy before the entry runs. An unspecified name starts as `prompt`. `yuzuko repl` installs a policy and does not ask, and it does not read `yuzuko.json`. `yuzuko test` installs a policy and does not ask, and it does not read `yuzuko.json`. An unspecified name stays `prompt`, and a missing grant throws `NotCapable`. `--allow-*` grants only the values it names. `--allow-all` grants every kind. `--deny-*` removes grants. `--no-prompt` does not change the test policy, because the test run never asks. A packaged application whose manifest has `permissions` installs that object with prompts off, and an omitted name is denied. A packaged application whose manifest omits `permissions` allows every check. `yuzuko run --watch` and `yuzuko run --watch-hmr` install the policy once. A restart of the isolate keeps the grants from this process, including a grant stored by a prompt answer.

A denied check throws `Yuzuko.errors.NotCapable`. The value is an `Error`, not a `DOMException`. `name` is `"NotCapable"`. `error instanceof Yuzuko.errors.NotCapable` and `error instanceof Error` are both true. The thrown value is the constructor captured when the realm started. Replacing `Yuzuko.errors.NotCapable` later does not change it. The constructor is on the main realm and in a dedicated worker in every build, including a build with no Cargo features and a build without `fs`. An AudioWorklet processor context does not have it. An operating-system `EACCES` on a file stays `Yuzuko.errors.PermissionDenied` when `fs` is enabled. A path, host, variable, or command is quoted in the message: `Requires read access to "/tmp/note", run again with the --allow-read flag`. An unscoped check has no quote: `Requires env access, run again with the --allow-env flag`. The message has no trailing period. An IPv6 host is shown in brackets, once. The quoted path, host, variable, or command escapes `\`, `"`, control characters, the bidirectional controls U+061C, U+200E, U+200F, U+202A through U+202E, and U+2066 through U+2069, and the separators U+2028 and U+2029, so a newline, a line separator, a terminal escape, or a right-to-left override in the name cannot redraw the prompt. When the current directory cannot be read while a path is resolved, the call throws `DOMException` `OperationError` with `The current directory could not be read.`

`query(descriptor)` and `request(descriptor)` return a promise of `{ state }`. `querySync` and `requestSync` return that object. `state` is `"granted"`, `"denied"`, or `"prompt"`. The object is a plain object. `revoke(descriptor)` and `revokeSync(descriptor)` return `undefined`. Each function has length 1. Calling one with `new` throws. The promise is fulfilled in the same turn. `request` and `requestSync` can block the calling thread while the prompt waits for a line. `query` and `querySync` do not ask. A descriptor that is not an object, including `null` and an array, throws `TypeError` with `The permission descriptor must be an object.` `name` must be a string primitive and one of the six names. Another type does not run `ToString`. A missing or non-string name throws `The permission name must be a string.` An unknown name throws `The permission name is not supported.` The detail field is `path` for `read`, `write`, and `ffi`, `host` for `net`, `variable` for `env`, and `command` for `run`. An omitted detail asks about the whole kind. A present detail must be a non-empty string primitive. An empty string or another type throws `The permission path must be a string.`, `The permission host must be a string.`, `The permission variable must be a string.`, or `The permission command must be a string.` A path or a name that contains NUL throws `The permission path must not contain NUL.` or `The permission name must not contain NUL.` A bad descriptor throws before a promise is returned.

A query with no detail is `"granted"` only when that kind is allowed as a whole. A list of paths, hosts, or names leaves the unscoped query at `"prompt"`. A deny of the whole kind is `"denied"`. A deny of one resource leaves a query of the kind, and a query of a different resource, at `"prompt"` when no broader deny applies. For `net`, a query of a host with no port is `"granted"` only by allow-all or by a rule that names that host with no port. A rule for one port leaves that query at `"prompt"`. A deny of `example.com:443` does not deny a query of `example.com`.

`revoke` of a kind, with no detail, hides the base allow for that kind and clears session allows and session denies. The next query is `"prompt"` while a sticky deny is absent. A sticky deny from `--deny-*` or from `false` in the config stays `"denied"`. `revoke` of one resource stores a session deny for that resource. A later `request` can grant it again, except where a sticky deny still matches. On a process that has not installed a policy, `query` and `request` report `"granted"`. `revoke` on that process installs an allow-all policy with prompts off and then applies the revoke.

The prompt is printed to stderr when the policy allows prompts and stdin is a terminal:

```text
┏ ⚠ Yuzuko requests read access to "/tmp/note".
┠─ To allow: run again with --allow-read
┗ Allow? [y/n/a] (y = yes, n = no, a = allow all read)
```

`y` and `yes` grant that resource for this process. `a` and `all` grant the whole kind for this process. Any other line stores a session deny, so the next request does not ask again. An unscoped request treats `y` as a grant of the whole kind. A `y` or a session deny for an `env` name that ends in `*`, or for the `net` host `*`, applies to that call only and is not stored, because a stored rule reads that text as a wildcard. A path grant from `y` stores the requested path and its canonical spelling. It does not store a different file reached by following a symlink and then applying `..`. When that grant does not cover every candidate, the call stays denied. A `y`, a session deny, or `revoke` for a run command that contains `/` or `\` stores the absolute path resolved when the answer is read. That resolution uses the current directory, or the child directory when the check is `spawn` with `cwd`. The stored path is the file the operating system would execute when that file is the requested path or its canonical spelling. It does not store a different file reached by following a symlink and then applying `..`. A later check uses the stored path and does not join the relative command to a new directory. A bare command stores that bare name. `--no-prompt`, and a stdin that is not a terminal, make `request` return `"denied"` and leave the stored state at `"prompt"`. `yuzuko repl` and a packaged application do not ask. A prompt answer is read while the policy lock is held, so two requests ask one after another. The prompt does not call back into JavaScript. Unread input on that terminal is discarded before the line is read, so a keystroke or injected input that arrived before the question does not answer it. A failure to discard that input does not reject the request.

Flags belong before the entry for `yuzuko run`, beside the other test flags for `yuzuko test`, and as the only arguments of `yuzuko repl`. A flag after the `yuzuko run` entry is `Yuzuko.args`. `yuzuko package` rejects these flags. The flags are `-A`, `--allow-all`, `--allow-read` (`-R`), `--allow-write` (`-W`), `--allow-net` (`-N`), `--allow-env` (`-E`), `--allow-run`, `--allow-ffi`, the matching `--deny-read`, `--deny-write`, `--deny-net`, `--deny-env`, `--deny-run`, and `--deny-ffi`, and `--no-prompt`. There is no `--deny-all` and no short deny flag. `--allow-sys`, `--allow-import`, and a named permission set are unknown flags and the process exits 2. A value follows `=` and is a comma-separated list. A doubled comma is one comma, so `--allow-read=a,,b,c` is `a,b` and `c`. `--allow-read=,,` is one item whose text is a comma. An empty `=` exits 2 with `--allow-read requires a value.` An empty item exits 2 with `A permission list contains an empty item.` `-A=foo` and `--no-prompt=` exit 2 with `--allow-all does not take a value.` or `--no-prompt does not take a value.` A bare flag allows or denies the whole kind. A value does not follow the flag as a separate argument.

`--allow-all` allows every kind and does not clear a deny. A later `--deny-*`, and a `false` from the config, still deny. The config is applied first, then allow flags, then `--allow-all`, then deny flags. A relative path on a flag is resolved against the current directory when the flag is parsed and stored absolute. `read`, `write`, and `ffi` values are paths. A `run` value is a path when it contains `/` or `\`, and a command name otherwise. `net` and `env` values stay as written.

`yuzuko.json` and `yuzuko.jsonc` accept `permissions`. Unknown keys inside it are errors. Each name is `true`, `false`, or an array of strings. `true` allows the kind. `false` denies the kind. An array allows those values and does not deny the rest. An empty array grants nothing. An omitted name is `prompt` for `yuzuko run` and denied for a packaged application. `{}` is valid. For a packaged application it denies every kind. A relative path in the file is resolved against the config directory for `yuzuko run`, and against the bundle `app/` directory at a packaged launch. An absolute path stays absolute. `yuzuko package` and `yuzuko run` reject a value that cannot be stored, before a bundle is written and before the entry runs. The manifest copies the object when it is present and omits the key when it is absent. An update that rewrites `version` and `entry` leaves `permissions` in place. A manifest whose `permissions` value is present and is not an object fails to launch.

A path grant is the normalized absolute path. `.` and `..` are collapsed without reading the file system. The grant covers that path and a descendant. `/tmp/project` covers `/tmp/project/note` and does not cover `/tmp/project2`. A check resolves the request in operating-system order as well as lexically. The operating system follows a symlink and then applies `..`, including when the final component is missing. `stat`, `lstat`, and `remove` do not follow a final symlink: the check names that directory entry. A parent symlink is still followed, and `..` still applies after it. The candidates are the lexically normalized path, its canonical spelling, the operating-system path, and that path's canonical spelling. On Windows a `\\?\` or `\\?\UNC\` prefix is removed before the comparison. On Windows a normal component also drops trailing dots and spaces, and drops the text from the first `:`, before the comparison. `secret.txt.`, `secret.txt `, `secret.txt:hidden`, and `secret.txt::$DATA` compare as `secret.txt`. A drive prefix such as `C:` stays a prefix. A component that becomes empty keeps its original spelling. Dropping stops at `.` or `..`, and such a component is compared as `.` or `..`. `.. ` and `... ` leave the directory the way `..` does, although Win32 keeps `.. ` as a name, so the check is stricter than the operating system there. The absolute path opened by the operating system keeps the caller's component spelling. Comparison is case-insensitive on macOS and Windows and case-sensitive on Linux. The check denies the call when any candidate matches a deny. It allows the call when every candidate matches an allow. A normal child of a file cannot be named, including where the operating system reports that child as missing. `..` still leaves the file. When the operating-system walk cannot name the file, the check does not throw `OperationError`. The lexical candidates still decide a deny or a prompt. A walk that fails after those candidates are all allowed is denied, so the failure cannot skip the operating-system path or reveal whether a component exists. A `..` that leaves through a symlink is outside a grant of the directory that contains the symlink. The denial names the requested path, not the other file. A grant of `/tmp` does not by itself cover a candidate whose canonical path is `/private/tmp`. A deny of a parent covers a child. A session deny of the same path can be replaced by a later session grant. A sticky deny is kept. A prompt yes stores the requested path and its canonical spelling, and does not store the other file.

A net rule is a host, or `host:port`, or `*:port`. An IPv6 host is written `[::1]` or `[::1]:443` and stored without brackets. A checked host drops one surrounding pair of brackets before the comparison, so `[::1]` and `::1` are the same host. A host with no port matches every port, including `0`. A host with a port matches that port. `*:443` matches every host on that port. Host comparison is case-insensitive. A host that parses as an IP address has one spelling. An IPv6 address uses the canonical text, so `[2001:0db8::1]` and `2001:db8::1` are `2001:db8::1`. An IPv4-mapped IPv6 address is the IPv4 address, so `[::ffff:127.0.0.1]` and `[::ffff:7f00:1]` are `127.0.0.1`. A zone identifier does not parse and stays in the host string. The first check uses the host string the caller passed. A trailing DNS root dot is removed, so `evil.com.` and `evil.com` are the same host. A Unicode domain and its punycode A-label are the same host. `localhost` and `127.0.0.1` are different grants. `fetch`, `XMLHttpRequest`, `EventSource`, `WebSocket`, `WebSocketStream`, `WebTransport`, and `autoUpdate` check a resolved address again before the connection when it is loopback, private, link-local, unique-local, site-local (`fec0::/10`), NAT64 (`64:ff9b::/96`), shared (`100.64.0.0/10`), multicast, broadcast, or unspecified. That includes `169.254.169.254` and an IPv4-mapped form of one of those addresses. A grant of the name does not cover that address. An address outside those ranges is not checked again. `2001:db8::/32` and a public address such as `8.8.8.8` are in that outside set. When the lookup returns more than one address, the connection uses only an address that this check allows. When every resolved address is denied, `fetch` and `XMLHttpRequest` throw `NotCapable`. `EventSource` treats that failure as a reconnect. `EventSource` checks the host again before each connection, including a reconnect. A denial does not contact the host and schedules another reconnect. `WebSocket` and `WebSocketStream` dispatch `error` and a close with code 1006. `WebTransport` rejects `ready` with the denial message. A denied address is not connected. An HTTP/3 `Alt-Svc` alternative is checked for that alternative's host and port before the connection. A denied alternative is not contacted, and the request uses HTTP/2 or HTTP/1.1 when the origin itself is allowed. `listenDatagram`, `listenTcp`, and `listenHttp` check `127.0.0.1` and port `0` when the options are omitted. A present hostname is checked before `localhost` is rewritten to `127.0.0.1`. `connectTcp` and `Datagram.send` check the destination. `accept`, `receive`, and a later read or write on a socket that already bound are not checked again. `fetch`, `XMLHttpRequest`, `EventSource`, `WebSocket`, `WebSocketStream`, and `WebTransport` check `http:`, `https:`, `ws:`, and `wss:` against the URL host and its default port. `blob:` and `data:` are not a net check. `file:` fetch is a read check and stays inside the entry directory. An `http:` or `https:` `importScripts` URL is a net check and throws `NotCapable` before the fetch. Each redirect that `fetch`, `XMLHttpRequest`, or `importScripts` follows is checked again before the next connection. A denied hop rejects `fetch` and `XMLHttpRequest` with `NotCapable`, and `importScripts` throws `NotCapable`. A JavaScript, TypeScript, or WebAssembly evaluation import is not a read check when every resolved form of the file is that kind of module. The forms are the lexical path and, when the file or its parent exists, the canonical path. Script forms use `.js`, `.mjs`, `.cjs`, `.ts`, or `.mts`. A WebAssembly form uses `.wasm`. A `.json` module uses `.json` on every form. A `.d.ts` or `.d.mts` form is rejected and is not read. Any other file, including a script name whose target has another extension, is not read. That import throws `TypeError` with `<path> must be imported with { type: "text" } or { type: "bytes" }`. An import with type `text`, `bytes`, or `json` requires read and throws `NotCapable`. `{ type: "json" }` on a file whose extension is not `.json` requires that read and then parses the file as a script, except a `.wasm` file, which stays a WebAssembly module. A `file:` worker script and a `file:` `importScripts` load require the same read. A worker URL whose host is `127.0.0.1`, `localhost`, or `web-platform.test` loads the entry-directory file for that URL path, on any port and scheme other than `file:`, `data:`, and `blob:`, and requires the same read. Every lexical and canonical candidate must be allowed, so a symlink is denied unless its target is allowed too. `data:` and `blob:` worker scripts are not a read check. `Yuzuko.autoUpdate`'s feed request is a net check. A denial rejects that call with `NotCapable` and `Requires net access, run again with the --allow-net flag`.

An env rule is a variable name or a name ending in `*`. `AWS_*` matches `AWS_REGION`. `*` matches every name. On Windows the name comparison is case-insensitive. On the other targets it is case-sensitive. `get`, `set`, `delete`, and `has` check the name after the name is validated, so an empty name, `=`, or NUL still throws `TypeError`. `toObject` requires env access for the whole environment. A list of names does not grant `toObject`. `spawn` checks each name in `options.env`. Creating the child also requires env access for the whole environment when `options.clearEnv` is not `true`, because the child inherits every variable the overlay does not replace. `clearEnv: true` does not require that whole-environment grant. An omitted `env` without `clearEnv: true` is that same whole-environment check.

A run rule that contains `/` or `\` matches that normalized path and does not cover a descendant. A rule that is a bare name matches a bare command only. It does not match a command that contains `/` or `\`. A command that contains no `/` or `\` does not match a path rule, including when `PATH` would find that file. On Windows a bare `git` matches a bare `git.exe`, and the `.exe` suffix is compared case-insensitively. A bare name grant is the executable that name finds on `PATH` when the policy is installed. On Windows a name with no extension is looked up as that name with `.exe` appended. A relative `PATH` entry is joined to the current directory at that moment. `spawn` resolves a bare command again with the `PATH` the child will have after `options.env` replaces or removes `PATH`. A relative entry in that `PATH` is joined to the child's directory. The child runs only when that file is the one the grant names, and the operating system receives that absolute path. A `PATH` that names a different file does not run it. When the child's `PATH` does not name the command, `spawn` throws `NotCapable` and does not ask the operating system to search. `query` of a bare command reports the name rule and does not resolve `PATH`. A command that contains a separator matches only a path rule for that normalized path. The match is the file the operating system would execute. A rule for another path does not match. That includes the path left after collapsing `..`, a symlink whose target is a different file, and a relative command resolved from a different directory. A rule that names the file that would run does match. A prompt answer and `revoke` for such a command store the absolute path resolved when the answer is read, as described above, and a later check uses that stored path. When `options.cwd` is set, a relative command is resolved from that directory, because that is the directory the operating system uses. `spawn` resolves a command that contains `/` or `\` once. The run check and the operating system use that absolute file, so a symlink changed after the check does not change the program. The prompt names that file. The `NotCapable` message names the caller's command, so it does not reveal where a symlink leads. `spawn` checks read access to `options.cwd` when that directory is set, then the program, then each environment name in `options.env`, then env access for the whole environment unless `options.clearEnv` is `true`. Whether `cwd` exists is checked after those permissions, so a missing grant does not reveal whether the directory exists. A relative `options.cwd` is joined to the current directory before that read check, and the child uses that absolute directory. The child is created after those checks succeed. When `run` is not granted as a whole, a command that contains `/` or `\` is passed as an absolute path. That path is the file that would run, or, when the file cannot be resolved, the command joined to the current directory or to `options.cwd`. The operating system does not receive the relative command. When `run` is granted as a whole, it receives the caller's command. When `run` is not granted as a whole, `spawn` rejects the child if the environment it will receive contains a variable whose name begins with `LD_` or `DYLD_`. The prefix comparison ignores ASCII case. An empty value is still present. Setting the variable to `null` in `options.env` removes it. The denial is the unscoped run message. `--allow-run` with no list and `--allow-all` grant `run` as a whole and accept those variables.

`dlopen` checks the library path after the path is validated and before the library is opened. A path that contains `/` or `\` uses the same path rules as `read` and `write`. That path is opened as the absolute path from the check. On Windows the open uses `LoadLibraryExW` with `LOAD_WITH_ALTERED_SEARCH_PATH`, so a relative name is not resolved through the DLL search order. On Unix the same absolute path is passed to `dlopen`. A path with no separator is allowed only when `ffi` is granted as a whole, because the system loader searches for that name and does not open a file under the current directory. A directory grant does not cover it. `--allow-ffi` and `--allow-all` do. A query of that string still names the relative path.

File-system calls check before the operating-system call, including before an asynchronous call leaves the realm thread. A relative path is joined to the current directory before that check, without removing `.` or `..`, and the operating system opens that absolute path. A content read or write opens that path once and then uses the file descriptor. `open`, `readFile`, `readTextFile`, `writeFile`, `writeTextFile`, `truncate`, and `copyFile` check the opened file again, without prompting. `copyFile` checks the source for read and the destination for write. The check uses the path the operating system reports for that descriptor. When the opened file is not granted, or that path cannot be read, the call throws `NotCapable` naming the requested path and does not read or write the other file. A process that has not installed a policy does not read the descriptor path. Creating a file can leave an empty file when the opened file is then rejected. The contents are not written, and the empty file is not removed. `stat` and `lstat` require read of the directory entry. A final symlink is not resolved for that check, so the grant covers the link and does not have to cover its target. A parent symlink is still followed, and `..` still applies after it. `stat` then follows the final symlink and reports the target, including when that target is outside the grant. `lstat` reports the link. Neither call checks a file descriptor again. `remove` without `recursive` requires write of the directory entry the same way, deletes that entry, and does not follow a final symlink or require write of its target. `remove` with `recursive: true` uses that entry check and is denied when a deny rule names the path or a descendant, so a denied child blocks deletion of the tree. It does not check a file descriptor again. `readDir`, `chmod`, `chown`, `rename`, `link`, `symlink`, `readLink`, `utime`, and `watchFs` keep using the path, follow a final symlink when that is the file the operating system would open, and do not check a file descriptor again. A later `chdir` does not choose a different file. `chdir` uses that same absolute path for its read check and for the directory it sets. `readFile`, `readTextFile`, `stat`, `lstat`, `readDir`, `realPath`, `readLink`, and `watchFs` require `read`. `open` requires `read` when `read` is set and `write` when the flags write, append, truncate, or create. An open that has neither is not checked. `create`, `writeFile`, `writeTextFile`, `mkdir`, `remove`, `truncate`, `chmod`, `chown`, and `utime` require `write`. `copyFile` requires `read` of the source and `write` of the destination. `rename` requires `read` and `write` of both paths. `link` requires `read` and `write` of the old path and `write` of the new path, because the new name is the same file. `symlink` requires `read` of the path the link will name and `write` of the new path. An absolute target is checked as written. A relative target is joined to the parent of the new path. A Windows junction is checked from the current directory. The stored link text is the caller's string. `umask` requires `write` with no path. `makeTempDir` and `makeTempFile` require `write` of `dir`, or of the system temporary directory when `dir` is omitted. Methods on an open `FsFile` are not checked again. The bundle guard still applies after the permission check. `chdir` requires `read` of the target after the empty-string case returns. The host denial is `NotCapable` with the read message above. When the operating system denies the change, `chdir` throws `NotAllowedError` with `The directory could not be changed.`

`pickFiles` with `"open"` stores a session read grant for each returned path. `"save"` and `"directory"` store a session read grant and a session write grant. `filedrop` stores a session read grant for each path. `filehover` does not. A sticky deny of that path stores nothing. These grants are session grants, so `revoke` of the kind clears them. Signals are not checked.

## Execution model

The entry point is an ES module, in JavaScript or TypeScript. Classic scripts are not supported. Module top-level bindings do not leak onto `globalThis`.

```js
const win = new Yuzuko.Window({
  title: "yuzuko",
  width: 1280,
  height: 720,
});
const ctx = win.surface.getContext("2d");
ctx.fillStyle = "#141820";
ctx.fillRect(0, 0, 1280, 720);

win.addEventListener("pointerdown", (e) => {
  ctx.fillRect(e.offsetX, e.offsetY, 4, 4);
});

win.addEventListener("compositionupdate", (e) => {
  win.setCompositionCaret(24, win.clientHeight - 32, 200, 24);
});

const tools = new Yuzuko.Window({ title: "tools", width: 400, height: 600 });
```

The `fillRect` above is presented on the next turn of the event loop. `requestAnimationFrame` is how a later frame draws again.

`Window` extends `EventTarget`, not `OffscreenCanvas`. `win.surface` is a `Yuzuko.WindowSurface`. It is not an `OffscreenCanvas` and cannot be transferred to a worker. It has the same drawing methods as `OffscreenCanvas`: `width`, `height`, `getContext`, `convertToBlob`, and `transferToImageBitmap`. `transferControlToOffscreen()` returns an `OffscreenCanvas` that presents in that window. Calling it again, or calling it after `getContext`, throws `InvalidStateError`. After it returns, drawing methods on the surface throw `InvalidStateError`. The returned canvas is what a worker receives. The constructor `width` and `height` are CSS pixels and default to 1280×720 when omitted. `x` and `y` are the frame's initial origin in CSS pixels. When both are omitted the window is centered on the primary monitor, or placed at `0, 0` when that monitor does not exist. If only one of `x` or `y` is set, the other is `0`. `resizable` defaults to `false` and can be assigned after creation. `decorations` and `active` are creation-only and default to `true`. `transparent` defaults to `false` and is creation-only. It asks the OS to composite the window's alpha. Unpainted pixels and the area outside the fitted bitmap are clear instead of black. `visible` defaults to `true`; `false` creates the window hidden. `maximized` defaults to `false`. `minWidth`, `minHeight`, `maxWidth`, and `maxHeight` limit the client size. An omitted edge is unset. Setting only one maximum uses 100000 CSS pixels for the other edge when telling the OS. `resizeTo` and `resizeBy` clamp into those limits. The initial `width` and `height` are clamped the same way. There is no `reload`. The constructor `title` is the initial OS title. `WindowSurface.title` reads and writes that title. `Window` has no `title` attribute.

| Member | Meaning |
| --- | --- |
| `surface` | The `WindowSurface` drawn inside this window. Its bitmap does not follow later window resizes |
| `resizable` | Whether the OS window can be resized. The default is `false`. Assigning it updates the live window |
| `clientWidth` / `clientHeight` | Window client size in CSS pixels |
| `devicePixelRatio` | That window's winit scale factor |
| `surface.title` | OS window title. The constructor `title` sets the initial value. The default is `"yuzuko"` |
| `cursor` | `"default"`, `"pointer"`, `"crosshair"`, `"text"`, `"none"`, and the other winit cursor names. Matching is case-insensitive. An unrecognized name is ignored |
| `screenX` / `screenY` | Client origin in CSS pixels. `screenLeft` and `screenTop` are the same values |
| `innerX` / `innerY` | Client origin. Same as `screenX` / `screenY` |
| `outerX` / `outerY` | Frame origin in CSS pixels, including the title bar |
| `visible` | Whether the OS window is shown. The constructor defaults to `true`. `false` creates it hidden until `show()` |
| `alwaysOnTop` | Keep the window above normal windows. The default is `false` |
| `decorations` | Whether the OS window has a title bar and borders. Set only in the constructor. The default is `true` |
| `active` | Whether the window is focused when it opens. Set only in the constructor. The default is `true` |
| `maximized` | Whether the window opens maximized. Not fullscreen. The default is `false` |
| `transparent` | Composite the window's alpha. Set only in the constructor. The default is `false` |
| `minWidth` / `minHeight` | Minimum client size in CSS pixels. Unset when omitted |
| `maxWidth` / `maxHeight` | Maximum client size in CSS pixels. Unset when omitted |
| `requestAnimationFrame` / `cancelAnimationFrame` | Runs before this window's rendering update, at the refresh rate of the monitor that window is on. A Canvas 2D or `bitmaprenderer` change is presented on the next event-loop turn without this callback. After the window is closed, `requestAnimationFrame` returns `0` and does not queue a callback |
| `resizeTo(width, height)` | Sets the client size in CSS pixels, clamped to `minWidth` / `maxWidth` and `minHeight` / `maxHeight`. Does not resize `surface` |
| `resizeBy(x, y)` | Adds CSS pixels to the client size, with the same clamp. Does not resize `surface` |
| `moveTo(x, y)` / `moveBy(x, y)` | Move the frame in CSS pixels. Positive `y` is downward |
| `show()` / `hide()` | Show or hide the OS window |
| `focus()` | Focus this window |
| `close()` | Dispatches a cancelable `close` event on this window |
| `alert(message)` | Shows a modal dialog with one accept button. The label starts as OK. The message is `ToString`. Blocks until the user dismisses it |
| `confirm(message)` | Shows a modal dialog with accept and cancel buttons. The labels start as OK and Cancel. Returns `true` for the accept button |
| `prompt(message, defaultValue)` | Shows a modal dialog with a text field and accept and cancel buttons. The labels start as OK and Cancel. Returns the entered string, or `null` when cancelled. An omitted `defaultValue` is `""` |
| `pickFiles(options)` | Shows a modal open, save, or directory dialog. Returns absolute paths, or `null` when cancelled |
| `setContextMenu(menu)` | Stores the menu an uncancelled context click shows. `null` clears it. Does not pop a menu |
| `showContextMenu(menu, x, y)` | Shows `menu` at CSS pixels in the client area. Does not replace `setContextMenu` |
| `setImeAllowed(allowed)` | IME for this window. The default is `false` |
| `setCompositionCaret(x, y, width, height)` | IME candidate rectangle, in CSS pixels relative to this window's client origin |
| `requestPointerLock()` / `exitPointerLock()` | Pointer lock for this window |
| `requestFullscreen()` / `exitFullscreen()` | Fullscreen for this window |
| `matchMedia(query)` | A `MediaQueryList` for this window's CSS size, `devicePixelRatio`, and display preferences. A `change` event fires when the result changes |

`WindowSurface.objectFit` is `"scale-down"` by default. `"none"`, `"contain"`, `"cover"`, and `"fill"` are the other values. Matching is case-insensitive. Any other value is ignored. The surface bitmap is centered in the window. Pixels outside that rectangle are black. `"none"` does not scale. `"contain"` fits the whole bitmap inside. `"cover"` covers the window and may crop. `"fill"` stretches to the window. `"scale-down"` is `"none"` when the bitmap already fits, and `"contain"` otherwise.

`WindowSurface.imageRendering` is `"auto"` by default. `"smooth"`, `"crisp-edges"`, and `"pixelated"` are the other values. Matching is case-insensitive. Any other value is ignored. `"auto"` and `"smooth"` sample bilinearly. `"crisp-edges"` samples the nearest pixel. `"pixelated"` scales to the nearest integer multiple with nearest-neighbor, then samples bilinearly to the final size. `"optimizeQuality"` is `"smooth"` and `"optimizeSpeed"` is `"pixelated"`. The property does not change a bitmap that is already the size of its fitted rectangle.

`WindowSurface.visibilityState` is `"visible"` or `"hidden"`. A new surface is `"visible"`. `visibilitychange` fires on the surface when the value changes. It does not bubble and cannot be cancelled. The state follows whether that OS window is on screen: minimized, hidden, or fully covered is `"hidden"`. Losing focus does not hide the surface. Closing the window sets `"hidden"` and fires `visibilitychange` when the surface was visible. `requestAnimationFrame` keeps running while the surface is hidden.

`new OffscreenCanvas(w, h)` is a buffer with no window. `width` and `height` on an `OffscreenCanvas`, and the same attributes on a `WindowSurface`, are `[EnforceRange] unsigned long long`. A finite value is truncated toward zero. A non-finite value, or a value outside 0 through `2^53 - 1`, throws `TypeError`. Assigning either attribute reallocates that bitmap. On a `WindowSurface` the assignment does not change the window's CSS size. The initial surface bitmap is device pixels: `round(cssWidth * devicePixelRatio)` by `round(cssHeight * devicePixelRatio)`. On a 2x display a 1280×720 window starts with a 2560×1440 surface. `clientX`, `clientY`, `pageX`, `pageY`, `offsetX`, and `offsetY` are CSS pixels from the window's top-left, with `y` growing downward.

`matchMedia` understands `screen` and `all`, `not` / `and` / `or`, and comma-separated lists. Width and height use `px`. `min-width` and `max-width` remain, and level 4 ranges such as `(width >= 800px)` and `(200px <= width <= 800px)` work for `width`, `height`, `resolution`, and `device-pixel-ratio`. `resolution` accepts `dppx`, `x`, `dpi`, and `dpcm`. `1dppx` is `devicePixelRatio`. `device-pixel-ratio` and `-webkit-device-pixel-ratio` are the same value, including the `min-` and `max-` prefixes. Also recognized: `orientation`, `color-gamut` (`srgb`, `p3`, `rec2020`), `prefers-color-scheme`, `prefers-reduced-motion`, `prefers-contrast`, and `pointer`. An unknown feature or a broken query does not match. `MediaQueryList` and `MediaQueryListEvent` cannot be constructed with `new`.

There is no global `requestAnimationFrame` on the main global. A frame belongs to a surface. A dedicated worker has `requestAnimationFrame` and `cancelAnimationFrame`. A frame there runs the callback, then copies each transferred window canvas into the window that owns it. That window presents the copy on the next turn of the main event loop.

A window's animation frames run at the refresh rate of the monitor that window is on. On macOS that rate is the screen's maximum, so a variable-refresh display runs at its maximum while frames are scheduled. Linux and Windows use the monitor's current mode. The next frame after the window moves uses the new monitor. A rate that cannot be read, a rate below 10 Hz or above 1000 Hz, and a headless window run at 60 Hz. A dedicated worker uses the slowest of those rates among the open windows whose canvas it holds. Each worker follows only the canvases it holds. A window that has not transferred a canvas does not count, and `new OffscreenCanvas` does not count. With no transferred window canvas, the worker runs at 60 Hz. Closing a window, or moving one to another monitor, applies the next time that worker schedules a frame.

`requestIdleCallback(callback)` and `cancelIdleCallback(handle)` are on the main `globalThis`. `IdleDeadline` cannot be constructed with `new`. An idle period is at most 50ms. It also ends at the next timer or the next window animation frame when that comes first. The period does not start when less than 5ms remains before that timer or frame. A positive `timeout` still runs the callback then: `didTimeout` is true and `timeRemaining()` is 0. A callback scheduled during an idle period runs in a later period, and that later period does not start until the current deadline. Dedicated workers do not have these functions. A thrown callback is reported on `globalThis`.

### Dialog labels

`Yuzuko.setDialogLabels(labels)` replaces the button labels the runtime draws. It is installed on the main realm when `window` is enabled. A dedicated worker does not have it. The call does not open a dialog, does not require a window, and works in a headless process, including `yuzuko test`. Omitted `labels`, or `undefined`, changes nothing. `null`, a string, or any other non-object throws `TypeError`. Each present field must be a string. A number is not converted with `ToString`. An empty string or a string that contains NUL throws `TypeError`. An omitted field keeps its current label. Unknown properties are ignored. The fields are read in the order `ok`, `cancel`, `open`, `save`, `select`. A thrown getter stops the call and leaves every label unchanged.

The initial labels are `OK`, `Cancel`, `Open`, `Save`, and `Select`. `ok` is the accept button on alert, confirm, and prompt. `cancel` is the other button on confirm and prompt, and on a Linux file chooser. `open`, `save`, and `select` are the accept buttons on a Linux open, save, and directory chooser. The message and the window title stay the caller's strings. Intl and ICU do not supply these words.

macOS alert, confirm, and prompt use `ok` and `cancel`. The Windows prompt uses them and widens its buttons when a label is longer than the English word. Linux alert, confirm, prompt, and the file chooser use the configured labels. Linux alert and confirm do not use GTK's stock button text. Windows alert and confirm use `MessageBox`, so their buttons stay in the operating-system language and ignore these labels. macOS file dialogs and Windows file and directory dialogs use the system buttons and ignore them too. On Linux `_` in a label is shown as itself. On the Windows prompt `&` is shown as itself.

### File picker

`pickFiles(options)` blocks until the native dialog returns, the same way `alert` does. Omitted `options`, or `undefined`, uses the defaults. `null`, a string, or any other non-object throws `TypeError` before the window is checked. A closed window throws `InvalidStateError`. A headless process, including `yuzuko test` and `YUZUKO_HEADLESS=1`, throws `NotSupportedError`. There is no `pickSaveFile`, no `pickDirectory`, and no File System Access API.

`mode` is `"open"`, `"save"`, or `"directory"`. An omitted `mode` is `"open"`. Any other value throws `TypeError`. `"open"` selects existing files. `"save"` asks for one file name. `"directory"` selects one directory and can create a directory. `multiple` applies only to `"open"`. `filters` applies to `"open"` and `"save"`. `suggestedName` applies only to `"save"`. A field that does not apply throws `TypeError`. Unknown properties are ignored.

`multiple` defaults to `false` and must be a boolean when present. `filters` is an array of `{ name, extensions }`. `extensions` is an array of extensions without a leading dot. A token that is exactly `*` selects every file. Other extensions in that same filter are ignored, and that filter may sit beside other filters. An empty `extensions`, a missing `extensions`, or a value that is not an array throws `TypeError`. An extension that is empty or contains `/`, `\`, `.`, NUL, or `*` throws `TypeError`. `name` and each extension are converted with `ToString`. A `name` that contains NUL throws `TypeError`. An empty or omitted `name` is `All files` when the filter selects every file, and otherwise the extensions joined by `, `. `suggestedName` is a file name for `"save"`. An empty name, `/`, `\`, or NUL throws `TypeError`. `.` is allowed.

`"open"` with `multiple: false`, `"save"`, and `"directory"` each return an array of one path. Cancelling, or accepting an empty selection, returns `null`. Each returned path receives a session read grant. `"save"` and `"directory"` also receive a session write grant. A sticky deny of that path stores nothing. The paths are absolute and are not canonicalized. Linux shows a GTK 3 chooser and does not parent it to the winit window. Windows and Linux show each filter, including one that selects every file, as its own choice. macOS keeps one allowed-type list: extensions from every filter are united, and there is no separate choice for each `name`. If any filter selects every file, or `filters` is omitted, macOS allows every file. `"directory"` does not use those filters. macOS uses `NSOpenPanel` and chooses directories only. Linux shows a GTK 3 folder chooser. Windows shows `SHBrowseForFolder`, parented to the window, with `BIF_RETURNONLYFSDIRS`, `BIF_NEWDIALOGSTYLE`, and `BIF_EDITBOX`. The dialog title is the window title. On Linux the chooser's accept button is `open`, `save`, or `select`, and its cancel button is `cancel`. macOS and Windows file dialogs use the system buttons.

### File drop

A file dragged over a window dispatches `filehover` on that window. Leaving without a drop dispatches `filehovercancel`. Releasing the files dispatches `filedrop`. These events do not bubble and cannot be cancelled. They target the window, not `surface`, and they are not delivered to `Yuzuko`. These events do not carry a `DataTransfer`. There is no HTML drag-and-drop.

`filedrop` and `filehover` carry `paths`, a new array of absolute paths in the order the operating system reported them. `filedrop` stores a session read grant for each path. `filehover` does not. A sticky deny of that path stores nothing. The paths are not canonicalized. A relative path is joined to the process current directory. Several files in one hover or one drop become one event. `filehovercancel` has no `paths`. macOS, Windows, and X11 deliver these events. Wayland does not. A headless window, including `yuzuko test`, does not receive an operating-system drop. `Yuzuko.__test.inject` delivers the same events when `YUZUKO_TEST_INPUT=1`.

### Frame order

Canvas 2D drawing, a `bitmaprenderer` update, a bitmap copied from a worker frame, and a change to `objectFit` or `imageRendering` are presented on the next turn of the event loop. That includes drawing at the top level of a script. The present runs once. It does not repeat until one of those changes again, and it does not queue an animation frame. A due animation frame still runs first, and drawing done by that callback is included in the same present. WebGPU still updates only in the steps below.

For each window:

1. Dispatch that window's OS events to its `Window`, one at a time, and run a microtask checkpoint after each event.
2. When an animation frame is due, run the `requestAnimationFrame` callbacks already queued on that surface. Callbacks queued during those callbacks wait for the next frame. If this frame is still running when that next frame's deadline has passed, the next frame runs one refresh period after this frame returns, and the event loop pumps the operating system before it.
3. Run a microtask checkpoint.
4. When that frame ran, or the canvas changed as described above, update that surface. For WebGPU, follow "update the rendering of a WebGPU canvas": expire the current texture and present. For Canvas 2D, rasterize the recorded commands and present. For `bitmaprenderer`, present the transferred bitmap.
5. If another animation frame is queued, request a redraw of that window.

When only timers or idle callbacks remain, the event loop sleeps until the next timer or idle deadline.

`getCurrentTexture()` returns the same `GPUTexture` until that surface's rendering update for the frame. The next call after the update returns a new texture.

`close` is cancelable. If `preventDefault()` is not called, only that window is destroyed. While `close` is being dispatched, and while the `visibilitychange` that follows a close that was not cancelled is being dispatched, the window is still open, so `requestAnimationFrame` queues a callback and returns a positive handle. Destroying the window drops callbacks queued on it, including one queued in those listeners. After the window is closed, `requestAnimationFrame` returns `0` and does not queue a callback or request a redraw. `0` is never a live handle. `cancelAnimationFrame` does nothing for an unknown handle, including `0`. A callback that is already running can call `close()` and then `requestAnimationFrame`, which returns `0`. Other windows and outstanding timers or promises remain. When no `Window` is open and the task queue is empty, the process exits with status 0. An uncaught exception and an unhandled rejection exit with status 1. `Yuzuko.exit` ends the process with the status from that call before this idle exit. A promise microtask runs before the next macrotask. Posting a V8 foreground task wakes the event loop.

### Headless mode

`YUZUKO_HEADLESS=1` makes `Window` skip OS window creation. The drawing buffer and animation frames (60 Hz) still run on the object. `yuzuko test` creates windows headless. Input injection is `Yuzuko.__test`. That command installs it only when `YUZUKO_TEST_INPUT=1`. `yuzuko run` and `yuzuko repl` do not install it. Web-platform tests run under `cargo test`, not under a `yuzuko` subcommand.

## Input

OS events come from winit 0.30. The mapping below is fixed.

`PointerEvent` is the source of truth. Its target is that window's `WindowSurface`, not `globalThis`. The path is the surface, then the `Window`. Capturing listeners on the window run first, then listeners on the surface, then bubbling listeners on the window when the event bubbles. `stopPropagation()` skips the rest of that path. `stopImmediatePropagation()` also skips the remaining listeners on the current object. During dispatch, `composedPath()` is `[surface, window]`. The `pointerId` space is per window. UI Events then derives `mousemove`, `mousedown`, `mouseup`, `click`, `dblclick`, `auxclick`, and `contextmenu` on that same path. `gotpointercapture` and `lostpointercapture` use it too. `WheelEvent` is dispatched on the `Window`.

A `PointerEvent` carries:

- `pointerId`, `pointerType` (`"mouse"`, `"pen"`, `"touch"`), and `isPrimary`
- `clientX` / `clientY`, `screenX` / `screenY`, and `offsetX` / `offsetY` (CSS pixels from that surface's origin). `layerX` / `layerY` are those same `offsetX` / `offsetY` values. There is no stacking context to measure from
- `button` and `buttons`
- `pressure`, `tangentialPressure`, `tiltX`, `tiltY`, `twist`, `width`, and `height`. Missing OS values are 0. A mouse uses `pressure` 0.5 while a button is down and 0 otherwise
- `movementX` / `movementY`, which are relative while the pointer is locked
- `ctrlKey`, `shiftKey`, `altKey`, `metaKey`, and `timeStamp`
- `getCoalescedEvents()` on `pointermove` and `pointerrawupdate`. A `pointermove` returns the moves coalesced into that frame. A `pointerrawupdate` returns one event, and that event's type is `pointerrawupdate`
- `setPointerCapture`, `releasePointerCapture`, and `hasPointerCapture` on that surface

`MouseEvent`, `WheelEvent`, `PointerEvent`, and `DragEvent` constructors take a required type, so each function's `length` is 1. `MouseEvent`, `WheelEvent`, and `DragEvent` floor `screenX`, `screenY`, `clientX`, `clientY`, `pageX`, `pageY`, `offsetX`, `offsetY`, `layerX`, and `layerY`. A `PointerEvent` whose type is `click`, `auxclick`, or `contextmenu` does the same. Any other `PointerEvent` type keeps those coordinates as doubles, except `layerX` and `layerY`, which stay floored. `initMouseEvent(type, bubbles, cancelable, view, detail, screenX, screenY, clientX, clientY, ctrlKey, altKey, shiftKey, metaKey, button, relatedTarget)` writes those fields unless the event is already dispatching. The tenth argument is `altKey` and the eleventh is `shiftKey`. Omitted arguments use the legacy defaults: booleans false, coordinates and `detail` and `button` 0, and `view` and `relatedTarget` null. It does not change `buttons`, `movementX`, `movementY`, or `isTrusted`. `view` must be this realm's global object or null. `new DragEvent(type)` has `dataTransfer` null. A `DataTransfer` is stored and returned as that object. Any other value throws `TypeError`. The runtime does not start an HTML drag-and-drop session. A dedicated worker has `DragEvent` and does not have `DataTransfer`.

`WheelEvent.momentum` is false unless the constructor dictionary sets it. A host `wheel` event is false: the runtime does not synthesize scroll inertia. `DOM_DELTA_PIXEL`, `DOM_DELTA_LINE`, and `DOM_DELTA_PAGE` are 0, 1, and 2 on both the constructor and the prototype. They are enumerable and neither writable nor configurable.

`navigator.maxTouchPoints` is the largest number of simultaneous contacts among connected touch screens. Each access reads that count from the operating system. A trackpad is not a touch screen. When no touch screen is connected, the value is 0. A touch screen that does not report a maximum counts as 1. Several touch screens contribute the largest count, not the sum. On Windows the count is `SM_MAXIMUMTOUCHES` when `SM_DIGITIZER` is ready and reports integrated or external touch, and a non-positive maximum still counts as 1. On Linux the count is the `ABS_MT_SLOT` span of a direct evdev touch screen (`INPUT_PROP_DIRECT`, `BTN_TOUCH`, and an X/Y axis). Opening that event node is not a permission check, and a screen whose slot count cannot be read counts as 1. On macOS the count is the Contact Count Maximum in the report descriptor of a HID digitizer whose usage is Touch Screen (`0x0D` / `0x04`). Touch Pad (`0x05`) is skipped, and the registry is read without opening the HID device. The attribute is on the main global only. A dedicated worker does not have it.

`pointerrawupdate` is a `PointerEvent` for each pointer move the operating system reports, including while the pointer is locked. It is dispatched on that surface before the `pointermove` for the same samples. It bubbles and is not cancelable. Its `movementX` and `movementY` are that sample's movement. Several moves that one turn coalesces into a single `pointermove` each dispatch their own `pointerrawupdate`. An unlocked move comes from winit `WindowEvent::CursorMoved`. While the pointer is locked, a move comes from winit `DeviceEvent::MouseMotion` and `CursorMoved` is not turned into a pointer event.

Pointer lock is `surface.requestPointerLock()` and returns a promise. Success dispatches `pointerlockchange` on that surface. Failure dispatches `pointerlockerror` on that surface. The implementation is winit cursor grab plus hiding the cursor. Lock is per window. `movementX` and `movementY` on the locked move are that motion's delta.

Fullscreen is `surface.requestFullscreen()`. Leaving it is `surface.exitFullscreen()`.

### Keyboard and IME

`keydown` and `keyup` are `KeyboardEvent`s. The fields are `key`, `code`, `location`, `repeat`, `isComposing`, the four modifiers, and `timeStamp`. `key` comes from the winit logical key. `code` maps the physical key to a UI Events code. The map lives in `yuzuko_window`. An unknown key is `"Unidentified"`.

IME does not run while that surface's `setImeAllowed` is `false`. The default is `false`. A text field calls `setImeAllowed(true)` and `setCompositionCaret(...)`.

winit `Ime` maps as follows:

| winit | DOM |
| --- | --- |
| `Enabled` | `compositionstart` with `data === ""` |
| `Preedit(text, range)` | `compositionupdate` with `data === text` |
| `Commit(text)` | `compositionend` with `data === text` |
| `Disabled` | `compositionend` when a composition is open |

While the preedit string is non-empty, the corresponding `keydown` and `keyup` have `isComposing === true`. After `compositionend`, one `beforeinput` with `inputType` `"insertText"` and the committed string is dispatched on that surface. `beforeinput` during composition uses `insertCompositionText`. The constructors `KeyboardEvent`, `CompositionEvent`, `InputEvent`, `PointerEvent`, `MouseEvent`, `WheelEvent`, `Touch`, `TouchList`, and `TouchEvent` are web standards and live on `globalThis`. `TouchList` has no constructor. `new TouchList()` throws `TypeError` with `Illegal constructor`. `new Touch(init)` requires `identifier` and `target`. `target` is an `EventTarget`. A missing required member throws `TypeError`. `clientX`, `screenX`, `pageX`, `radiusX`, `rotationAngle`, `force`, and the other coordinate members default to 0. `new TouchEvent(type)` is not cancelable. `touches`, `targetTouches`, and `changedTouches` default to empty `TouchList` objects. `TouchList` indices are the `Touch` objects. `item(index)` returns `null` when `index` is past the end. An index cannot be assigned or deleted. The runtime does not dispatch a trusted `TouchEvent`. A touch contact is a `PointerEvent` with `pointerType` `"touch"`.

winit and the host OS can disagree with browsers, including a Windows `key` of `"Process"` and `compositionstart` arriving on the other side of `keydown`. Record each observed difference in `docs/deviations.md` with the OS name. The acceptance bar is that the composing string and the committed string are readable from `data`.

If `keydown` calls `preventDefault()`, that key does not produce a normal text input. A `Commit` the OS has already produced is still delivered as `compositionend`.

### Keyboard lock

`navigator.keyboard` is installed with the `window` feature on the main global. It is the same object on every read. `Keyboard` extends `EventTarget`. A dedicated worker does not have `navigator.keyboard` or `Keyboard`. Those names are absent when `window` is off. `getLayoutMap` is absent, and `layoutchange` does not fire.

`lock(keyCodes)` reserves UI Events `code` values for the focused window. An omitted argument, `undefined`, or an empty list reserves every key. Each code is converted with `ToString`. A code is accepted when this runtime can report it from `KeyboardEvent.code`, including `"Unidentified"`. A duplicate is stored once. A list longer than 1024 codes rejects `TypeError` with `The key code list is too long`. A value that is not iterable rejects `TypeError` with `The key code list is not a sequence`. The promise settles in the same turn. A later `lock` replaces the reserved codes and does not reject the earlier call with `AbortError`. Fullscreen is not required. There is no permission prompt. Holding Escape does not show an overlay and does not leave fullscreen.

No focused window rejects `InvalidStateError` with `No window is focused` and leaves the previous reservation. A code this runtime cannot report rejects `InvalidAccessError` with `The key code is not a valid code` and clears the reservation. `unlock()` clears it. Closing the focused window clears it. Losing focus keeps the reservation and drops the operating-system inhibitor until a window of this process is focused again.

Reserved keys still dispatch `keydown` and `keyup` on that window. A headless process records the reservation and does not change operating-system shortcuts.

macOS calls `PushSymbolicHotKeyMode` with `kHIHotKeyModeAllDisabled` while the reserved set is empty or contains `Escape`, `Tab`, `Space`, `MetaLeft`, or `MetaRight`, and only while a window of this process is focused. The mode applies while the process is frontmost. Command-Tab and Command-Option-Escape stay with the system. Without assistive access the call does not change shortcuts. A list that names none of those keys does not change the symbolic hotkey mode.

Windows installs a low-level keyboard hook while a lock is held and a window is focused. The hook swallows a reserved key only when a window of this process is in the foreground, then posts that key to the window. Ctrl+Alt+Delete stays with the system. If the hook cannot be installed, `lock()` still resolves.

Linux calls `XGrabKeyboard` on an X11 window only when the list is empty, and only while that window is focused. A partial list does not grab. Wayland does not grab, so compositor shortcuts stay with the compositor. A failed grab still resolves `lock()`.

Focus changes dispatch `focus` and `blur` as `FocusEvent`s on that `Yuzuko.Window`. They do not bubble or cancel, and `relatedTarget` is null. `WindowSurface` does not receive them. Resize and scale-factor changes dispatch `resize` on the window. Size is read from `clientWidth` and `clientHeight`.

## Gamepad

The web Gamepad API. `navigator.getGamepads()` returns the connected gamepads. `gamepadconnected` and `gamepaddisconnected` fire on `globalThis`, and so do `ongamepadconnected` and `ongamepaddisconnected`. These do not live on `Yuzuko`. Physical devices are read with gilrs while the event loop runs, and an already-connected device is exposed without waiting for a button press. `GamepadHapticActuator.effects` is a frozen array listing `"dual-rumble"` when that device can play force feedback, and is otherwise empty. `playEffect("dual-rumble")` drives the low-frequency and high-frequency motors. Magnitudes are in the range [0, 1]. `duration` and `startDelay` are milliseconds, and their sum is capped at 5000. The playing promise resolves `"complete"` when that time has elapsed. It resolves `"preempted"` when another effect replaces it, when `reset()` stops it, or when the gamepad disconnects. `reset()` resolves `"complete"` while the gamepad is connected. `trigger-rumble` is not listed and rejects `NotSupportedError`. A parameter that is not a valid effect rejects `TypeError`. A call on a disconnected gamepad rejects `InvalidStateError`. `GamepadPose` reports no pose.

## Clipboard

`navigator.clipboard` `writeText`, `readText`, and `ClipboardItem` for `text/plain` and `image/png`. Reads and writes succeed only after a pointer or key press on the focused `Window`. The same calls reject with `NotAllowedError` without that action, and when the window is not focused. There is no permission prompt. `copy`, `cut`, and `paste` are dispatched on that surface.

`DataTransfer` is on the main global when `window` is enabled. `new DataTransfer()` creates an empty read/write store. `dropEffect` and `effectAllowed` start as `"none"`. A dedicated worker has no `DataTransfer`. `items`, `files`, `setDragImage`, `DataTransferItem`, and `DataTransferItemList` are absent. `DragEvent` is a separate constructor and does not carry this store unless script passes it.

`types` is a frozen array of the stored formats, in list order. The same array is returned until the list changes. `setData` always changes the list: an existing format is removed and the new value is appended, so that format moves to the end, and the next `types` read is a new array. `clearData` with no argument removes every string entry. `clearData(format)` removes that format. Either call leaves the current `types` array in place when it removes nothing. `getData`, `setData`, and `clearData` convert `format` with `ToString` and then to ASCII lowercase. `"text"` means `text/plain`. `"url"` means `text/uri-list`. `getData` of a missing format returns `""`. `getData("url")` returns the first `text/uri-list` line that is not empty and does not start with `#`. Line breaks are LF and CRLF. When no such line exists, the result is `""`. `getData("text/uri-list")` returns the stored string unchanged.

`dropEffect` accepts `"none"`, `"copy"`, `"link"`, and `"move"`. `effectAllowed` accepts `"none"`, `"copy"`, `"copyLink"`, `"copyMove"`, `"link"`, `"linkMove"`, `"move"`, `"all"`, and `"uninitialized"`, and only while the store is read/write. Any other string is ignored. On a read-only store, `setData` and `clearData` do nothing.

A host `copy` or `cut` carries a new empty read/write `DataTransfer`. A host `paste` carries a read-only `DataTransfer`. Its `text/plain` entry is the string `readText` would return when that cache holds text, including `""`. When the cache has no text, `text/plain` is absent and `getData` returns `""`. The paste store does not include `text/html` or `image/png`. If the host event is cancelled and the store contains `text/plain`, including `""`, that string is published the same way as `writeText`: it replaces the cached text, clears a cached `image/png`, and fires `clipboardchange`. Any other format stays on the `DataTransfer` and is not written to the operating system. An uncancelled host `copy` or `cut` leaves the clipboard unchanged. There is no selection to copy or delete. A `ClipboardEvent` constructed or dispatched by script does not write the clipboard.

`new ClipboardEvent(type)` has `clipboardData` null. An init value that is not an object is ignored, and `clipboardData` stays null. `null`, a missing `clipboardData`, or `undefined` stores null. A `DataTransfer` is stored and returned as that same object. Any other value throws `TypeError` with `clipboardData is not a DataTransfer`. A thrown `clipboardData` getter throws that exception.

`ClipboardChangeEvent` is on the main global. `new ClipboardChangeEvent(type, init)` stores `init.types` and `init.changeId`. `types` defaults to an empty sequence. A present value that is not an array, including a string, throws `TypeError`. Each entry is converted with `ToString`. The getter returns a new frozen array. `changeId` defaults to `0n`. A present value is converted with `ToBigInt`. A value that does not fit in 128 bits throws `TypeError`. A user-constructed event keeps the types it was given.

The host event type is `clipboardchange`. It does not bubble and cannot be cancelled. `isTrusted` is true. `types` lists the mandatory types that are present, in the order `text/plain`, `text/html`, `image/png`. Any other type is omitted. An event can list no types. `onclipboardchange` is the handler on `navigator.clipboard`. Assigning a function listens. Assigning any other value, including `null`, clears it.

A successful `write` or `writeText` dispatches the event before the promise resolves when a window is focused. A call that rejects before the pasteboard is updated does not dispatch. Listeners run before `await` continues. macOS uses the pasteboard `changeCount` as `changeId`. Windows uses `GetClipboardSequenceNumber`. On those systems a later poll sees the same sequence and does not dispatch again. The first observation of the pasteboard is not a change. A change observed while no window is focused replaces one pending event, and that event is dispatched once after the next `focus` event. `blur` does not dispatch it. Linux dispatches for `write` and `writeText` only. A cancelled host `copy` or `cut` that publishes `text/plain` dispatches it the same way. A dedicated worker has no `Clipboard`, no `ClipboardChangeEvent`, and no `DataTransfer`.

## Screen Wake Lock

`navigator.wakeLock` is installed with the `window` feature on the main global. It is the same object on every read. A dedicated worker does not have `navigator.wakeLock`, `WakeLock`, or `WakeLockSentinel`. Those names are absent when `window` is off.

`request()` with an omitted type, or with `"screen"`, resolves a `WakeLockSentinel`. Any other value is converted with `ToString`. A result other than `"screen"` rejects `TypeError` with `The wake lock type is invalid`. If that conversion throws, `request()` throws the same exception. `type` is `"screen"`. `released` is false until `release()`. `onrelease` starts as null.

`release()` sets `released` to true, dispatches a trusted `release` event on that sentinel, and then resolves `undefined`. The event does not bubble and cannot be cancelled. `released` is already true while the listeners run. A second `release()` resolves `undefined` and does not dispatch again.

The runtime asks the operating system to keep the display awake while at least one sentinel is unreleased. The first successful `request()` creates the platform assertion. The last `release()` drops it. macOS calls `IOPMAssertionCreateWithName` with type `PreventUserIdleDisplaySleep`, level on, and name `Yuzuko`, and drops it with `IOPMAssertionRelease`. Windows calls `SetThreadExecutionState` with `ES_CONTINUOUS | ES_DISPLAY_REQUIRED`, and calls it with `ES_CONTINUOUS` when the last sentinel releases. Linux spawns `systemd-inhibit --what=idle:sleep --who=Yuzuko --why=screen wake lock --mode=block sleep infinity` and kills that child when the last sentinel releases. If the operating system refuses the request, `request()` rejects `NotAllowedError` with `The platform refused the screen wake lock`.

There is no permission prompt and no document. Hiding a window does not release a sentinel. `new WakeLock()` and `new WakeLockSentinel()` throw `TypeError` with `Illegal constructor`.

## Menu bar

`Yuzuko` is an `EventTarget`. `Yuzuko.Menu` and `Yuzuko.setMenu(menu)` install one application menu with `muda`. A selection delivered through the same input path as pointer and key events dispatches `menuclick` on `Yuzuko` and carries the item's `action` string. macOS has one menu for the app. On Windows the same menu is attached to the focused window. On Linux, winit does not expose a GTK window, so `setMenu` throws `NotSupportedError`.

## Context menu

`setContextMenu(menu)` stores a `Yuzuko.Menu` on that window. The menu may contain top-level actions. `null` clears it and does not show a menu. A value that is not a `Menu` or `null` throws `TypeError` before the window is checked. A closed window throws `InvalidStateError`. The call works in a headless process. It does not pop a menu.

`showContextMenu(menu, x, y)` shows that menu at `x` and `y` CSS pixels from the client origin. It does not replace the menu stored by `setContextMenu`. Non-finite coordinates throw `TypeError` before the window is checked. A closed window throws `InvalidStateError`. A value that is not a `Menu` throws `TypeError` after the window is checked. A headless process throws `NotSupportedError`. On Linux the call throws `NotSupportedError` because winit exposes no GTK window. The popup is synchronous. A selection dispatches `menuclick` on that window before the method returns. The event is trusted and carries the item's `action` string.

A `contextmenu` event whose default action is allowed shows the menu stored by `setContextMenu` at `clientX` and `clientY` when that menu is stored and the platform can show it. `preventDefault()` leaves that menu hidden. The listener can then call `showContextMenu` with a different menu. A headless process, a window with no stored menu, and Linux do not throw from that default action.

## Tray and dock

`Yuzuko.Tray` is an `EventTarget`. `new Yuzuko.Tray()` adds a status item. `setIcon(bytes, options)` takes PNG bytes. `options.template` asks macOS to draw that icon as a template image. `setTooltip(text)`, `setMenu(menu)`, and `close()` update the item. `menu` is a `Yuzuko.Menu` and may contain top-level actions. `bounds` is `{ x, y, width, height }` in CSS pixels, or `null` when the system cannot report the rectangle. The constructor throws `NotSupportedError` when no status item can be created.

## Images

`createImageBitmap` accepts `Blob`, `ImageData`, `ImageBitmap`, and `OffscreenCanvas`, including the crop arguments `sx, sy, sw, sh`.

A `Blob` is identified by its signature.

| Format | Decoder |
| --- | --- |
| JPEG | `zune-jpeg`. EXIF orientation comes from `exif` |
| PNG | `png`, including `tRNS`. 8-bit samples stay unorm8. 16-bit samples are stored as float16 |
| WebP | `image-webp`, lossy and lossless, with alpha. Samples stay unorm8 |
| JPEG XL | `jxl-oxide` (pure Rust). Do not link `libjxl`. Sample depth above 8 bits is stored as float16 |
| AVIF | rav1d, profiles 0–2 at 8, 10, and 12 bits, 4:2:0, 4:2:2, 4:4:4, and monochrome, one still frame. An animated file is that one frame. A major brand of `avis` is rejected by avif-parse, so the sequence is not walked. An alpha item is composited into the display image. Any other bit depth is rejected |
| GIF | `gif`. GIF87a and GIF89a. Frames are composited onto the logical screen. A transparent sample leaves the pixel. One frame is still. Two or more frames are animated |
| BMP | In-tree. `BM` with a 40-, 108-, or 124-byte header. 8-bit palette, 24-bit BGR, opaque 32-bit `BI_RGB`, and 32-bit `BI_BITFIELDS`. Bottom-up and top-down. Other compression is rejected |

`createImageBitmap` stores that AVIF display image as unorm8 sRGB. `drawImage`, `createPattern`, and `copyExternalImageToTexture` sample it. `new VideoFrame` from that bitmap copies the samples as `RGBA`. `createImageBitmap` of the `ImageDecoder` frame uses the same image.

An `ImageBitmap` stores a color space and a sample format. The color space is `"srgb"` or `"display-p3"`. The sample format is unorm8 or float16. `ImageBitmap` does not expose those choices as attributes. `premultiplyAlpha` follows `"default"`, `"premultiply"`, and `"none"`. `imageOrientation` accepts `"from-image"` and `"flipY"`. `resizeWidth` / `resizeHeight` use nearest for `"pixelated"` and `"low"`, and triangle for `"medium"` and `"high"`.

`colorSpaceConversion: "none"` keeps an sRGB or Display P3 source in that space, including its sample format. `colorSpaceConversion: "default"` stores sRGB. A source profile that is neither sRGB nor Display P3 is converted to sRGB with `moxcms` for either setting. Conversion between sRGB and Display P3 uses the CSS Color 4 matrices: linearize, apply the matrix, then encode again. Float samples wider than float16 round to float16. Eight-bit sources stay unorm8.

`createImageBitmap` from an `ImageData` or a 2D canvas copies that object's color space and sample format. Float16 components are the encoded values of the stored color space, not linear-light values, and are not clamped to 0..1. `ImageData` stores alpha unpremultiplied.

`ImageData` is serializable. `structuredClone` copies its pixels, color space, and pixel format, including float16 Display P3, into a new typed array. The clone does not share the source buffer. `ImageData` is not transferable. Listing one in a transfer list throws `DataCloneError`. Transferring its `data` buffer detaches that buffer, and the clone keeps the pixels.

`ImageBitmap` is serializable and transferable. `structuredClone` without a transfer list copies the bitmap and leaves the source open. Listing the bitmap in the transfer list of `structuredClone`, `postMessage`, or an owning stream detaches the source: `width` and `height` are 0, and `close()` has the same effect. A detached bitmap throws `DataCloneError`.

`createImageBitmap` uses the first frame of an animated image. `ImageDecoder` returns every frame of an animated PNG, WebP, JPEG XL, or GIF and does not advance those frames. A BMP file is one still frame. An AVIF file is one still frame, including when the file is animated. A major brand of `avis` is rejected by avif-parse, so an animated sequence is not walked. Input that cannot be decoded rejects with `InvalidStateError`. Decoding does not block the event loop: it runs on a dedicated thread, and the host object is created on the main thread afterward. A decoder panic is caught with `catch_unwind` and becomes `InvalidStateError`.

The limits are 16384 pixels on the longer edge and 100 million pixels in total. Exceeding either rejects with `InvalidStateError`.

`fetch` loads `file:`, `blob:`, `data:`, `http:`, and `https:`. A `file:` URL must stay under the entry module's directory. `http:` and `https:` follow redirects. Each hop is checked with the same permission before the next connection, and a denied hop rejects the fetch with `NotCapable`. A `421` is retried once on a new connection. `AbortSignal` cancels the fetch. A blob URL `Range` answers `206` or a network error. This works:

```js
const url = new URL("./hero.jxl", import.meta.url);
const bitmap = await createImageBitmap(await (await fetch(url)).blob());
```

## OffscreenCanvas

`getContext` accepts `"2d"`, `"webgpu"`, and `"bitmaprenderer"`. A different kind from the one already created returns `null`. An unimplemented drawing method throws `NotSupportedError`.

### Canvas 2D

The GPU rasterizer is vello_gpu and the CPU rasterizer is vello_cpu. Text shaping uses parley and fontique. When `Yuzuko.canvasRenderer === "gpu"`, the scene runs on the process wgpu device and the result is written to an `Rgba8Unorm` color attachment. When there is no device, or vello_gpu cannot be created on that device, the renderer is `"cpu"` and vello_cpu produces the pixels. The device uses the adapter's limits, so a downlevel adapter is not rejected before that renderer is created. If a wgpu device exists, CPU pixels are uploaded to a texture and presented. If no device exists, they are presented through a CPU framebuffer. WebGPU does not use this fallback: `requestAdapter()` resolves to `null` when no adapter exists.

Both renderers paint an sRGB unorm8 target. The GPU target is `Rgba8Unorm`. Scene colors are converted to sRGB and packed to 8 bits before the draw. Image brushes are `Rgba8` or `Bgra8`. The pixmap is premultiplied RGBA8. A Display P3 source color can be supplied, and the rasterizer converts it to sRGB while packing, which clips chroma outside sRGB.

`getContext("2d", { colorSpace, colorType })` still selects `"srgb"` or `"display-p3"`, and `"unorm8"` or `"float16"`. The defaults are `"srgb"` and `"unorm8"`. `getContextAttributes()` returns them. The default context is that sRGB unorm8 target. `"srgb-linear"` and `"display-p3-linear"` throw `TypeError` from `getContext` and from `ImageDataSettings`.

A `display-p3` or `float16` context has its own backing store, owned here rather than by the rasterizer. On the GPU that store is `Rgba8Unorm` interpreted as Display P3, or `Rgba16Float` in the canvas color space. Without a device it is a CPU buffer of the same layout. `putImageData` and a `drawImage` whose source already matches the destination write that store and keep the samples. An opaque axis-aligned solid `fillRect` on a float16 store is written in that store's color space at float16 precision, so a `color(display-p3 ...)` fill can produce encoded components outside 0..1. Other path fills, strokes, text, and gradients are painted in sRGB unorm8 and then converted into the store, so those paints lose chroma outside sRGB and precision beyond 8 bits.

`fillStyle` and `strokeStyle` accept the existing sRGB forms plus `color(srgb ...)`, `color(srgb-linear ...)`, `color(display-p3 ...)`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, and `color-mix()`, with or without alpha. A color component accepts `calc()` and `none`. Gradient stops accept the same forms. `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color-mix()`, and `color(srgb-linear ...)` are converted to encoded sRGB, and the getter returns `color(srgb ...)`. `color(display-p3 ...)` still round-trips. `color-mix()` accepts `srgb`, `srgb-linear`, `display-p3`, `lab`, `oklab`, `lch`, `oklch`, `hsl`, and `hwb`. `xyz` does not parse. A hue method (`shorter`, `longer`, `increasing`, or `decreasing`) is accepted only in a polar space. An unrecognized color does not change the current style. `getImageData`, `putImageData`, and `createImageData` take `ImageDataSettings`. `colorSpace` is `"srgb"` or `"display-p3"`. `pixelFormat` is `"rgba-unorm8"`, stored in a `Uint8ClampedArray`, or `"rgba-float16"`, stored in V8's `Float16Array`. A buffer of the other typed-array kind throws `InvalidStateError`. `getImageData` converts when the requested color space or pixel format differs from the backing store. An omitted `colorSpace` is `"srgb"`. An omitted `pixelFormat` is `"rgba-unorm8"`. `createImageData(sw, sh)` uses those defaults. `createImageData(imageData)` copies that object's color space and pixel format. `putImageData` converts into the canvas color space in floating point when either side is float16. An 8-bit channel is the encoded 0..1 value times 255. Float16 `ImageData` keeps values outside 0..1.

Present uses an explicit wgpu `SurfaceColorSpace`, never `Auto`. An sRGB unorm8 canvas uses `Srgb`. A Display P3 unorm8 canvas uses `DisplayP3` when the surface capabilities list that pair, and is converted to sRGB for present otherwise. A float16 canvas uses `ExtendedDisplayP3` or `ExtendedSrgb` with `Rgba16Float` only when that pair is advertised. Otherwise present quantizes it to the sRGB unorm8 swapchain. `Auto` on `Rgba16Float` resolves to linear scRGB, which is a different encoding.

Conformance pixel tests always use the CPU renderer so GPU vendors do not perturb the result.

Level A is:

- State stack: `save`, `restore`, `reset`, `resetTransform`
- Transforms: `scale`, `rotate`, `translate`, `transform`, `setTransform`, `getTransform`
- `globalAlpha`. `globalCompositeOperation` stores `source-over`, `source-in`, `source-out`, `source-atop`, `destination-over`, `destination-in`, `destination-out`, `destination-atop`, `lighter`, `copy`, `xor`, `clear`, and the CSS blend modes. Any other value is ignored. Painting uses the stored operator inside the current clip
- Styles: CSS color strings, `color(srgb ...)`, `color(srgb-linear ...)`, `color(display-p3 ...)`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color-mix()`, linear gradients, radial gradients, conic gradients, and `createPattern` from `ImageBitmap` or `OffscreenCanvas` with all four repeat modes. Modern colors other than `color(display-p3 ...)` serialize as `color(srgb ...)`
- Lines: `lineWidth`, `lineCap`, `lineJoin`, `miterLimit`, `setLineDash`, `getLineDash`, `lineDashOffset`
- Rectangles and paths: `fillRect`, `strokeRect`, `clearRect`, `rect`, `beginPath`, `closePath`, `moveTo`, `lineTo`, `quadraticCurveTo`, `bezierCurveTo`, `arc`, `arcTo`, `ellipse`, `roundRect`, `fill`, `stroke`, `clip`. Fill rules are nonzero and evenodd. A negative `roundRect` edge flips that axis and keeps each radius on the corner named before the flip. One negative edge reverses the subpath. Two negative edges restore the positive direction
- `Path2D`, `isPointInPath`, `isPointInStroke`
- All three `drawImage` overloads. Sources are `ImageBitmap` and `OffscreenCanvas`
- `imageSmoothingEnabled` defaults to true. `imageSmoothingQuality` is `"low"`, `"medium"`, or `"high"` and defaults to `"low"`. An unrecognized quality is ignored. `false` selects nearest-neighbor. `"low"` selects bilinear sampling. `"medium"` selects bicubic sampling. `"high"` prefilters a scaled `drawImage` with a separable Lanczos-3 kernel when the draw is not an axis-aligned scale within 2% of 1:1, then samples that bitmap bilinearly. That 1:1 case uses bilinear sampling for every quality. A pattern is recorded before its destination size is known, so `"medium"` and `"high"` both sample it bicubically. A layer bitmap stays nearest-neighbor
- `getImageData`, `putImageData`, `createImageData`, including `colorSpace` and `pixelFormat`. `getImageData` may stall on a GPU readback
- Text: `font`, `lang`, `textAlign`, `textBaseline`, `direction`, `fillText`, `strokeText`, `measureText`. `actualBoundingBoxLeft`, `actualBoundingBoxRight`, `actualBoundingBoxAscent`, and `actualBoundingBoxDescent` are the glyph-outline ink relative to the `textAlign` anchor and the `textBaseline` line. An empty outline, including a space, reports zeros. The font and em boxes use the typographic ascent and descent, shifted onto that baseline. Positive `hangingBaseline`, `alphabeticBaseline`, and `ideographicBaseline` point down from `textBaseline`. The shorthand accepts `italic` or `oblique`, `small-caps`, a weight, a `px` or `pt` size, an optional line height, and a family list. The getter omits a weight of 400, a normal style, and the line height. `small-caps` is stored and returned. `cursive` and `fantasy` stay in the list. A family is a loaded `FontFace`, a generic (`sans-serif`, `serif`, or `monospace`, mapped to the OS UI font), or another family name. A list uses the first loaded family, or else the first of those generics. A size that names only an unregistered family, or only `cursive` or `fantasy`, is stored and shaped as `sans-serif`. A value that does not parse is ignored. CJK glyphs must draw. `lang` is a BCP 47 tag, `""`, or `"inherit"` (the default) and is part of the canvas state. It selects localized glyphs when the text is shaped. `direction` is `"ltr"`, `"rtl"`, or `"inherit"` and defaults to `"inherit"`. An unrecognized value is ignored. There is no document, so `"inherit"` is shaped left to right
- Layers: `beginLayer()` and `endLayer()`. `beginLayer` takes an optional dictionary `{ filter }`. Draws between the calls are one group. The explainer is [Layers](https://github.com/fserb/canvas2D/blob/master/spec/layers.md)

`filter` is a CSS filter string, default `"none"`. A value that parses as `none` or a `<filter-value-list>` is stored, and the getter returns that assigned string. `none` is case-insensitive. `""`, `inherit`, `initial`, `unset`, `revert`, `revert-layer`, `null`, and `undefined` do not parse, so the current filter stays. A filter length does not accept `calc()`. A color inside `drop-shadow()` accepts the same colors as `fillStyle`, including `calc()` in a component. HTML removed the `CanvasFilter` class in August 2022 ([whatwg/html#7874](https://github.com/whatwg/html/pull/7874)) for lack of multi-implementer agreement, and this runtime does not provide it. `ctx.filter` remains a CSS filter string. `beginLayer({ filter })` uses the same CSS syntax. `null`, `undefined`, and `""` omit the argument. Any other unparsable value, including a filter dictionary, throws `TypeError` and does not open a layer. The dictionary throws because that interface is not in the specification.

`beginLayer` and `endLayer` share a stack with `save` and `restore`. `restore` throws `InvalidStateError` when the top entry is a layer. `endLayer` throws `InvalidStateError` when the top entry is a save or the stack is empty. `reset` discards open layers, and a later `endLayer` throws. An open layer is not rasterized. `endLayer` composites it. Entering a layer sets `globalAlpha` to `1`, `globalCompositeOperation` to `"source-over"`, `shadowBlur`, `shadowOffsetX`, and `shadowOffsetY` to `0`, `shadowColor` to transparent black, `filter` to `"none"`, and the clip list to empty. The saved `globalAlpha` and clips then apply to that bitmap. The current transform continues inside the layer and is restored on `endLayer`. `setTransform` and `resetTransform` replace the matrix until the layer ends. The current path is not saved. A parent `translate` therefore moves draws inside the layer, and a clip around the layer clips the bitmap rather than surviving `endLayer` as a context clip.

`ctx.filter` and a layer `filter` are applied when the drawing is composited. The functions are `blur`, `brightness`, `contrast`, `drop-shadow`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`, `sepia`, and `url()`. They run left to right on the shape's premultiplied sRGB unorm8 ink, before the composite operator. Lengths are canvas pixels and are not scaled by the current transform. A `url()` reference has no SVG filter, so that function clears the ink and later functions in the list do not run. When a filter is set, the canvas shadow is included in that bitmap and the result is composited once. A filtered drawing is rasterized on the CPU. A shadow is painted when `shadowColor` has nonzero alpha and `shadowBlur` or either offset is nonzero. Offsets and blur are canvas pixels and are not affected by the current transform. The blur is a Gaussian whose σ is `shadowBlur` / 2, capped at 128. The shadow is composited with the current operator inside the clip, then the shape is composited the same way. A shape outside the canvas still casts a shadow into it. `clearRect` and `putImageData` do not use the operator or the shadow. A non-finite blur or offset is ignored, and a negative blur is ignored. An unparsable shadow color is ignored. A recognized `globalCompositeOperation` is stored and used inside the clip. `lighter` is additive. A list with an operator other than `source-over`, or with a shadow, is rasterized on the CPU.

`createConicGradient(startAngle, x, y)` paints one clockwise turn in canvas space. Offset 0 is `startAngle` radians from the positive x-axis, and offset 1 is that same ray. A non-finite argument throws `TypeError`. A gradient with no color stops does not paint. `addColorStop` throws `TypeError` when `offset` is not finite, `IndexSizeError` when `offset` is outside 0 through 1, and `SyntaxError` when `color` does not parse. Named fonts are resolved by `FontFace`. CSS `@font-face` is not implemented. Extending past level A updates this list and `docs/deviations.md` in the same change. `YUZUKO_SKIP_GPU=1` reports `Yuzuko.canvasRenderer === "cpu"`.

`convertToBlob` produces `image/png`, `image/jpeg`, and `image/webp`. JPEG XL encoding is out of scope. `putImageData` of a float16 Display P3 `ImageData` round-trips through `getImageData` within one float16 ulp. An opaque solid `fillRect` on a float16 canvas uses that same conversion. Any other path painted with `color(display-p3 ...)` is compared after the sRGB unorm8 conversion, not as a wide-gamut round trip. A plain `source-over` list with no shadow and no filter draws on both the GPU and CPU renderers. Any other operator, a shadow, or a filter is rasterized on the CPU.

### WebGPU

WebGPU is implemented on wgpu. The process has one default adapter. Canvas 2D uses the same `wgpu::Device`. Each `Window` has its own swapchain. `copyExternalImageToTexture` copies from `ImageBitmap` and `OffscreenCanvas` on the GPU, and takes a CPU path only when the formats do not match. The copy converts from the source color space into the destination `colorSpace`, `"srgb"` or `"display-p3"`. A float16 source is quantized to the destination texture format.

Every wgpu call in v1 happens on the main thread. `YUZUKO_SKIP_GPU=1` makes `requestAdapter` resolve `null`.

The WebGPU surface is:

- `navigator.gpu.requestAdapter`, `requestDevice`, and `getPreferredCanvasFormat`
- `GPUCanvasContext.configure`, `getCurrentTexture`, and `unconfigure`. `alphaMode` accepts `"opaque"` and `"premultiplied"`
- Shader modules, render pipelines, compute pipelines, command encoders, render passes, and compute passes
- Render bundle encoders, `finish`, and `executeBundles`
- Buffers, textures, samplers, bind groups, bind group layouts, query sets, `queue.writeBuffer`, and `queue.submit`
- `copyBufferToBuffer`, `copyTextureToBuffer`, `resolveQuerySet`, and indexed and indirect draws (`setIndexBuffer`, `drawIndexed`, `drawIndirect`, `drawIndexedIndirect`, `dispatchWorkgroupsIndirect`)
- Depth and stencil attachments, occlusion queries, and timestamp queries when `timestamp-query` is enabled

## Server messages

`EventSource` and `WebSocket` live on `globalThis`, including a dedicated worker. `EventSource` is installed with the `fetch` feature and is absent from a build without it. `EventSource` reads an `http:` or `https:` `text/event-stream` response and dispatches `MessageEvent`s. The default reconnection time is 3000ms. `retry` replaces it. Each connection, including a reconnect, checks the net permission again. A denial does not open a socket and the client schedules another reconnect. `close()` stops the stream. `withCredentials` is stored on the object.

`new WebSocket(url)` opens a `ws:` or `wss:` connection. The second argument is a protocol string, a sequence of protocol strings, or a `WebSocketInit` dictionary `{ protocols, targetAddressSpace }`. `targetAddressSpace` is `"loopback"`, `"local"`, or `"public"`. The connection fails unless the connected address is in that space. Any other value, including the legacy alias `"private"`, throws `TypeError`. A further argument is ignored. `send` accepts a string, a `BufferSource`, or a `Blob`. `binaryType` is `"blob"` or `"arraybuffer"`. `close(code, reason)` uses code 1000 or a code from 3000 through 4999. `extensions` stays `""`.

`new WebSocketStream(url, options)` opens the same kind of connection. `options.protocols` is a sequence of protocol strings. `options.signal` aborts the handshake. `opened` resolves to `{ readable, writable, protocol, extensions }`. Text messages are strings and binary messages are `Uint8Array` values. `closed` resolves to `{ closeCode, reason }` after a clean close and rejects with `WebSocketError` after an unclean close. `close({ closeCode, reason })` sends that close. A readable `pull` reads one message, and further socket reads wait, which applies receive backpressure.

`new WebTransport(url, options)` opens an `https` session on its own QUIC connection. It is on `globalThis` in the main realm and in a dedicated worker. `ready` resolves when the handshake finishes. `reliability` is `"pending"` until then, then `"supports-unreliable"` or `"reliable-only"`. `closed` resolves `{ closeCode, reason }` after a clean close and rejects with `WebTransportError` after an unclean close. A failed handshake rejects both `ready` and `closed`, and those rejections are marked handled. `datagrams` is `{ readable, writable }`. With `datagramsReadableType` omitted, `readable` is a default readable stream whose high-water mark is 0. Each chunk is one datagram as a `Uint8Array`, and `getReader({ mode: "byob" })` throws `TypeError`. `datagramsReadableType: "bytes"` makes `readable` a readable byte stream whose high-water mark is 0. One read returns one datagram. A BYOB view shorter than that datagram rejects the read with `RangeError`. A view whose element size is not 1, including a `DataView`, rejects the read with `TypeError`. An empty datagram in that mode rejects the read with `TypeError`. Any other string throws `TypeError` from the constructor. `createBidirectionalStream()` resolves `{ readable, writable }`. That `readable`, and each value read from `incomingUnidirectionalStreams`, is a readable byte stream, so a short BYOB view keeps the unread bytes for the next read. `createUnidirectionalStream()` resolves a `WritableStream`. `incomingBidirectionalStreams` and `incomingUnidirectionalStreams` are default readable streams of those values. `close({ closeCode, reason })` closes the session. `congestionControl` is `"default"`, `"throughput"`, or `"low-latency"`.

## Virtual accessibility nodes

The `accessibility` feature installs `Yuzuko.AccessibleNode` and `Yuzuko.ComputedAccessibleNode` on the main realm, `attachAccessibleRoot()` and `accessibleRoot` on `Yuzuko.WindowSurface`, and `getComputedAccessibleNode()` on `Yuzuko.Window`. An `AudioWorklet` processor realm does not have them. A dedicated worker does not have `Yuzuko.AccessibleNode` or `Yuzuko.ComputedAccessibleNode`. With the feature off, the names are absent. Neither constructor is on `globalThis`. A bare `AccessibleNode` or `ComputedAccessibleNode` reference throws `ReferenceError`. The feature enables `window`. There is no permission prompt.

This is the Accessibility Object Model Phase 3 virtual accessibility node draft. The explainer hangs that tree from a canvas: `attachAccessibleRoot()`, then `accessibleRoot.appendChild(new AccessibleNode())`. There is no document and no canvas element, so those members are on `WindowSurface`. `parent`, `firstChild`, `lastChild`, `previousSibling`, and `nextSibling` read the authored `AccessibleNode` tree. The published tree is read through `ComputedAccessibleNode`.

`new Yuzuko.AccessibleNode()` creates a node. It is an `EventTarget`. `attachAccessibleRoot()` has length 0. It returns one new root and does not accept an existing node. A second call throws `InvalidStateError` with `An accessible root is already attached.` `accessibleRoot` returns that root, or `null` before one is attached. Children of the root are added with `appendChild`. After the window's `close()`, both `attachAccessibleRoot()` and `accessibleRoot` throw `InvalidStateError` with `The window is closed.` The closed check runs before the already-attached check. Closing keeps the stored root. Further platform updates stop. Tree edits on the nodes still succeed. Calling either member on a value that is not a `WindowSurface` throws `TypeError` with `illegal invocation`.

`appendChild(node)`, `insertBefore(node, child)`, `replaceChild(node, child)`, and `removeChild(node)` accept only `AccessibleNode` values. Any other value throws `TypeError` with `The node must be an AccessibleNode.` `insertBefore` has length 1. `null` or `undefined` for `child` appends. `insertBefore(node, node)` keeps that node in place when it is already a child, and throws `NotFoundError` with `The node is not a child.` when it is not. Moving a node detaches it from its previous parent first. A cycle throws `HierarchyRequestError` with `The node is an ancestor.` Appending a node onto itself is that ancestor error. The accessible root cannot be moved, which is checked before the ancestor check, and throws `HierarchyRequestError` with `The accessible root cannot be moved.` `removeChild` and `replaceChild` of a node that is not a child throw `NotFoundError` with `The node is not a child.` `replaceChild` returns the removed child. When `node` and `child` are the same child, it returns that child and does not change the tree. A missing required argument throws `TypeError` with `Not enough arguments`.

The authored properties are `role`, `name`, `description`, `roleDescription`, `valueText`, `checked`, `pressed`, `disabled`, `expanded`, `hidden`, `selected`, `busy`, `modal`, `required`, `readOnly`, `multiselectable`, `multiline`, `valueNow`, `valueMin`, `valueMax`, `colCount`, `rowCount`, `colIndex`, `colSpan`, `rowIndex`, `rowSpan`, `level`, `setSize`, `posInSet`, `live`, `orientation`, `focusable`, `offsetLeft`, `offsetTop`, `offsetWidth`, `offsetHeight`, and `offsetParent`. Omitted ARIA members are absent. There is no `label` property. `name` is the accessible name.

`role`, `name`, `description`, `roleDescription`, and `valueText` use `ToString`. `null` or `undefined` clears the property, and the getter then returns `null`. An explicit empty string is stored and the getter returns `""`. `checked` and `pressed` are `"true"`, `"false"`, or `"mixed"`, or `null`. A boolean uses `ToString`, so `true` becomes `"true"`. Any other token throws `TypeError` with `The value is not a valid token.` `disabled`, `expanded`, `hidden`, `selected`, `busy`, `modal`, `required`, `readOnly`, `multiselectable`, and `multiline` are booleans or `null`. `null` and `undefined` clear them. Any other value uses the ordinary boolean conversion. `focusable` defaults to `false` and is not nullable. `valueNow`, `valueMin`, and `valueMax` are finite numbers or `null`. A non-finite number throws `TypeError` with `The value must be a finite number.` `colCount`, `rowCount`, `colIndex`, `colSpan`, `rowIndex`, `rowSpan`, `level`, `setSize`, and `posInSet` are IDL `long` values or `null`. `null` and `undefined` are checked before `ToInt32`, because `null` would become `0`. `live` is `"off"`, `"polite"`, or `"assertive"`, or `null`. `orientation` is `"horizontal"` or `"vertical"`, or `null`. Any other token throws `TypeError` with `The value is not a valid token.`

`offsetLeft`, `offsetTop`, `offsetWidth`, and `offsetHeight` are CSS pixel lengths. The getter returns `null` or a string such as `"30px"`. The setter accepts `null`, `undefined`, a finite number, or a string primitive that is a bare number or a `px` length. The `px` suffix is case-insensitive. Ends are trimmed. `"30 px"` is rejected because of the internal space. Exponents and other units, including `"30em"`, throw `TypeError` with `The offset must be a CSS pixel length.` A string object or any other object throws that error. A non-finite number throws that error. `offsetParent` is `null` or a strict ancestor `AccessibleNode`. Any other value throws `TypeError` with `The offset parent must be an AccessibleNode.` A node that is not a strict ancestor, including the node itself, throws `HierarchyRequestError` with `The offset parent is not an ancestor.`

When `offsetParent` is unset, `offsetLeft` and `offsetTop` are relative to the parent. When it is set, they are relative to that ancestor and are not accumulated through the parents in between. The author root's parent is not a JavaScript node, so its offsets are relative to the window and `parent` is `null`. A missing width or height is a zero-size rectangle. A non-finite length is published as 0. A non-finite or non-positive window scale is published as 1.

`focus()` moves accessible focus only. It does not move operating-system focus and it does not dispatch `focus`, `blur`, or `accessiblefocus`. A node that is not `focusable` throws `InvalidStateError` with `The node is not focusable.` A node that is not connected to a root throws `InvalidStateError` with `The node is not connected.` A connected node whose window is closed throws `InvalidStateError` with `The window is closed.` Those checks run in that order.

Assistive-technology actions are events. They bubble through the authored parent chain and are not cancelable. They do not bubble to the window. `dispatchEvent` stays single-target. The events are `accessibleclick`, `accessiblecontextmenu`, `accessibledecrement`, `accessiblefocus`, `accessibleincrement`, `accessiblescrollintoview`, and `accessiblesetvalue`. There are no `onaccessible*` handlers. `accessiblesetvalue` is a `CustomEvent` whose `detail` is the requested finite number, or `null` when the request has no number. The event does not change `valueNow` or `valueText`. Delivering these events reveals that an assistive technology is in use. There is no permission prompt.

`Yuzuko.__test.inject`, when `accessibility` is enabled, accepts a record `{ kind: "accessible", type, node, value }`. `type` is `click`, `contextmenu`, `decrement`, `focus`, `increment`, `scrollintoview`, or `setvalue`. `node` is an `AccessibleNode`. `value` is the number for `setvalue`. An unknown `type` throws `TypeError` with `The value is not a valid token.` When `accessibility` is off, that `kind` throws `TypeError` with `unknown inject kind accessible`. The call dispatches the event before it returns.

The platform tree is an AccessKit tree updated through `accesskit_winit`. The AccessKit root is a synthetic window node. It is not a JavaScript `AccessibleNode`. Its role is `window`, its name is the window title, and its bounds are the client area in physical pixels. The author root is its only child. Before a root is attached, activation still publishes that window node. The toolkit name is `Yuzuko`. Every update is a full tree. Focus is the focused virtual node when that node is in the published tree, and the window node otherwise. Removing a focused node, or a focused descendant, clears that focus. Moving a node does not.

Recognized `role` tokens are `alert`, `alertdialog`, `application`, `article`, `banner`, `blockquote`, `button`, `caption`, `cell`, `checkbox`, `code`, `columnheader`, `combobox`, `complementary`, `contentinfo`, `definition`, `dialog`, `directory`, `document`, `emphasis`, `feed`, `figure`, `form`, `generic`, `grid`, `gridcell`, `group`, `heading`, `image`, `img`, `link`, `list`, `listbox`, `listitem`, `log`, `main`, `marquee`, `math`, `menu`, `menubar`, `menuitem`, `menuitemcheckbox`, `menuitemradio`, `meter`, `navigation`, `none`, `note`, `option`, `paragraph`, `presentation`, `progressbar`, `radio`, `radiogroup`, `region`, `row`, `rowgroup`, `rowheader`, `scrollbar`, `search`, `searchbox`, `separator`, `slider`, `spinbutton`, `status`, `strong`, `switch`, `tab`, `table`, `tablist`, `tabpanel`, `term`, `textbox`, `time`, `timer`, `toolbar`, `tooltip`, `tree`, `treegrid`, `treeitem`, and `window`. The match is case-sensitive after `ToString`. `generic`, `none`, `presentation`, an omitted role, and `""` publish a generic container. The getter returns `null` when `role` was cleared and `""` when it was set to an empty string. `directory` publishes a list. `image` and `img` publish an image. `option` publishes a list-box option. `progressbar` publishes a progress indicator. `radio` publishes a radio button. `scrollbar` publishes a scroll bar. `searchbox` publishes a search input. `separator` publishes a splitter. `textbox` publishes a text input, or a multiline text input when `multiline` is true. ## File system

The `fs` feature installs file-system functions on `Yuzuko` in the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have them. With the feature off, the names are absent. Each call checks Permissions before the operating-system call. A process with no policy may read and write any path the operating-system user can use. A packaged application can read its bundle and cannot modify it. `yuzuko run`, `yuzuko repl`, and `yuzuko test` record no bundle root, so the project tree can be written when the permission allows it. `file:` fetch stays limited to the entry directory and does not depend on `fs`.

A path string is a file-system path. A relative path is joined to the process current directory before the permission check, without removing `.` or `..`, and that absolute path is what the operating system opens. A later `chdir` does not retarget the call. `Yuzuko.cwd` reads that directory and `Yuzuko.chdir` replaces it. The path does not use the entry directory or the directory of `import.meta.url`. A `URL` object must be `file:`. A string that looks like `file://...` is a path, not a URL. An empty string is the current directory. A path component that is not UTF-8 is returned with U+FFFD for those bytes. An unpaired surrogate in a JavaScript string becomes U+FFFD.

For a packaged app, the process current directory is the directory from which the user launched the app. `Yuzuko.chdir` may name a directory inside the bundle and does not modify the bundle. A write through a `file:` URL under `import.meta.url` is inside the bundle and fails. A save file is an absolute path outside the bundle.

A synchronous call blocks the calling thread, including the main event loop. An asynchronous call runs the operating-system call on a background thread and settles the promise on that realm's event loop. A bad argument throws `TypeError` before the call. An operating-system failure rejects the promise, or throws from the synchronous form.

The functions are `open`, `create`, `readFile`, `readTextFile`, `writeFile`, `writeTextFile`, `mkdir`, `remove`, `rename`, `stat`, `lstat`, `readDir`, `copyFile`, `realPath`, `truncate`, `makeTempDir`, `makeTempFile`, `chmod`, `chown`, `link`, `symlink`, `readLink`, and `utime`. Each of those has a synchronous twin whose name ends in `Sync`. `umask` is synchronous and has no twin. `watchFs` returns an `FsWatcher` immediately. `create` and `createSync` take only a path and open it for write, with create and truncate, and without read. `readDir` returns an array of `{ name, isFile, isDirectory, isSymlink }`. The array is not sorted and is not an iterator. Directory entry types do not follow a symlink.

`Yuzuko.FsFile` has no public constructor. `new Yuzuko.FsFile()` throws. `read` and `readSync` take an `ArrayBufferView`, including a `DataView`, and return the number of bytes read, or `null` at the end of the file. A zero-length view returns `0` and does not change the view. Bytes past the read are left as they were. A bare `ArrayBuffer` throws `TypeError` with `The buffer must be a Uint8Array.` `write` and `writeSync` take a buffer source and return the count from one write, which can be short. `seek` and `seekSync` take an offset and a whence and return the new position. `stat` and `statSync` describe the open descriptor. `truncate` and `truncateSync` default the length to 0. `sync` and `syncSync` flush the file and its metadata. `syncData` and `syncDataSync` flush the file data. `lock`, `tryLock`, `unlock`, `utime`, `isTerminal`, `setRaw`, `readable`, and `writable` are also on `FsFile`. `close` releases the descriptor. A second close throws `BadResource` with `The file is closed.` When `Symbol.dispose` exists, it calls `close`. When `Symbol.asyncDispose` exists, it returns a promise for that close. Dropping the last handle closes the descriptor. `close` waits for an in-flight lock or terminal change on that file, then restores a terminal mode saved by `setRaw`.

`Yuzuko.stdin`, `Yuzuko.stdout`, and `Yuzuko.stderr` are `FsFile` values for the process standard streams. They are installed with `fs` on the main realm and in a dedicated worker, and they are absent when `fs` is off. Each is a duplicate of the process descriptor. On Unix the duplicate is created with `FD_CLOEXEC`. On Windows the duplicate is not inheritable. `close` closes that duplicate and does not close the process standard stream. A second `close` throws `BadResource` with `The file is closed.` The runtime does not call `setRaw` on them. `setRaw`, `isTerminal`, `readable`, and `writable` behave as they do on any other `FsFile`. A write to `stdout` or `stderr` emits bytes from the process. A read of `stdin` returns bytes fed to the process, or `null` at the end of the stream. The duplicate shares the file offset with the process stream, so a read in one realm advances the next read in every realm. These handles are not checked against a path grant. They do not replace the terminal the permission prompt or the REPL reads.


`Yuzuko.SeekMode` is the object `{ Start: 0, Current: 1, End: 2 }`. Whence must be exactly 0, 1, or 2, including a non-finite value, or the call throws `whence must be 0, 1, or 2.` The offset must be a finite integer. A non-finite offset throws `The seek offset must be a finite number.` A non-integer throws `The seek offset must be an integer.` A negative offset from the start throws `A seek from the start cannot be negative.` Current and end allow a negative offset. The returned position is a number and can be above 2^53.

File-system failures use the classes on `Yuzuko.errors`. The thrown value is an instance of the constructor installed at startup. Replacing a property later does not change the thrown object. `NotFound`, `AlreadyExists`, `PermissionDenied`, `IsADirectory`, `NotADirectory`, `Interrupted`, `InvalidData`, `ConnectionRefused`, `ConnectionReset`, `ConnectionAborted`, `NotConnected`, `AddrInUse`, `AddrNotAvailable`, `BrokenPipe`, `TimedOut`, `WriteZero`, `UnexpectedEof`, `WouldBlock`, and `NetworkUnreachable` are thrown for that operating-system kind. The message is the operating-system text. An operating-system invalid argument, `InvalidInput`, throws `TypeError`. A symbolic-link loop throws `FilesystemLoop`, including Unix `ELOOP` and Windows error 1921, and also when the kind's debug name is `FilesystemLoop`. A closed file throws `BadResource`. An unsupported operation, a seek on a file that cannot seek, a read-only file system, a busy resource, `DirectoryNotEmpty`, and any other operating-system failure throw a plain `Error` whose message is the operating-system text. When Deno would set `code` on that operating-system error, the thrown value has `code` set to that errno name. A call that is not an operating-system kind stays the class named for that call. That includes `NotSupported` for a packaged bundle, for `chown` on Windows, and for `setRaw` on a file that is not a terminal.

`chmod` and `chmodSync` set the mode to an integer from 0 through 262143. The process umask does not change that result. The operating system may store fewer bits. On macOS the stored mode is 16 bits. The call follows the final symlink. On Windows only the owner write bit is used: when `0o200` is clear the file becomes read-only, and when it is set the read-only attribute is cleared. The other bits are ignored.

`chown` and `chownSync` take a user id and a group id. `null` leaves that id unchanged. `undefined` throws `TypeError`. Each number is a finite integer from 0 through 4294967295. A non-integer throws `The user id must be an integer or null.` or `The group id must be an integer or null.` The call follows the final symlink. On Windows both forms throw `NotSupported` with `Changing the owner is not supported on Windows.` after the arguments are checked and before the file system is touched, including when the path does not exist.

`umask` returns the previous mask. An omitted argument leaves the mask unchanged. On Unix an omitted mask is read by setting the mask to 0 and restoring it, and another thread can observe that window. A supplied mask is an integer from 0 through 262143. On Windows the result is always 0 and a mask in that range is ignored. A bad mask still throws `TypeError`. `umask` does not use a path and does not consult the bundle root.

`link` and `linkSync` create a hard link. The final component of neither path is followed. Both paths are bundle mutations of the directory entry. `symlink` and `symlinkSync` store `oldPath` as the link text. A string is stored as that string, and a file URL is stored as its file-system path. The target does not have to exist, and `oldPath` is not resolved against the bundle. Only `newPath` is created. The permission check for a relative target joins it to the parent of `newPath`. The stored text stays the caller's string. A Windows junction's relative target is joined to the current directory once, before the permission check, and the reparse text is that checked path, so a later `chdir` does not change it. On Unix a `"junction"` type creates a symbolic link, so its relative target is checked from the parent of `newPath` like any other. `options.type` is `"file"`, `"dir"`, or `"junction"`. Omitted means `"file"`. Any other value throws `The link type must be "file", "dir", or "junction".` Unix ignores the type. Windows creates that kind of link. A junction is a mount-point reparse point. A relative junction target is joined to the current directory for the reparse text. Creating a symlink can throw `PermissionDenied` on Windows when the process is not allowed to create one. `readLink` and `readLinkSync` return the stored text without canonicalizing it. A NUL in that text becomes U+FFFD. A path that is not a symlink throws the operating-system error. Reading a link does not modify the bundle.

`utime` and `utimeSync`, and `FsFile.utime` and `FsFile.utimeSync`, set the access time and the modification time. Each time is a `Date` or a finite number of seconds since the Unix epoch, and a fractional second is kept. A string, boolean, `null`, or `undefined` throws `The time must be a Date or a finite number.` before number conversion, so the string `"1700000000"` is rejected. Another object uses `ToNumber`. A non-finite result throws that same message. A time the operating system cannot store throws `The time is out of range.` Those checks throw before the call. The path form follows the final symlink. `FsFile.utime` uses the open descriptor. When a bundle root is set, a descriptor whose path cannot be resolved is rejected.

`lock` and `lockSync` take an optional exclusive flag. An omitted or `undefined` flag is a shared lock. A present value uses `ToBoolean`, so `null` is shared. A conversion that throws rejects or throws `The lock mode could not be read.` The lock is advisory and covers the whole file. The asynchronous form waits on a background thread. `tryLock` and `tryLockSync` return a boolean and do not wait. A closed file throws `BadResource` with `The file is closed.` On Unix the lock is per process, so a second lock in the same process succeeds. On Windows a lock is per handle. Unlocking a file that is not locked succeeds on Unix. On Windows that unlock throws a plain `Error`. An interrupted wait inside the lock is retried. The lock is not a bundle check.

`isTerminal` returns a boolean. A descriptor that is not a terminal returns `false` and does not throw. `setRaw(mode, options)` is synchronous. `mode` uses `ToBoolean`, and a conversion that throws is rethrown. `options.cbreak` defaults to false. `null` or `undefined` options use that default. The first `setRaw(true)` saves the terminal mode. A later `setRaw(true)` starts from that saved mode and does not replace it. `setRaw(false)` restores it. `setRaw(false)` with nothing saved does nothing, including on a file that is not a terminal. `setRaw(true)` on a file that is not a terminal throws `NotSupported` with `The file is not a terminal.` `cbreak` keeps signal characters. The call is not a bundle check.

`readable` and `writable` are getters. Each returns the same stream for that file. Calling the getter on a value that is not an `FsFile` throws `TypeError` with `illegal invocation`. `readable` is a default readable stream. A pull reads at most 16384 bytes into a new buffer. `null` closes the stream. A read of 0 enqueues nothing. Any other count enqueues that prefix. A rejected read errors the stream. Cancelling the stream does not close the file. `writable` accepts a view, an `ArrayBuffer`, or a `SharedArrayBuffer`. Anything else errors the stream with `Data must be a BufferSource.` A short write is repeated until the chunk is consumed. A write that returns 0 errors the stream with `The write wrote no bytes.` An empty chunk resolves without writing. Closing or aborting the writable stream does not close the file. Both streams use the file's current position.

`watchFs(paths, options)` returns a `Yuzuko.FsWatcher`. There is no public constructor. `paths` is a string, a file URL, or an array of those. An empty array throws `At least one path is required.` A value that is none of those throws `The paths must be a string, a file URL, or an array.` A bad element uses the path error. Each path must already exist, and that check follows a symlink. Watching is a read, so a path inside the bundle is allowed. `options.recursive` defaults to true. `null` or `undefined` options use that default. `{ recursive: null }` is not recursive. The watcher is an async iterator. `[Symbol.asyncIterator]()` returns the watcher, and calling it on another object throws `TypeError` with `illegal invocation`. `next` resolves `{ value, done }`. `value` is `{ kind, paths, flag }`. `kind` is `"access"`, `"create"`, `"modify"`, `"remove"`, `"rename"`, `"any"`, or `"other"`. `paths` are absolute path strings. `flag` is `"rescan"` when the watcher lost events, and it is omitted otherwise. A NUL in a reported path becomes U+FFFD. One action can produce several events. `close` stops the watcher. A second `close` throws `BadResource` with `The watcher is closed.` `return` stops the watcher and resolves `{ done: true }` even when it is already closed, and it does not consume a queued event. After the watcher is closed, `next` returns queued events and then `{ done: true }`. An open watcher keeps the process alive until `close` or `return`. On macOS the watch is a kqueue vnode watch. A directory event names that directory, not the child that changed. On Linux the watch is inotify and names the child. On Windows the watch is `ReadDirectoryChangesW`. More than 60 paths throws `NotSupported` with `Too many watch paths.` before the paths are checked. A file is watched through its parent, and only that file's events are reported. A file with no parent throws `NotSupported` with `The path has no parent directory.` A recursive watch that would add more than 4096 directories reports one `{ kind: "any", flag: "rescan", paths: [] }` and stops adding watches. An operating system other than Linux, macOS, and Windows throws `NotSupported` with `watchFs is not supported on this operating system.` before the paths are checked.

An option named `signal` is ignored. Unknown option fields are ignored.

Omitted `open` options, and `null` or `undefined`, mean `{ read: true }`. On an options object, `read` defaults to true and `write`, `append`, `truncate`, `create`, and `createNew` default to false, so `{ write: true }` is read and write. A missing property keeps the default. A present property uses `ToBoolean`, so `{ read: null }` does not read. `truncate` without `write` or `append` throws `truncate requires write access.` `create` or `createNew` without `write` or `append` throws `create requires write or append access.` `read`, `write`, and `append` all false throws `The file must be opened for reading or writing.` `append` together with `truncate` throws `append and truncate cannot both be set.` When both `create` and `createNew` are set, `createNew` is used. `mode` is an integer from 0 through 262143. On Unix it is applied to the new file or directory and the process umask still applies. On Windows `mode` is ignored. Opening a directory is allowed. A later read of that descriptor is operating-system dependent.

`writeFile` and `writeTextFile` create the file and truncate it unless `append` is set. `append` does not truncate. `create` defaults to true. Parent directories are not created. `writeFile` data is a buffer source, not a string (`Data must be a BufferSource.`). `writeTextFile` requires a string (`Text must be a string.`) and writes UTF-8. A buffer longer than 2147483647 bytes throws `The buffer is too large.` A detached buffer throws `The buffer is detached.` `readFile` has no size limit. A directory throws `IsADirectory` with `The path is a directory.` A symlink to a directory does too. `readTextFile` of bytes that are not UTF-8 throws `InvalidData` with `The file is not valid UTF-8.`

`mkdir` takes `{ recursive, mode }`. It resolves `.`, `..`, and symlinks, then creates that path, so a `..` that leaves the bundle does not create a directory inside the bundle on the way. Non-recursive creation of an existing directory throws `AlreadyExists`. Recursive creation succeeds when the resolved path is already a directory, and throws `AlreadyExists` when that path exists and is not a directory. `remove` without `recursive` deletes a file, an empty directory, or a symlink, and does not follow that symlink. `recursive: true` deletes a directory tree. A symlink is still deleted as a file. A directory that is not empty throws a plain `Error`. `rename` renames both paths. `copyFile` overwrites the destination after the opened file is checked, and returns undefined. `truncate` on a path requires the file to exist and changes that file only after the opened file is checked. `stat` follows a final symlink and reports the target. Its read check names the link, so the target does not need its own grant. `lstat` names and reports the link. `remove` without `recursive` deletes the entry and does not follow a final symlink. `recursive: true` is denied when a descendant is denied. `realPath` returns the canonical path when that path is granted. When it is not, the call throws `NotCapable` naming the requested path and does not return the other path.

`FileInfo` is a plain object: `isFile`, `isDirectory`, `isSymlink`, `size`, `mtime`, `atime`, `birthtime`, `mode`, `dev`, `ino`, `nlink`, `uid`, `gid`, `blksize`, `blocks`, `isBlockDevice`, `isCharDevice`, `isFifo`, and `isSocket`. Times are `Date` objects, or `null` when the time is missing or before the Unix epoch. On Windows the identity fields are 0 and the device-type flags are false.

`makeTempDir` and `makeTempFile` take `{ dir, prefix, suffix }`. The default directory is the operating-system temporary directory. That directory is read once, before the write check, and the file or directory is created there, so a later change to `TMPDIR` does not move it. An omitted prefix or suffix is empty. A prefix or suffix that is not a string throws `The prefix must be a string.` or `The suffix must be a string.` One that contains `/`, `\`, or NUL throws `The prefix must not contain a path separator or NUL.` or the same sentence for the suffix. Those checks throw before the call. The name is the prefix, the time in hexadecimal, `-`, the process id, `-`, a counter in hexadecimal, and the suffix. A name that already exists is tried again, up to 64 times, and then throws `AlreadyExists` with `Could not create a unique temporary path.` The returned path is absolute, with parent symlinks resolved.

A path that is not a string or a `file:` URL throws `The path must be a string or a file URL.` Another URL scheme throws `The URL scheme must be file.` An unusable URL throws `The URL is invalid.` A `file:` URL that is not a path throws `The file URL is invalid.` Options that are not an object, `null`, or `undefined` throw `Options must be an object.` A getter that throws, or a field that cannot be read, throws `The options could not be read.` `mode` outside 0 through 262143 throws `mode must be an integer from 0 through 262143.` A length that is not a finite integer of at least 0 throws `The length must be an integer that is at least 0.` A panic in the background call rejects or throws `The file operation failed.`

A packaged launch records the bundle root before the entry runs. On macOS the root is the `.app` bundle. On Windows and Linux it is the directory that contains the executable and `yuzuko.bundle.json`. A mutation whose resolved path is that directory, or a path inside it, throws `NotSupported` with `Cannot modify the application bundle.` `open` for write, `writeFile`, `writeTextFile`, `truncate`, `chmod`, `chown`, `utime`, and a `copyFile` destination follow the final symlink, so a symlink outside the bundle that points inside it is rejected. `remove`, `rename`, `link`, `mkdir`, `symlink`'s new path, and a temporary path keep the directory entry: deleting a symlink that lives outside the bundle is allowed when the symlink points into the bundle. The text stored in a symbolic link is not a bundle check. `FsFile.utime` rejects a descriptor inside the bundle when a bundle root is set. `autoUpdate` writes `Updates/` from Rust and is not subject to this guard.

## Datagrams

The `udp` feature installs `Yuzuko.listenDatagram` and `Yuzuko.Datagram` on the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have them. With the feature off, the names are absent. `listenDatagram` and `send` check the net permission in Permissions. A process with no policy may send and receive datagrams on any address the operating-system user can use. The names are not on `globalThis`. `listenDatagram` is not a constructor. `Yuzuko.Datagram` has no public constructor. `new Yuzuko.Datagram()` throws `TypeError` with `Illegal constructor`. Calling `send`, `connect`, `disconnect`, `setBroadcast`, `joinMulticast`, `leaveMulticast`, `receive`, or `close`, or reading `addr`, on a value that is not a `Datagram` throws `TypeError` with `illegal invocation`.

`listenDatagram(options)` binds a UDP socket and returns the `Datagram`. It has length 0. An omitted argument, `null`, or `undefined` binds `127.0.0.1` and port `0`. `options` otherwise must be an object. Anything else throws `TypeError` with `Options must be an object.` Unknown fields are ignored. `reusePort` may be omitted, `null`, `undefined`, or `false`, and then the bind is unchanged. The boolean primitive `true` creates the socket and sets `SO_REUSEPORT` before `bind` on macOS and Linux. Any other value throws `TypeError` with `reusePort must be a boolean.` On Windows, `true` throws `Yuzuko.errors.NotSupported` with `Windows cannot reuse a listening port.` before a socket is created. `hostname` defaults to `"127.0.0.1"` when it is omitted or `undefined`. A present value is converted with `ToString`. `localhost` is ASCII case-insensitive and means `127.0.0.1`. Any other value must be an IP address, without surrounding brackets. A DNS name, an empty string, or a bracketed address throws `TypeError` with `The hostname must be an IP address or "localhost".` There is no DNS lookup. `port` defaults to `0` when it is omitted or `undefined`. A present value is converted with `ToNumber` and must be an integer from 0 through 65535. `-0` is 0. Any other result throws `TypeError` with `The port must be an integer from 0 through 65535.` If `ToString` or `ToNumber` throws, or a getter throws, `listenDatagram` throws that exception. When the options cannot be read for any other reason, it throws `TypeError` with `The options could not be read.` Port `0` asks the operating system for an ephemeral port. The call binds before it returns and blocks the caller for that bind. A failure whose kind is listed in Socket errors throws that class. Any other failure throws `Error` with `The socket could not bind.` The messages do not include operating-system text.

`addr` returns a new plain object on each read. `hostname` is the bound IP address, so a `localhost` bind reports `127.0.0.1`. `port` is the bound port and is not `0` after an ephemeral bind. Those values do not change.

`send(data, addr)` has length 1. Fewer arguments throw `TypeError` with `Not enough arguments.` `data` is a `BufferSource`: an `ArrayBuffer`, a `SharedArrayBuffer`, or a view, including a view with a byte offset. A string or any other value throws `TypeError` with `The data must be a BufferSource.` A detached buffer throws `The buffer is detached.` A buffer longer than 65507 bytes throws `The datagram is too large.` Those checks throw before a promise is returned. An omitted `addr`, or `undefined`, sends to the connected peer. When the socket is not connected, that call throws `Yuzuko.errors.NotConnected` with `The socket is not connected.` before a promise is returned. A closed socket still rejects `BadResource` before that check. A present `addr`, including `null`, must be an object. `null` or any other value throws `TypeError` with `The address must be an object.` A failure while reading it throws `TypeError` with `The address could not be read.` The exact ASCII case-insensitive name `localhost` means `127.0.0.1` and is not a DNS lookup. An IP address, without surrounding brackets, is that address. Any other non-empty name is a DNS name. The lookup uses the trimmed text, including its case and a trailing DNS root dot. An empty string or a bracketed address throws `TypeError` with `The hostname must be an IP address or "localhost".` An omitted port is `0`. Its port uses `ToNumber` and must be an integer from 1 through 65535, so an omitted port throws. Any other result throws `TypeError` with `The port must be an integer from 1 through 65535.` The net check uses the host string before the lookup. A name denial throws `Yuzuko.errors.NotCapable` before a promise is returned. An IP literal whose address family differs from the bound socket throws `TypeError` with `The address family does not match the socket.` before a promise is returned. The call then returns a promise and sends on a background thread. A DNS name is resolved there. A restricted address is checked again. The send uses the first allowed address whose family matches the bound socket. When none of the allowed addresses match that family, the promise rejects `TypeError` with `The address family does not match the socket.` When every resolved address is denied, the promise rejects `Yuzuko.errors.NotCapable`. A name that cannot be resolved rejects `Error` with `The host could not be resolved.` A lookup that the operating system reports as timed out is that resolve failure, not `TimedOut`. The promise resolves to the number of bytes the operating system accepted. An empty datagram resolves `0`. A closed socket rejects `BadResource` with `The socket is closed.` A failure whose kind is listed in Socket errors rejects that class. Any other operating-system failure rejects `Error` with `The datagram could not be sent.` A panic in the background call rejects that same message. The messages do not include operating-system text.

`receive()` has length 0. It returns a promise for the next datagram and does not block the realm thread. The result is a plain object `{ data, hostname, port }`. `data` is a new `Uint8Array` of the payload the operating system delivered, at most 65536 bytes. `hostname` and `port` are the source address. `hostname` has no brackets. At most one `receive` waits on a socket. A second call rejects `Busy` with `A receive is already waiting.` A closed socket rejects `BadResource` with `The socket is closed.` `close` while a receive is waiting rejects that same message. A receive that the operating system reports as a connection reset keeps waiting, because UDP has no connection. An operating-system failure whose kind is listed in Socket errors rejects that class. Any other operating-system failure rejects `Error` with `The datagram could not be received.` A panic in the background call rejects that same message.

`close()` has length 0. It drops the socket. A second `close` throws `BadResource` with `The socket is closed.` Dropping the last handle also closes the socket. An open socket does not keep the process alive. A waiting `send` or `receive` does, until that promise settles. When the runtime cannot create that promise, `send`, `connect`, and `receive` throw `TypeError` with `The socket operation failed.` `connect(addr)` has length 1. `addr` uses the same destination rules as a `send` that passes an address. The promise resolves `undefined` after the operating system stores that default peer. It is not a handshake. A failure whose kind is listed in Socket errors rejects that class. Any other failure rejects `Error` with `The socket could not be connected.` `disconnect()` has length 0. It clears the default peer. On macOS and Linux, `EAFNOSUPPORT`, `EINVAL`, and `ENOTCONN` still count as success. On Windows, `WSAEAFNOSUPPORT`, `WSAEINVAL`, and `WSAENOTCONN` still count as success. Any other failure throws `Error` with `The socket could not be disconnected.` `setBroadcast(enabled)` has length 1. `enabled` must be a boolean primitive. The call does not use `ToBoolean`. Any other value throws `TypeError` with `enabled must be a boolean.` `true` sets `SO_BROADCAST` and `false` clears it. A failure throws `Error` with `The broadcast option could not be set.` `joinMulticast(address, networkInterface)` and `leaveMulticast(address, networkInterface)` each have length 1. `address` must be a string primitive that parses as a multicast IP address. The call does not use `ToString`. Any other value throws `TypeError` with `The address must be a multicast address.` An address family that differs from the bound socket throws `TypeError` with `The address family does not match the socket.` An omitted `networkInterface`, `null`, or `undefined` uses `0.0.0.0` for an IPv4 group and interface index `0` for an IPv6 group. A string is an IPv4 interface address and is accepted only for an IPv4 group. A number primitive is an IPv6 interface index, an integer from 0 through 4294967295, and is accepted only for an IPv6 group. The call does not use `ToNumber`. A string on an IPv6 group throws `TypeError` with `The network interface must be an index.` A number on an IPv4 group, or any other value on an IPv4 group, throws `TypeError` with `The network interface must be an address.` A string that is not an IPv4 address throws that address message. A number that is not that integer, or any other value on an IPv6 group, throws the index message. Joining sets `IP_ADD_MEMBERSHIP`, and `IPV6_JOIN_GROUP` on macOS or `IPV6_ADD_MEMBERSHIP` on Linux. Leaving sets `IP_DROP_MEMBERSHIP`, and `IPV6_LEAVE_GROUP` on macOS or `IPV6_DROP_MEMBERSHIP` on Linux. A failure throws `Error` with `The multicast group could not be joined.` or `The multicast group could not be left.` A later `send` still checks its destination. `disconnect`, `setBroadcast`, `joinMulticast`, and `leaveMulticast` throw `BadResource` with `The socket is closed.` when the socket is already closed.

## TCP

The `tcp` feature installs `Yuzuko.listenTcp`, `Yuzuko.connectTcp`, `Yuzuko.TcpListener`, and `Yuzuko.TcpConn` on the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have them. With the feature off, the names are absent. `listenTcp` and `connectTcp` check the net permission in Permissions. `addr` on a listener returns a new plain object on each read. `hostname` is the bound IP address, so a `localhost` bind reports `127.0.0.1`. `port` is the bound port and is not `0` after an ephemeral bind.

`accept()` has length 0. It returns a promise for the next connection and does not block the realm thread. The promise resolves a `TcpConn`. At most one `accept` waits on a listener. A second call rejects `Busy` with `An accept is already waiting.` A closed listener rejects `BadResource` with `The socket is closed.` `close` while an accept is waiting rejects that same message. An operating-system failure whose kind is listed in Socket errors rejects that class. Any other operating-system failure rejects `Error` with `The connection could not be accepted.` A panic in the background call rejects that same message. The messages do not include operating-system text. When the runtime cannot create that promise, `accept` throws `TypeError` with `The socket operation failed.`

`connectTcp(addr)` has length 1. An empty string or a bracketed address throws `TypeError` with `The hostname must be an IP address or "localhost".` An omitted port is `0`. Its port uses `ToNumber` and must be an integer from 1 through 65535, so an omitted port throws. Any other result throws `TypeError` with `The port must be an integer from 1 through 65535.` The net check uses the host string before the lookup. A name denial throws `Yuzuko.errors.NotCapable` before a promise is returned. The call then returns a promise, resolves the name, checks each restricted address again, and connects to the allowed addresses in order. The promise resolves a `TcpConn` for the first success. When every resolved address is denied, the promise rejects `Yuzuko.errors.NotCapable`. A name that cannot be resolved rejects `Error` with `The host could not be resolved.` A lookup that the operating system reports as timed out is that resolve failure, not `TimedOut`. A connect failure uses the classes in Socket errors. When every address fails, the rejection is the last of those failures. Any other failure rejects `Error` with `The connection could not be opened.` A panic rejects that message. When the runtime cannot create that promise, `connectTcp` throws `TypeError` with `The socket operation failed.`

`localAddr` and `remoteAddr` each return a new plain object on each read. `hostname` is an IP address without brackets. `port` is the local or peer port. A connection disables Nagle's algorithm when the operating system allows it.

`read(buffer)` has length 1. `buffer` is a `BufferSource`: an `ArrayBuffer`, a `SharedArrayBuffer`, or a view, including a view with a byte offset. A string or any other value throws `TypeError` with `The data must be a BufferSource.` A detached buffer throws `The buffer is detached.` A buffer longer than 2147483647 bytes throws `The buffer is too large.` A zero-length buffer resolves `0` and does not wait. Otherwise the call returns a promise and reads on a background thread. If `buffer` was detached or no longer covers those bytes, the promise rejects `Error` with `The buffer is detached.` At most one `read` waits on a connection. A second call rejects `Busy` with `A read is already waiting.` A `write` may wait at the same time. A closed connection rejects `BadResource` with `The socket is closed.` `close` while a read is waiting rejects that same message, including when the operating system reports end of stream because this side closed. A failure whose kind is listed in Socket errors rejects that class. A clean read of zero bytes resolves `null` and is not `UnexpectedEof`. A poll timeout while the read is waiting is not `TimedOut`. Any other operating-system failure rejects `Error` with `The bytes could not be read.` A panic rejects that same message. When the runtime cannot create that promise, `read` throws `TypeError` with `The socket operation failed.`

`write(data)` has length 1. `data` uses the same `BufferSource` rules and the same 2147483647-byte limit. Those checks throw before a promise is returned. The bytes are copied before the call returns, so the caller may reuse the buffer. An empty buffer resolves `0` and does not wait. Otherwise the call returns a promise, writes every copied byte, and resolves that count. It does not resolve a short write. At most one `write` waits. A second call rejects `Busy` with `A write is already waiting.` A closed connection rejects `BadResource` with `The socket is closed.` A failure whose kind is listed in Socket errors rejects that class. A poll timeout while the write is waiting is not `TimedOut`. A write that returns zero rejects `WriteZero` with `The bytes could not be written.` Any other operating-system failure rejects `Error` with `The bytes could not be written.` A panic rejects that same message. When the runtime cannot create that promise, `write` throws `TypeError` with `The socket operation failed.`

`close()` has length 0 on a listener and on a connection. It ends the socket. A second `close` throws `BadResource` with `The socket is closed.` Dropping the last handle also closes it. An open listener or connection does not keep the process alive. A waiting `accept`, `connectTcp`, `read`, or `write` does, until that promise settles. There is no half-close. DNS names and TLS are described in DNS and TLS.


## DNS

`Yuzuko.resolveDns` is installed when `tcp` or `udp` is enabled, on the main realm and in a dedicated worker. It is absent when both features are off. An `AudioWorklet` processor realm does not have it. It is not a constructor.

`resolveDns(host, type)` returns a promise of an array of address strings. It has length 2. `host` and `type` must be string primitives. Another type does not run `ToString`. A host that is not a string throws `TypeError` with `The host must be a string.` An empty host throws `The host must not be empty.` A type that is not a string, or a string other than `"A"`, `"AAAA"`, `"CNAME"`, `"NS"`, `"PTR"`, `"MX"`, `"TXT"`, `"SRV"`, `"SOA"`, `"CAA"`, or `"NAPTR"`, throws `TypeError` with `The record type must be "A", "AAAA", "CNAME", "NS", "PTR", "MX", "TXT", "SRV", "SOA", "CAA", or "NAPTR".` Those checks throw before a promise is returned and do not look up a name. The net check is the host with no port, so a grant of that host with no port allows the call and a grant of one port does not. A denial throws `Yuzuko.errors.NotCapable` before a promise is returned. The message quotes the host and does not add a port. The lookup uses the trimmed host, including its case and a trailing DNS root dot. It does not rewrite `localhost` to `127.0.0.1`. `"A"` keeps IPv4 addresses and `"AAAA"` keeps IPv6 addresses. Duplicate addresses are removed. The promise resolves those strings. A name that exists and has no records of that type resolves `[]`. A name that cannot be resolved rejects `Error` with `The host could not be resolved.` A lookup that the operating system reports as timed out is that same failure, not `Yuzuko.errors.TimedOut`. `"A"` and `"AAAA"` resolve those address strings. `"CNAME"`, `"NS"`, and `"PTR"` resolve string arrays. `"MX"` resolves `{ preference, exchange }`. `"TXT"` resolves an array of character-string arrays, one inner array per record, and invalid UTF-8 uses the replacement character. `"SRV"` resolves `{ priority, weight, port, target }`. `"SOA"` resolves `{ mname, rname, serial, refresh, retry, expire, minimum }`. `"CAA"` resolves `{ critical, tag, value }`, and `critical` is bit 0 of the flags. `"NAPTR"` resolves `{ order, preference, flags, services, regexp, replacement }`. Only records of the requested type are returned. A `CNAME` in the answer does not become a record of another type. Domain names have no trailing dot. The other types use the system resolver. An empty answer of that type resolves `[]`. `NXDOMAIN`, `SERVFAIL`, a timeout, and any other resolver failure reject `Error` with `The host could not be resolved.`

## TLS

`Yuzuko.connectTls`, `Yuzuko.startTls`, and `Yuzuko.TlsConn` are installed when `tcp` is enabled, on the main realm and in a dedicated worker. They are absent when `tcp` is off. An `AudioWorklet` processor realm does not have them. They are not on `globalThis`. `connectTls` and `startTls` are not constructors. `Yuzuko.TlsConn` has no public constructor. `new Yuzuko.TlsConn()` throws `TypeError` with `Illegal constructor`. Calling a method, or reading an address, on a value that is not a `TlsConn` throws `TypeError` with `illegal invocation`.

`connectTls(options)` has length 1. `options` must be an object. `hostname` uses the same destination rules as `connectTcp`, including a DNS name. `port` defaults to 443 when it is omitted or `undefined`. A present port uses `ToNumber` and must be an integer from 1 through 65535. `caCerts` is an optional array of PEM strings. Those certificates are trusted in addition to the default web PKI roots. `caCerts` that is not an array, or an element that is not a string, throws `TypeError` with `caCerts must be an array of PEM strings.` An empty PEM, a PEM that cannot be parsed, or a certificate that cannot be added throws `TypeError` with `The certificate is not valid PEM.` Those checks throw before a promise is returned. The net check uses the hostname and port before the lookup. A name denial throws `Yuzuko.errors.NotCapable` before a promise is returned. The call then returns a promise. It resolves the name, checks restricted addresses, connects, and completes the TLS handshake before the promise resolves. The promise resolves a `TlsConn`. Certificate verification is not skipped. The server name is `hostname`. A handshake that does not finish rejects `Error` with `The TLS handshake failed.` A connect or resolve failure uses the same classes and messages as `connectTcp`. The handshake does not use the short poll timeout.

`startTls(conn, options)` upgrades an open `TcpConn`. `conn` must be a `TcpConn`. Another value throws `TypeError` with `The connection must be a TcpConn.` `options.hostname` is the server name and is checked with the same string rules as a connect hostname. `options.caCerts` uses the same PEM rules. The net check uses that hostname and the connection's remote port before the TCP stream is taken. A denial throws `Yuzuko.errors.NotCapable` and leaves the `TcpConn` open. A read or a write that is already waiting throws `Busy` with `A read is already waiting.` or `A write is already waiting.` and leaves the connection open. A closed `TcpConn` throws `BadResource` with `The socket is closed.` Otherwise the call takes the TCP stream, marks the `TcpConn` closed without shutting the socket down, and returns a promise. The handshake runs before the promise resolves. The promise resolves a `TlsConn`. A handshake failure leaves the `TcpConn` closed and rejects `Error` with `The TLS handshake failed.`

`TlsConn` has `read`, `write`, `close`, `localAddr`, and `remoteAddr`. They follow `TcpConn`, including the socket error classes. A waiting read uses a short timeout so `close` can finish. That timeout is not `TimedOut`. `close` shuts the socket down. When a read holds the stream, `close` marks the connection closed and that read drops the stream instead of putting it back.

## Socket errors

`listenDatagram`, `listenTcp`, `Datagram.send`, `connectTcp`, `TcpConn.read`, `TcpConn.write`, `connectTls`, `startTls`, `TlsConn` `read` and `write`, and `listenHttp` map an operating-system failure that is not a poll retry onto `Yuzuko.errors`. The classes are installed in every build. The thrown value is the constructor captured when the realm started. Replacing the property later does not change it. `instanceof` that class and `instanceof Error` are both true. `name` is the class name.

| Kind | Class | Message |
| --- | --- | --- |
| address already in use | `AddrInUse` | The address is already in use. |
| address not available | `AddrNotAvailable` | The address is not available. |
| connection refused | `ConnectionRefused` | The connection was refused. |
| connection reset | `ConnectionReset` | The connection was reset. |
| connection aborted | `ConnectionAborted` | The connection was aborted. |
| not connected | `NotConnected` | The socket is not connected. |

## HTTP

The `http` feature installs `Yuzuko.listenHttp`, `Yuzuko.HttpServer`, and `Yuzuko.HttpRequest` on the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have them. A present value is converted with `ToNumber` and must be an integer from 0 through 65535. `-0` is 0. Any other result throws `TypeError` with `The port must be an integer from 0 through 65535.` If `ToString` or `ToNumber` throws, or a getter throws, `listenHttp` throws that exception. The server speaks HTTP/1.0 and HTTP/1.1. There is no TLS and no HTTP/2. Each accepted connection carries one request. The request version must be `HTTP/1.0` or `HTTP/1.1`. The request target must be origin-form, beginning with `/`, at most 8192 bytes, and is returned without decoding. A missing `Host` header is accepted. `Transfer-Encoding` is accepted only when every coding is `identity`, and it does not replace `Content-Length`. A missing `Content-Length` is an empty body. Duplicate `Content-Length` values must be identical. The server does not send `100 Continue`. Bytes after the request body are ignored. The connection disables Nagle's algorithm when the operating system allows it.

`addr` on a server returns a new plain object on each read. `hostname` is the bound IP address, so a `localhost` bind reports `127.0.0.1`. `port` is the bound port and is not `0` after an ephemeral bind.

`accept()` has length 0. It returns a promise for the next request and does not block the realm thread. The promise resolves an `HttpRequest`. At most one `accept` waits. A second call rejects `Busy` with `An accept is already waiting.` A closed server rejects `BadResource` with `The socket is closed.` `close` while an accept is waiting rejects that same message. A header block longer than 65536 bytes, or a body longer than 1048576 bytes, rejects `Error` with `The request is too large.` A malformed request rejects `Http` with `The request could not be read.` An operating-system failure while accepting the connection rejects the class in Socket errors, or `Error` with `The connection could not be accepted.` when the kind is not listed. A panic in the background call rejects `Http` with `The request could not be read.` The messages do not include operating-system text. When the runtime cannot create that promise, `accept` throws `TypeError` with `The socket operation failed.`

Any other value throws `TypeError` with `The data must be a string or a BufferSource.` A detached buffer throws `The buffer is detached.` A body longer than 1048576 bytes throws `The data is too large.` Those checks throw before a promise is returned. The bytes are copied before the call returns, so the caller may reuse the buffer. `status` defaults to `200` when it is omitted or `undefined`. A present value is converted with `ToNumber` and must be an integer from 100 through 599. Any other result throws `TypeError` with `The status must be an integer from 100 through 599.` The call then returns a promise and writes on a background thread. ## Signals

The `signal` feature installs `Yuzuko.addSignalListener` and `Yuzuko.removeSignalListener` on the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have them. With the feature off, the names are absent. There is no permission prompt. The feature does not enable `window`. The names are not on `globalThis`. Neither function is a constructor.

`addSignalListener(signal, listener)` and `removeSignalListener(signal, listener)` each have length 2. Fewer arguments throw `TypeError` with `Not enough arguments`. Extra arguments are ignored. `signal` must be a string primitive. The call does not use `ToString`. Any other type throws `TypeError` with `The signal must be a string.` On macOS and Linux the catchable names are `SIGHUP`, `SIGINT`, `SIGQUIT`, `SIGPIPE`, `SIGALRM`, `SIGTERM`, `SIGUSR1`, `SIGUSR2`, `SIGCHLD`, `SIGCONT`, `SIGTSTP`, `SIGTTIN`, `SIGTTOU`, `SIGURG`, `SIGXCPU`, `SIGXFSZ`, `SIGVTALRM`, `SIGPROF`, `SIGWINCH`, and `SIGIO`. Linux also catches `SIGPWR` and `SIGSTKFLT`. macOS also catches `SIGINFO` and `SIGEMT`. `SIGKILL` and `SIGSTOP` throw `TypeError` with `The signal cannot be caught.` Any other name, including `SIGABRT`, `SIGILL`, `SIGTRAP`, `SIGBUS`, `SIGFPE`, `SIGSEGV`, and `SIGSYS`, throws `TypeError` with `The signal is not supported.` On Windows only `SIGINT` and `SIGTERM` can be caught. Any other name from that Unix list throws `Yuzuko.errors.NotSupported` with `Windows cannot catch this signal.` `SIGKILL`, `SIGSTOP`, and a name outside that list, including `SIGABRT`, throw the same type errors as on Unix. `listener` must be a function. Any other value throws `TypeError` with `The listener must be a function.`

`addSignalListener` registers `listener` for that signal in the calling realm. The same function object is registered once; a second add for that pair does nothing. `removeSignalListener` removes one registration of that function object in the calling realm. Removing a function that is not registered succeeds. Listeners run in registration order, on the realm thread, with no arguments and with `this` as `undefined`. A return value is ignored. A listener added during a delivery does not run for that delivery. A listener removed before it is called does not run. A listener that throws does not skip the later listeners for that delivery. The exception is reported with `reportError`. During `yuzuko test` it fails the test.

The first listener for a signal, in any realm, replaces that signal's default terminate action. The handler only records the signal. It does not run JavaScript. Each recorded signal is delivered once to every realm that has a listener for it. Those listeners then run on that realm's thread. Removing the last listener for a signal, across every realm, restores the previous disposition. Shutting down a realm drops only that realm's listeners. A dedicated worker's shutdown does not restore the default action while the main realm, or another worker, still has a listener. A registered listener does not keep the process alive. A delivery that has been recorded and not yet run does, until those listeners are called. If the operating system cannot install the handler, `addSignalListener` throws `Error` with `The signal could not be caught.` and does not register that listener. A signal that cannot be recorded is dropped.

On Unix the handler is installed with `sigaction`, `SA_RESTART`, and without `SA_RESETHAND`. The signal number is the platform's libc constant. `SIGILL`, `SIGTRAP`, `SIGABRT`, `SIGBUS`, `SIGFPE`, `SIGSEGV`, and `SIGSYS` are not caught. `SIGKILL` and `SIGSTOP` cannot be caught. On Windows, `SIGINT` is `CTRL_C_EVENT` and `SIGTERM` is `CTRL_BREAK_EVENT`, because Windows has no `SIGTERM`. There is no second name for Ctrl+Break. A Windows process without a console does not observe those events. The handler returns that it handled the event only while a listener for that signal remains, so the process is not terminated. Other console events keep their default action.

`Yuzuko.raiseSignal(signal)` exists only during `yuzuko test`, on the main realm and in a dedicated worker, and only when `signal` is enabled. It is absent during `yuzuko run` and `yuzuko repl`. It has length 1. It uses the same `signal` checks. It asks the operating system to deliver that signal to this process and returns after the delivery has been queued for this realm. It does not call the listener. No listener for that signal in this realm throws `Error` with `The signal is not caught.` and does not deliver the signal. If the operating system does not accept the signal, or the delivery is not queued, it throws `Error` with `The signal could not be delivered.` On Unix the call is `raise`. On Windows it is `GenerateConsoleCtrlEvent` for the console process group.

## Child processes

## Foreign functions

The `ffi` feature installs `Yuzuko.dlopen` and `Yuzuko.Library` on the main realm and in a dedicated worker. An `AudioWorklet` processor realm does not have them. With the feature off, the names are absent. `dlopen` checks the ffi permission in Permissions. The feature does not enable `window`. The names are not on `globalThis`. `Yuzuko.dlopen` is not a constructor. `new Yuzuko.Library()` throws `TypeError` with `Illegal constructor`.

`Yuzuko.dlopen(path, symbols)` has length 2. Fewer arguments throw `TypeError` with `Not enough arguments`. Extra arguments are ignored. `path` must be a non-empty string primitive. The call does not use `ToString`. Any other type throws `TypeError` with `The path must be a string.` An empty string throws `TypeError` with `The path must not be empty.` A path that contains a null character throws `TypeError` with `The path must not contain a null character.` `symbols` must be an object. `null`, `undefined`, and any other non-object throw `TypeError` with `The symbols must be an object.` Reading a property that throws throws that exception. A failure to read the object throws `TypeError` with `The symbols could not be read.`

Each own enumerable string property is one symbol. Names inherited from the prototype are ignored, and so are symbol keys. The property name is the C name passed to the loader. A name that is not a string throws `TypeError` with `The symbol name must be a string.` An empty name throws `TypeError` with `The symbol name must not be empty.` A name that contains a null character throws `TypeError` with `The symbol name must not contain a null character.` More than 256 symbols throws `TypeError` with `There are too many symbols.` The property value must be an object and not an array. Any other value throws `TypeError` with `The symbol definition must be an object.`

`parameters` may be omitted, `null`, or `undefined`, and then the function takes no arguments. Otherwise it must be an array of at most 4 string primitives. An array longer than 4 is rejected before its elements are read. Each element is `"i32"`, `"f64"`, `"pointer"`, `"buffer"`, or `"cstring"`. `result` may be omitted, `null`, or `undefined`, and then the result is `void`. Otherwise it must be the string primitive `"void"`, `"i32"`, `"f64"`, `"pointer"`, or `"cstring"`. `"buffer"` is not a result. These strings do not use `ToString`. An `"f64"` parameter cannot be mixed with another parameter type, there are at most 2 `"f64"` parameters, and `result` is then `void` or `"f64"`. `"i32"`, `"pointer"`, `"buffer"`, and `"cstring"` are the integer class. They may be mixed with each other, there are at most 4, and `result` is then `void`, `"i32"`, `"pointer"`, or `"cstring"`. A `void`, `"i32"`, `"pointer"`, or `"cstring"` result with no parameters is allowed. Any other shape throws `TypeError` with `The function type is not supported.` These checks run before the library is opened.

The permission check runs after those symbol checks and before the library is opened. A path containing `/` or `\` uses the path rules in Permissions. A path with no separator is allowed only when `ffi` is granted as a whole. The call then blocks while the operating system loads the library and resolves every symbol. On Unix it is `dlopen` with `RTLD_NOW` and `RTLD_LOCAL`, then `dlsym` for each C name. A path that contains `/` or `\` is joined to the current directory when it is not already absolute, and that absolute path is passed to `dlopen`. A name with no separator is passed through and searched by the loader. The Mach-O leading underscore is not part of the C name. On Windows a path with no separator is `LoadLibraryW` of that name as UTF-16, so the loader searches. A path that contains `/` or `\` is joined to the current directory when it is not already absolute, including a drive-relative path such as `C:name`, and that absolute path is passed to `LoadLibraryExW` with `LOAD_WITH_ALTERED_SEARCH_PATH`. The loader opens that file and does not search for another file of the same relative name. `GetProcAddress` resolves each name. On any other operating system the load fails. If the load fails, or any symbol is missing, `dlopen` throws `Error` with `The library could not be opened.` and does not return a library. A partial library is not left open.

The returned `Library` has `symbols`, one object. Each read returns that same object. Its own properties are host functions, named by the C names. A function's length is its parameter count. Calling one is not a construct call. Fewer arguments than the length throw `TypeError` with `Not enough arguments`. Extra arguments are ignored and are not converted. An `"i32"` argument uses `ToInt32`, so `valueOf` runs. An `"f64"` argument uses `ToNumber`. If `ToInt32` or `ToNumber` throws, that exception propagates. A `"pointer"` argument is `null`, a bigint primitive, or a number primitive. `null` and `0n` are the null pointer. A bigint must be an unsigned value that fits in a pointer. A number must be an integer from 0 through `Number.MAX_SAFE_INTEGER` that fits in a pointer. The call does not use `ToBigInt` or `ToNumber`, so a boxed bigint, a number object, and `undefined` are rejected. A `"buffer"` argument is a `BufferSource`: an `ArrayBuffer`, a `SharedArrayBuffer`, or a view, including a view with a byte offset. A detached buffer throws `TypeError` with `The buffer is detached.` Any other value throws `TypeError` with `The data must be a BufferSource.` A buffer longer than 2147483647 bytes throws `The buffer is too large.` The pointer passed to C addresses those bytes. A zero-length buffer may have a null data pointer, and that pointer is what is passed. The length is not implied; the caller passes it as a separate `"i32"` when the C function needs it. A `"cstring"` argument is a string primitive. The call does not use `ToString`. Any other value throws `TypeError` with `The string must be a string.` A string containing a null character throws `TypeError` with `The string must not contain a null character.` The pointer passed to C addresses that string as UTF-8 with a trailing NUL. A conversion that fails without an exception throws `TypeError` with `The argument could not be converted.`

A buffer or C-string pointer is valid only for that synchronous call. The C function must not retain it and must not call back into JavaScript. Bytes written into a buffer are visible in the JavaScript buffer when the call returns. A `void` result is `undefined`. An `"i32"` or `"f64"` result is a number. An `"i32"` result is the low 32 bits, read as a signed integer. A `"pointer"` result is a bigint. The null pointer is `0n`, not JavaScript `null`. A `"cstring"` result reads bytes until NUL, at most 1048576 bytes, and returns a string. Invalid UTF-8 becomes U+FFFD. A null pointer returns JavaScript `null`. If no NUL appears within 1048576 bytes, the call throws `Error` with `The result is not a C string.` An invalid native pointer has undefined behavior and may crash the process.

There is no `libffi`. An `"f64"` call uses one homogeneous `extern "C"` function of that shape: `() -> void`, `() -> f64`, `(f64) -> f64`, `(f64, f64) -> f64`, `(f64) -> void`, or `(f64, f64) -> void`. An integer-class call passes each argument in a pointer-sized integer register and passes only the declared arguments. An `"i32"` argument is zero-extended into that register. On the five targets in Platforms, a callee compiled for `int` reads the low 32 bits, and an `int` result is those low 32 bits of the return register. Every combination of up to 4 integer-class parameters with a `void`, `"i32"`, `"pointer"`, or `"cstring"` result is supported, including a result with no parameters.

`close()` has length 0. It unloads the library. On Unix that is `dlclose`. On Windows it is `FreeLibrary`. If the operating system refuses to unload, the library still stays closed to JavaScript. A second `close` throws `Error` with `The library is closed.` A call after `close` throws `Error` with `The library is closed.` `symbols`, `close`, and a symbol call throw `TypeError` with `illegal invocation` when the receiver or the function is not the library's. Dropping the `Library` unloads it. The `Library` must stay reachable while a symbol function runs. An open library does not keep the process alive. Realm shutdown unloads every library that is still open.

## Modules

Every static import, dynamic `import()`, `import defer`, `import.defer()`, `import.source()`, and entry path goes through `oxc_resolver`, then, for TypeScript, through `oxc_transformer`. The loader does not invoke `tsc` or the oxc CLI. `import.meta.url` is the absolute `file:` URL of the source file that was resolved, including a `.ts` or `.mts` URL.

Resolution options:

- Conditions are `import` and `default`. The `types` and `require` conditions are not used, so a resolver result is never a `.d.ts` or a CommonJS entry chosen by `require`.
- Extensions searched are `.ts`, `.mts`, `.js`, `.mjs`, `.json`, and `.wasm`.
- `extensionAlias` maps a `.js` specifier to `.ts` then `.js`, and a `.mjs` specifier to `.mts` then `.mjs`. `import "./foo.js"` loads `foo.ts` when that file exists.
- `tsconfig.json` discovery, `extends`, project references, `baseUrl`, and `paths` are oxc_resolver's. `compilerOptions.target`, `module`, `jsx`, and `strict` do not change loading.
- A bare specifier resolves through `package.json` `"imports"` and `"exports"` when oxc_resolver finds a file. Nothing is downloaded. `node:` throws `TypeError`. A result whose module type is CommonJS, an addon, or a declaration file throws `TypeError`.
- JSON, text, and bytes modules load with `with { type: "json" }`, `with { type: "text" }`, and `with { type: "bytes" }`. A `.wasm` evaluation import is linked as described below.
- An evaluation import reads a file only when every resolved form is `.js`, `.mjs`, `.cjs`, `.ts`, `.mts`, or `.wasm`, or when every form is `.json` and the import uses `{ type: "json" }`. The forms are the path the loader resolved and the canonical path when the file or its parent exists. A symlink is included. A target with another extension is not read, and the import throws `TypeError` with `<path> must be imported with { type: "text" } or { type: "bytes" }`. That `<path>` is the path the importer named, not the canonical target of a symlink. `.d.ts` and `.d.mts` throw `TypeError` with `cannot execute declaration file <path>` and are not read. `{ type: "json" }` on a non-`.json` file still requires read and then parses that file as a script, except a `.wasm` file, which stays a WebAssembly module. An unrecognized `type` on a script file leaves it a script.

### WebAssembly modules

The loader loads `.wasm` as an ES module, in two forms: a direct import and `import source`.

A direct import instantiates the module and exposes its exports:

```js
import { add } from "./add.wasm";
```

`await import("./add.wasm")` does the same. The namespace follows the WebAssembly ES module integration. A function export is a JavaScript function. A memory export is a `WebAssembly.Memory`. A table export is a `WebAssembly.Table`. A global export is the value it holds.

`import defer * as ns from "./add.wasm"` compiles and links that module. `new WebAssembly.Instance`, and evaluation of the Wasm module's own imports, run on the first observation of `ns`.

Imports declared inside the Wasm module are specifiers. The loader resolves each one relative to the `.wasm` file with `oxc_resolver`, evaluates that module, and passes its exports as the import object. The target may be JavaScript, TypeScript, or another `.wasm` module. A missing export or a type mismatch fails instantiation and rejects the module graph.

A source-phase import compiles the bytes and does not instantiate them:

```js
import source mod from "./add.wasm";
// mod instanceof WebAssembly.Module
```

The Wasm module's own imports are not evaluated for a source-phase import. `WebAssembly.instantiate` is how that `Module` is instantiated later. oxc parses `import source` and leaves it in the graph.

A source-phase import of JavaScript or TypeScript returns a `ModuleSource`. That constructor is not a global. The object's prototype chain includes `%AbstractModuleSource%.prototype`, the same prototype `WebAssembly.Module` uses. The file is fetched and parsed. Its imports are not loaded or evaluated.

```js
import source worker from "./worker.ts";
const w = new Worker(worker);
```

`import.source("./worker.ts")` does the same. Repeated source-phase imports of one URL in one module-map generation return that same object. A `--watch-hmr` reload returns a new object for that URL when that module is re-evaluated, and returns the same object when it is not. `ModuleSource` is structured-cloneable: a clone in another realm is a `ModuleSource` for that URL. `import(moduleSource)` does not evaluate the source: V8 converts the specifier to a string before the host callback. `new Worker(moduleSource)` infers `{ type: "module" }`. `{ type: "classic" }` throws `TypeError`. A `WebAssembly.Module` is not a worker script. A source-phase import of a JSON, text, or bytes module throws `TypeError`.

The pinned `v8` must report the module request phase to the host resolver. Invalid Wasm bytes reject evaluation. Dedicated workers use this same loader.

### Text and bytes modules

`import value from "./file" with { type: "text" }` and `import(url, { with: { type: "text" } })` load any file as a synthetic module whose default export is a string. The bytes are decoded as UTF-8. An invalid sequence becomes U+FFFD. A leading byte order mark stays in the string as U+FEFF. The file stays raw source, so `.js`, `.ts`, `.json`, `.wasm`, and extension-less files are left unparsed.

`import value from "./file" with { type: "bytes" }` and `import(url, { with: { type: "bytes" } })` load any file as a synthetic module whose default export is a `Uint8Array` of the raw bytes. `value.buffer` is an immutable `ArrayBuffer`: `immutable` is true, `resizable` is false, and the buffer stays attached. `resize`, `transfer`, `transferToImmutable`, and a write through the view throw `TypeError`. An empty file is a zero-length view.

The `type` attribute is what selects the record. `file.wasm` or `file.json` with `{ type: "text" }` or `{ type: "bytes" }` is that synthetic module. A `.json` file imported without `{ type: "json" }` throws. `{ type: "json" }` on a file whose extension is not `.json` loads that file as JavaScript or TypeScript, except a `.wasm` file, which stays a WebAssembly module. An unrecognized `type` on JavaScript or TypeScript, such as `"css"` or `"javascript"`, leaves the module as a script. A `.txt` file, an extension-less file, and any other file that is not a JavaScript, TypeScript, JSON, or WebAssembly module needs `{ type: "text" }` or `{ type: "bytes" }`. The extension comparison is case-sensitive, so `.JSON` is not a `.json` module. A symlink is an evaluation import only when the lexical path and the canonical target are the same kind of module. Otherwise the file is not read, and the import throws `TypeError` with `<path> must be imported with { type: "text" } or { type: "bytes" }`. That `<path>` is the path the importer named, not the canonical target of a symlink. A sandboxed process requires read access before it reads a text, bytes, or json module, including `{ type: "json" }` on a file that is then parsed as a script. A missing grant throws `NotCapable` and the file is not read. That denial names the path the importer named. A JavaScript, TypeScript, or WebAssembly evaluation import is not a read check when every resolved form is that kind of file.

The module map key is the resolved URL, the module type, and a generation. JavaScript, TypeScript, and a Wasm evaluation import share one record. `"text"`, `"bytes"`, and `"json"` are separate records of the same URL. A failed load leaves its key empty, so a later import with the attribute can succeed, and a later import without the attribute fails again. The same URL, type, and generation reuse one module record, and a repeated bytes import in that generation is the same `Uint8Array`. `yuzuko run`, `yuzuko test`, `yuzuko repl`, and a dedicated worker stay on generation 0. `yuzuko run --watch-hmr` re-evaluates a module when its file changes, or when it statically imports a module that is re-evaluated, including `import source` and `import defer`. Those importers are new module records. A dependency whose file did not change, and that does not statically import a re-evaluated module, stays the record that already ran. `import.meta.url` and the script origin stay the canonical `file:` URL. Each re-evaluated specifier is compiled at the next generation. After that graph evaluates, module records, synthetic sources, and source-phase objects from earlier generations of those specifiers are dropped. A module that was not re-evaluated stays in the map, including one the new graph no longer imports. A compile or link failure drops only the new generation and leaves the previous graph in place. `--watch` starts a new isolate, and that isolate's module map dies with it. See CLI.

The string or `Uint8Array` is created when the module evaluates. `import defer` waits until the deferred namespace is observed. `import.defer(specifier, { with })` takes the same attributes. The only export is `default`, so a named import fails to link. `import source` of a text or bytes module throws `TypeError`. Dedicated workers use this loader.

`ArrayBuffer.prototype.immutable`, `transferToImmutable`, and `sliceToImmutable` are part of the realm. `immutable` is false on an ordinary buffer. `transferToImmutable` detaches its receiver and returns an immutable buffer. `sliceToImmutable` returns an immutable copy of a byte range and leaves its receiver attached.

### Deferred evaluation

`import defer` fetches and links the module with the rest of the graph. The module body runs when code first observes the deferred namespace. The static form is `import defer * as ns from "./mod.ts"`. `import defer from "./mod.ts"` is an ordinary default import whose local name is `defer`. `import defer { x } from "./mod.ts"` and `import defer name from "./mod.ts"` are syntax errors.

A string key other than `"then"` observes the namespace through `[[Get]]`, `[[GetOwnProperty]]`, `[[HasProperty]]`, `[[DefineOwnProperty]]`, and `[[Delete]]`. `[[OwnPropertyKeys]]` observes it for every key, so `Object.keys`, `Object.getOwnPropertySymbols`, `Object.isFrozen`, and `Object.isSealed` evaluate the module. Reading `"then"` or a symbol, including `Symbol.toStringTag`, leaves the module unevaluated. `ns[Symbol.toStringTag]` is `"Deferred Module"` before and after evaluation. `Object.prototype.toString` reports `[object Deferred Module]`.

When the module does not export `then`, `ns.then` is `undefined`. When it does export `then`, that binding stays on the deferred namespace. Reading it before evaluation throws `ReferenceError` and leaves the module unevaluated. `"then" in ns` is true and leaves the module unevaluated. After another observation evaluates the module, the read returns the export.

A deferred namespace and the ordinary namespace of the same module are different objects. Repeated `import defer` of one module share one deferred namespace. An ordinary import evaluates the module once, and the deferred namespace then reads that same module state.

A module with top-level await, and the modules its evaluation needs, runs while the importer is evaluated. A synchronous module reached only through `import defer` stays unevaluated until observation. `import.defer(specifier)` fulfills with the deferred namespace after asynchronous dependencies settle, and rejects when one of those dependencies throws. A parse error, a link error, or a missing module fails the importer immediately. An evaluation error is thrown by the observation, and a later observation throws that same error.

JSON still requires `with { type: "json" }`. The text is parsed when the deferred namespace is observed. Text and bytes still require `with { type: "text" }` and `with { type: "bytes" }`. The string or `Uint8Array` is created when that namespace is observed. `import.defer(specifier, { with })` accepts the same import attributes as `import()`. Dedicated workers use this same loader.

TypeScript source (`.ts`, `.mts`) is parsed with oxc and passed through oxc's TypeScript transform before V8 compiles the module. The transform erases types, interfaces, type aliases, type-only imports and exports, assertions, `satisfies`, and generics. It also rewrites runtime TypeScript syntax that erasure cannot delete: `enum`, `namespace`, and parameter properties. JavaScript syntax is not downleveled. The JSX transform is off, and `.tsx` fails to load.

A type-only import is gone before V8 resolves specifiers, so its target is not fetched. Import specifiers that remain are left unchanged. oxc does not rewrite `.ts` extensions to `.js` in the output. The host resolver sees the original specifier.

Erasure is cached in memory for the process, keyed by path, modified time, and length. The loader does not write a `.js` file next to the source. oxc's codegen source map is attached to the V8 script origin, so an exception stack uses the TypeScript path and line.

Parse and transform failures reject module evaluation with the source path and span. Dynamic `import()` and workers use this same loader.

Image decoders are pure Rust. TLS uses rustls. HTTP/1.1 and HTTP/2 use hyper. HTTP/3 uses quinn and h3. `https:` offers ALPN `h2` and `http/1.1`. `http:` stays HTTP/1.1. A later request to an `https` origin uses HTTP/3 after an `Alt-Svc` `h3` advertisement when that alternative's host and port are granted. A denied alternative is not contacted. Versions are pinned in `Cargo.lock`. The oxc crates used for resolution and erasure stay on one version. A `v8` upgrade, and an oxc upgrade, are each their own change.

## CLI

```text
yuzuko run <entry.js|entry.ts> [arg...]
yuzuko run --watch [--no-clear-screen] <entry.js|entry.ts> [arg...]
yuzuko run --watch-hmr [--no-clear-screen] <entry.js|entry.ts> [arg...]
yuzuko test [<path>...] [--filter <substring>]
yuzuko package <entry.js|entry.ts> [--config <file>] [--output <path>]
yuzuko repl
```

Permission flags, before the entry: `-A`, `--allow-all`, `--allow-read[=<path>...]` (`-R`), `--allow-write[=<path>...]` (`-W`), `--allow-net[=<host>...]` (`-N`), `--allow-env[=<name>...]` (`-E`), `--allow-run[=<command>...]`, `--allow-ffi[=<path>...]`, and the matching `--deny-*` flags. `--no-prompt` skips the question. The rules are in Permissions.

`yuzuko` with no command starts the same session as `yuzuko repl`. `console.log` prints. `Yuzuko` is present. `Yuzuko.test` is absent. A session that never constructs a window opens none. `yuzuko help`, `yuzuko --help`, and `yuzuko -h` print usage and do not start a session.

`yuzuko run <entry> [arg...]` evaluates the entry module. Tokens after the entry become `Yuzuko.args`, including a token that starts with `-`. A token that starts with `-` before the entry is an unknown flag and the process exits 2, except `--watch`, `--watch-hmr`, `--no-clear-screen`, and the permission flags in Permissions. The policy is installed before the entry runs. When stdin is a terminal and `--no-prompt` is absent, a missing grant asks. Otherwise the call throws `NotCapable`. `yuzuko repl` accepts only permission flags. Any other argument prints `yuzuko repl` and exits 2. The session does not ask and does not read `yuzuko.json`. `--` before the entry consumes that separator and takes the next token as the entry, including an entry whose name starts with `-`. One `--` placed immediately after the entry is discarded and is not an argument. `yuzuko run game.ts --fullscreen` records `["--fullscreen"]`. `yuzuko run game.ts -- --fullscreen` records the same array. `yuzuko run game.ts -- --` records `["--"]`. `yuzuko run -- script.ts -- x` records `["x"]`. `yuzuko run game.ts --watch` records `["--watch"]` and does not watch. `yuzuko run` with no entry, including `yuzuko run --`, exits 2.

`yuzuko run --watch <entry> [arg...]` evaluates the entry and, when a watched file changes, starts a new isolate and a new realm. `yuzuko run --watch-hmr <entry> [arg...]` keeps the isolate and the realm and evaluates the next module graph there. The two flags cannot be combined. `--no-clear-screen` is valid only with one of them. Combining the flags, or passing `--no-clear-screen` alone, exits 2. A missing entry exits 2.

The watcher notes the entry and every module file the loader compiles, including a file whose compile fails. It does not walk `node_modules`. A new import is noticed when the file that imports it changes. A change waits for 200 ms of quiet. The event loop polls about every 50 ms while a watch flag is set. When stderr is a terminal, the screen clears before the next run unless `--no-clear-screen` is set. The sequence is `ESC [ H ESC [ 2 J ESC [ 3 J`.

An idle event loop does not exit the process. `--watch` prints `Watcher Process finished. Restarting on file change...` and waits outside that isolate. `--watch-hmr` waits in the same realm. The next quiet change starts the next run. A compile or evaluation error is printed. `--watch` then prints `Watcher Process failed. Restarting on file change...` and waits. `--watch-hmr` prints `HMR failed to reload <path>.` When the new graph fails to compile or link, the previous graph keeps running. When evaluation of a re-evaluated module throws, listeners, timers, and animation callbacks from the modules being re-evaluated are already removed, and a dedicated worker or GPU device those modules created is already gone. A window or `AudioContext` whose creating module was not re-evaluated stays, including audio nodes the failed evaluation added to a context that stayed. That new generation stays. `Yuzuko.exit` ends the session with that status. Ctrl+C ends the process the same way as `yuzuko run` without a watch flag.

Status lines go to stderr. `--watch` prints `Watcher Process started.` and `Watcher Restarting! File change detected: <path>`. `--watch-hmr` prints `HMR Process started.` and, after a successful reload, `HMR Reloaded <path>.`

Own properties of `globalThis` survive `--watch-hmr`. A module is re-evaluated when its file changes or when it statically imports a re-evaluated module. A module that is not re-evaluated stays, and so does a `Yuzuko.Window` or `AudioContext` it created: the same object, its listeners, its animation callbacks, pointer lock, queued input, its accessible tree, and playback on that context. Listeners, timers, and animation callbacks registered by a re-evaluated module are removed before it runs again, including ones on a window that stays. A dedicated worker or GPU device created by a re-evaluated module is terminated. One created by a module that stays is left. Loaded fonts are cleared only when every previously evaluated module is re-evaluated. Files, sockets, signals, child processes, and host jobs are not tracked per module, so a hot reload leaves them in place, including ones a re-evaluated module opened. `--watch` drops every window and audio context by leaving the realm.

A window whose creating module is not re-evaluated keeps its size, position, fullscreen state, pointer lock, queued input, animation callbacks from that module, and accessible tree. Calling `attachAccessibleRoot` again on that window throws `AlreadyAttached`. A running `AudioContext` from that module keeps its nodes, its buffers, its output device, and its clock. An `OfflineAudioContext` is left as it is. An `AudioWorklet` processor realm stays with its context. A module that imports the changed file is re-evaluated with it. The module that creates the window stays unevaluated when it does not import the changed file and the changed file is the one that imports it. A single file that calls `new Yuzuko.Window()` runs that call again when that file changes, because the creating module is the module that changed.

After the new graph is evaluated, a window or realtime `AudioContext` created by a re-evaluated module is closed when this evaluation did not create a replacement and it is not reachable from `globalThis` through own enumerable data properties of objects and arrays. That walk does not call getters and does not read values a function captured. At most 4096 objects are visited, and an object with more than 4096 own properties ends the walk; nothing is closed in that case. `globalThis.game = { win }` keeps `win`. A window or context created by a module that was not re-evaluated stays even when that walk cannot see the module binding. A source `start()`ed by a re-evaluated module plays together with sources already connected in a context that stayed. `getContext("2d")` on a surface whose window stayed is the same context. `getContext("webgpu")` is the same context. A device created by a re-evaluated module is lost, and `configure` takes a new device. A device created by a module that stayed is still that device. A changed module that is reached only by dynamic `import()` is re-evaluated, and the namespace from the previous `import()` is not updated. A failed first evaluation drops windows and realtime contexts from that attempt except ones left reachable from `globalThis`, because that generation's module records are discarded.

`--watch-hmr` re-evaluates modules. It does not patch source that is already running. There is no `import.meta.hot`.

The prompt is `> `. Each complete chunk is evaluated, its completion value is printed with the console inspector, and queued microtasks and already-due macrotasks run before the next prompt. A string completion is quoted. A timer that schedules itself again with delay 0 runs once for that chunk and does not keep the prompt waiting. `1 + 1` prints `2`. A TypeScript annotation is erased before evaluation, so `const labeled: number = 3` then `labeled` prints `3`. Top-level `await` prints the resolved value. `await import()` of a relative `.ts` file loads it the same way `yuzuko run` loads a module, from the current directory. A thrown exception is reported and the next chunk still runs. EOF on an empty line exits 0. `Yuzuko.exit` ends the session with that status. The completion value and an exception stack are not printed. A timer can call it while the prompt is waiting, except during a Windows pipe read, which blocks until the next line. See Process.

A completion is colored when stdout is a terminal. A non-empty `FORCE_COLOR` colors it when stdout is not a terminal. A non-empty `NO_COLOR` disables color when `FORCE_COLOR` is empty or absent. `console` prints uncolored text. A number, a bigint, and a boolean are yellow. `undefined` and an empty array hole are grey. `null` is bold. A string and a symbol are green. A date is magenta. A Temporal object is cyan. A regular expression is red. A function, `<ref *1>`, `[Circular *1]`, `[Getter]`, `[Setter]`, `[Getter/Setter]`, a collapsed object such as `[Object]`, `<pending>`, `<rejected>`, `<items unknown>`, `(detached)`, and `[Uint8Contents]` are cyan. An identifier property name has no color. A syntax error and a thrown exception keep their text and are red.

An unclosed `(`, `{`, `[`, string, template literal, or block comment keeps the continuation prompt `... ` and is not evaluated. A trailing `.` that continues a member access does the same. A finished invalid chunk reports a syntax error, and the next chunk still runs.

On a terminal, the line editor uses the Node.js readline emacs bindings. Left and Right, or Ctrl-B and Ctrl-F, move one character. Up and Down, or Ctrl-P and Ctrl-N, recall chunks submitted in this session. Ctrl-A and Home move to the start of the current line. Ctrl-E and End move to the end of that line. Ctrl-Left and Escape then B move one word left. Ctrl-Right and Escape then F move one word right. Backspace deletes the character on the left. Ctrl-D and Delete delete the character on the right, and Ctrl-D on an empty buffer ends the session. Ctrl-U deletes back to the start of the line. Ctrl-K deletes through the end of the line. Ctrl-W deletes the word on the left. Escape then D deletes the word on the right. Ctrl-Y inserts the text last removed by Ctrl-U or Ctrl-K. Ctrl-L clears the screen and redraws the buffer. History ends when the process exits. Tab completes names from this realm. `Ma` offers `Math`. `Math.` offers properties including `abs`. A binding created by an earlier chunk in the same session is offered. A name that does not exist is not invented. A pipe reads complete lines and treats EOF as the end of the session. While a Unix terminal or a Windows console waits for the next key, the event loop still runs. Timers, host tasks, and open windows keep receiving turns, so `requestAnimationFrame`, input, and drawing continue, and a key still interrupts that wait. A host job that has already finished runs before the editor blocks, and a job that finishes during the wait interrupts it. The Windows console runs with virtual terminal input, so the keys above arrive as the same sequences a Unix terminal sends. The same switch colors the input line. The cursor column counts the input characters and ignores color codes. A string or template is green. A number, a bigint, `true`, `false`, and `null` are yellow. A keyword is cyan. `undefined` and a comment are grey. `Infinity` and `NaN` are yellow. An identifier before `(` is intense blue. A regular expression is red. `from` is cyan only when a string literal follows it. A Unix pipe also runs the loop while it waits for the next line. A Windows pipe blocks until the next line arrives. REPL chunks are not ES modules. See `docs/deviations.md`.

## Tests

### `Yuzuko.test`

`Yuzuko.test` is installed only when the process is `yuzuko test`. `yuzuko run` does not have it.

```js
Yuzuko.test("addition", () => {
  if (1 + 1 !== 2) throw new Error("bad sum");
});

Yuzuko.test("async decode", async () => {
  const bitmap = await createImageBitmap(blob);
  if (bitmap.width !== 2) throw new Error("width");
});

Yuzuko.test({
  name: "macos window",
  ignore: Yuzuko.build.os !== "darwin",
  fn() {},
});

Yuzuko.test.ignore("later", () => {});
Yuzuko.test.only("focus this", () => {});
```

The call forms are `(fn)` when the function has a name, `(name, fn)`, `(name, options, fn)`, and `(options)`. `options` is `{ name, fn, ignore, only }`. `fn` may be async and receives a `TestContext`. `t.step(name, fn)` registers a nested step. A nested `Yuzuko.test` call throws. Registration happens while the module evaluates, before any test runs.

Discovery follows `*_test.js`, `*.test.js`, `*_test.ts`, and `*.test.ts`. The test runner loads those files through the same oxc resolver and TypeScript transform. Arguments are files or directories. `--filter` keeps tests whose names contain the substring. The run installs the permission policy described in Permissions and does not ask. A missing grant throws `NotCapable`. `--allow-all` grants every kind. `--allow-*` grants only the values it names. The runner does not apply `permissions` from `yuzuko.json`.

The runner evaluates one file at a time in one isolate, in registration order. A thrown exception or a rejected promise fails that test. Ignored tests are reported and do not fail the run. If any test sets `only`, the run executes only those tests and then exits 1, so a focused test cannot stay green. The summary line is `ok | <passed> passed | <failed> failed | <ignored> ignored`. Exit status is 0 when every executed test passes and none set `only`. It is 1 when a test fails or any test set `only`. `Yuzuko.exit` during evaluation or from a test function stops the run with that status, and the summary line is not printed.

There is no op or resource sanitizer. Those track a host-call layer this runtime does not have. The runner does fail a test that leaves a timer it started, or that produces an unhandled rejection after the test function settles.

`Yuzuko.build` is described in Process. `os` in the example above is `"darwin"`, `"linux"`, or `"windows"`.

`Yuzuko.__test` injects pointer, key, IME, wheel, focus, menu, tray, and gamepad input, and, when `accessibility` is enabled, assistive-technology actions. `yuzuko test` installs it only when `YUZUKO_TEST_INPUT=1`. Without that variable the property is absent. `yuzuko run` and `yuzuko repl` do not install it.

Use `Yuzuko.test` for behavior WPT does not cover: `Window`, input mapping, IME event order, present, the canvas renderer fallback, the CLI, and timer and microtask order.

### WPT

Web APIs are tested with [web-platform-tests](https://github.com/web-platform-tests/wpt), upstream, not with copies of those tests.

`tests/wpt/suite` is a git submodule pinned to one upstream commit. Upgrading the pin is its own change, separate from a feature change. `tests/wpt/expectations/` holds one JSON file per top-level suite.

`cargo test -p yuzuko --test wpt` executes the enrolled testharness tests in a fresh realm per file. The runner loads upstream `testharness.js` and reports each subtest. It runs `.any.js` variants and testharness documents that do not need a layout engine. A variant whose `promise_setup` rejects through `assert_implements_optional`, and whose subtests did not run, is omitted from the file result. Upstream `testharness.js` records that rejection as a harness error. Dedicated `.worker.js` files run in a worker. Files that need a DOM node, CSS layout, or a WebView stay in the expectation file as `{"ignore": "text"}`. `text` is the reason. A file the runner can execute may still skip on `linux`, `macos`, or `windows`, and each of those values is a reason. A file that passes on some runs and misses on others for the same platform is `flaky` instead of `ignore`. `flaky` uses the same shape. Suites that need the network (`fetch`, and any test that loads an HTTP resource) use the WPT server from that cargo test. `url`, `encoding`, and the other enrolled directories that do not load an HTTP resource run without that server.

Expectation leaves use these values:

| Value | Meaning |
| --- | --- |
| `true` | Every subtest is expected to pass |
| `false` | The whole file is expected to fail |
| `{"expectedFailures": ["name"]}` | Those subtests fail. The rest pass |
| `{"ignore": "text"}` | Skip the file on every platform. `text` is a non-empty reason. `YUZUKO_WPT_NO_IGNORE=1` runs it anyway |
| `{"ignore": {"linux": "text", "macos": "text"}}` | Skip where a key is present. Keys are `linux`, `macos`, and `windows`. Each value is that platform's non-empty reason. Every other platform expects a pass |
| `{"expectedFailures": ["name"], "ignore": {"windows": "text"}}` | Skip on `windows`. On the other platforms, those subtests fail and the rest pass |
| `{"fail": true, "ignore": {"linux": "text"}}` | Skip on `linux`. On the other platforms, the whole file is expected to fail |
| `{"flaky": "text"}` | Run the file on every platform, up to three times, until the expectation matches. `text` is a non-empty reason |
| `{"expectedFailures": ["name"], "flaky": {"macos": "text"}}` | On `macos`, retry until the expectation matches, at most three times. On the other platforms, run once. Those subtests fail and the rest pass |

`ignore` and `flaky` are the reason. A string covers every platform. An object names platforms, and each value is that platform's reason. When `linux`, `macos`, and `windows` all carry the same reason, the entry is that string. A file this runner always skips uses `{"ignore": "text"}`. A platform `ignore` is only for a file the runner can execute, and the runner rejects it on a file that it always skips. `flaky` is also only for a file the runner can execute. The same platform is not both `ignore` and `flaky`. An all-platform `ignore` does not combine with `flaky`, and an all-platform `flaky` does not combine with `ignore`. On a flaky platform the runner tries the file up to three times and keeps the first attempt that matches the expectation. If none match, the last attempt fails the cargo test. `YUZUKO_WPT_NO_IGNORE=1` runs ignored files and does not disable `flaky`. The cargo test fails when a result differs from the expectation, including a subtest that starts passing. `YUZUKO_WPT_UPDATE=1 cargo test -p yuzuko --test wpt` rewrites the expectation files to the results just observed. It runs each file once. It keeps an all-platform reason when the runner still skips the file. It keeps a platform `ignore` for a platform that did not run. It keeps `flaky`. `YUZUKO_WPT_NO_IGNORE=1` together with update records this host's result and drops the ignore that covered this host. The next run then passes. Update expectations in the same change that changes the results.

The first runner is single-process and sequential, because V8 and winit stay on the main thread. Splitting suites across processes, one top-level directory each, can come later.

A change that adds or changes a web API enrolls the upstream directories for that API and runs them. Tests in those directories that need an absent host stay ignored in expectations. The `ignore` value says why.

The enrolled upstream directories are `url`, `encoding`, `hr-time`, `html/webappapis/atob`, `html/webappapis/timers`, `FileAPI`, `dom/events`, `wasm/jsapi`, `console`, constructor tests under `pointerevents` and `uievents` that do not need an element, `html/canvas` image and `createImageBitmap` tests that operate on blobs (plus the image fixtures those tests use), `html/canvas/offscreen` and the 2D context tests that do not need a displayed HTML canvas (run on the CPU renderer), `webgpu`, `fetch`, `streams`, `compression`, `urlpattern`, `WebCryptoAPI`, `mimesniff`, `wasm/webapi`, `css/geometry`, `gamepad`, `clipboard-apis`, the `DataTransfer` string-store tests under `html/editing/dnd/datastore`, `screen-wake-lock`, `css/css-font-loading`, dedicated-worker tests that do not need a document, and `webaudio`.

`requestidlecallback` is enrolled with the main-global idle callbacks. `eventsource` and `websockets` are enrolled with those clients. `webcodecs` is enrolled with `VideoDecoder`, `AudioDecoder`, `VideoFrame`, `AudioData`, and `ImageDecoder`. The JPEG XL `ImageDecoder` documents are enrolled with that decoder. `dom/abort` is enrolled with `AbortSignal`. `html/webappapis/microtask-queuing` and `html/webappapis/structured-clone` are enrolled with `queueMicrotask` and `structuredClone`. `imagebitmap-renderingcontext` is enrolled with `ImageBitmapRenderingContext`. Files that need a document, a frame, or `requestAnimationFrame` on `globalThis` stay ignored or fail as recorded.

Pixel comparisons for Canvas 2D use the CPU renderer. Unorm8 sRGB pixels that did not cross a color-space boundary match exactly. A conversion from that output into another color space may differ by one unorm8 code point. `putImageData` and `ImageBitmap` float16 samples may differ by one float16 ulp. Where WPT has no reference, a `Yuzuko.test` golden image covers the case. The GPU renderer has a smoke test that one frame reaches a surface. Test both `YUZUKO_CANVAS=cpu` and the `"cpu"` fallback when the GPU is unavailable. WebGPU tests may skip when `YUZUKO_SKIP_GPU=1` and no GPU is available. A skip is not a failure.

Event order, the key map, and the IME state machine are `Yuzuko.test` tests. Decoders also have golden files, corrupt input, and limit checks beside the WPT cases.

## Packaging

`yuzuko package` produces an application that starts from a double click. The bundle contains the `yuzuko` executable that ran the command, the entry module graph, and the assets listed in the config. That executable keeps the Cargo features it was built with. `yuzuko package` does not rebuild it. A packager built with `--no-default-features` is the JavaScript runtime from Build features. `--features` selects the subset. The default packager includes every feature. The targets are the five triples in Platforms. The macOS output is a `.app`. Windows and Linux outputs are directories. There is no WebView and no `backend` choice. The `Contents/MacOS` binary and opening the `.app` both run the packaged entry. A bundled executable always runs that entry. Arguments other than a `-psn_` token become `Yuzuko.args`, and the executable does not dispatch `run`, `test`, `package`, or `repl`. `codesign --verify` succeeds for an ad-hoc signature. `import.meta.url` is a `file:` URL under `Contents/Resources/app/`. A listed asset outside the entry directory is fetched from that tree, and a `file:` URL outside it fails. An omitted window title is the config `name`. The launch directory stays the caller's current directory. Windows and Linux directories from the same packager store the AppUserModelID, the `.desktop` id, and the icon bytes. The Windows executable in a bundle is marked as a GUI-subsystem image, so a double click opens no console window. Standard handles a parent passes in still receive output. A Windows bundle sets that AppUserModelID for the process before its first window and uses `AppIcon.ico` for the window and taskbar icon. A Linux bundle sets the X11 `WM_CLASS` and the Wayland `app_id` to the identifier, uses the widest PNG under `icons/` as the window icon, and its `.desktop` entry names the identifier as `StartupWMClass`.

The module graph follows static imports and exports, including `import defer` and `import source`. Type-only imports stay unloaded. `import()`, `import.defer()`, and `import.source()` are followed when the argument reduces to one specifier and that specifier resolves to a file. The specifier may be a string literal, a template literal with no substitution, or those strings joined by `+`. It may also be `import.meta.resolve` of such a specifier. A second argument is part of that form only when it is `import.meta.url`. It may also be `new URL(specifier, import.meta.url)`, or that expression's `.href` or `.toString()`. Parentheses and TypeScript `as`, `satisfies`, angle assertions, and non-null assertions wrap the same forms. A dynamic specifier that fails to resolve stays out of the bundle, so a missing file, a `node:` specifier, or a remote URL does not fail `yuzuko package`. A computed argument, a template substitution, a binding, and a `Worker` URL stay out. A JavaScript `import source` is a graph edge, so `new Worker(moduleSource)` from that import packages the worker module and the static imports of that file. `.wasm` and `.json` files in the graph are copied as bytes. Imports written inside those files are followed only from a parsed JavaScript or TypeScript module. A static import, a re-export, or a concrete dynamic import whose options object literal says `type: "text"` or `type: "bytes"` copies that file and leaves its source unparsed. Another edge that imports the same file as JavaScript or TypeScript parses it.

The config file is `yuzuko.json` or `yuzuko.jsonc`. `yuzuko.jsonc` is JSON with `//` and `/* */` comments and with trailing commas. `yuzuko.json` is strict JSON. Discovery starts at the entry file's directory and walks toward the root. The nearest directory that contains either file wins. Both names in that directory is an error. The entry is the path argument. `yuzuko package` with no path fails before anything is written. `--config` names the file and skips the walk. `--output` replaces the output path for the host OS. A command-line value wins over the file.

Unknown keys are errors. There is no `exports` key. Paths are relative to the config file and must stay inside that directory.

```jsonc
{
  // Display name. The default window title when `title` is omitted.
  "name": "My Game",
  "version": "1.0.0",
  "identifier": "com.example.mygame",
  "icons": {
    "macos": "./icons/app.icns",
    "windows": "./icons/app.ico",
    "linux": "./icons/app.png"
  },
  "assets": ["./assets/**"],
  "output": {
    "macos": "./dist/MyGame.app",
    "windows": "./dist/MyGame",
    "linux": "./dist/my-game"
  },
  "macos": {
    "codesignIdentity": "-"
  },
  "permissions": {
    "read": ["./assets"],
    "net": ["updates.example.com"],
    "env": false
  }
}
```

| Field | Meaning |
| --- | --- |
| `name` | Display name. Used as the default `Window` title, the macOS menu-bar name, and the bundle name. When omitted, the config directory's name is used |
| `version` | Stored in the bundle and compared by `autoUpdate`. Exposed as `Yuzuko.appVersion`. Dot-separated decimal integers from 0 through 2^64−1, at most 32 components, each at most 20 digits. A missing trailing component is 0, so `1.0` equals `1.0.0`. A missing version is `"0.0.0"`. Any other form fails `yuzuko package` before anything is written |
| `identifier` | Reverse-DNS id. macOS `CFBundleIdentifier`, the Windows AppUserModelID, and the Linux `.desktop` id. When omitted, `com.yuzuko.<slug>` from `name`. At least two labels. Each label starts with an ASCII letter and then contains letters, digits, or `-` |
| `icons.macos` | An `.icns` path, or an array of `{ "path", "size" }` PNGs assembled at package time. A missing file is an error. No entry means the bundle has no custom icon |
| `icons.windows` | An `.ico` path. PNGs are not assembled. It becomes the executable's icon resource, which Explorer, taskbar pins, and shortcuts show, and is copied as `AppIcon.ico` for the window icon. A file that is not a valid icon directory fails `yuzuko package` |
| `icons.linux` | A `.png` path, or the same PNG array as macOS |
| `assets` | Globs copied into the bundle, relative to the config file. The module graph is included without being listed. Paths that escape the config directory are errors |
| `output.macos` | A path ending in `.app` |
| `output.windows` | A directory path. `.msi` is not produced |
| `output.linux` | A directory path. `.deb`, `.rpm`, and `.AppImage` are not produced |
| `macos.codesignIdentity` | Passed to `codesign`. `"-"` or omission is an ad-hoc signature so the `.app` opens from Finder on this Mac. A named identity that `codesign` rejects fails the command |
| `permissions` | `read`, `write`, `net`, `env`, `run`, and `ffi`. Each value is `true`, `false`, or an array of strings. `true` allows the kind. `false` denies it. An array allows those values. An omitted name is denied when the packaged application launches. The key itself may be omitted, and the launch then allows every check. Relative paths are resolved against the bundle `app/` directory. An unknown name, or a value that cannot be stored, fails `yuzuko package` before anything is written. The object is copied into `yuzuko.bundle.json` |

An output path whose extension is `.dmg`, `.msi`, `.deb`, `.rpm`, or `.AppImage` fails the command. Those formats are not produced.

Inside the `.app`, the entry and the assets keep their paths relative to the config file, under `Contents/Resources/app/`. `import.meta.url` and `fetch` of a `file:` URL refer to that tree. The process current directory stays the directory from which the user launched the app.

Window position, size, `decorations`, `transparent`, and the other `Yuzuko.Window` options stay in the script. The config does not open a window. `yuzuko run` reads the same file to fill an omitted window `title` from `name` and to install `permissions`. A relative path in that object is resolved against the config directory.

There is no `backend` key. There is no `deepLinks` key. There is no `errorReporting` key. There is no `release` key. A bad identifier, a missing icon, an unknown key, an `exports` key, and both config names in one directory fail before anything is written.

## Automatic updates

`Yuzuko.appVersion` and `Yuzuko.autoUpdate` are installed on the main global. They are absent in a dedicated worker. `appVersion` is the packaged manifest `version` captured when the realm starts, or `null` when the process is not a packaged application or that version cannot be read. Assigning to the property does not change the version `autoUpdate` compares. Nothing is fetched while `yuzuko package` runs, and nothing is fetched at process start. There is no `apply()`, and the running process is not replaced.

`autoUpdate(options)` returns a promise. The promise is the first check. It resolves to `undefined`. When the process is not packaged, the promise resolves without contacting a host and without calling `onUpdateReady`. This includes `yuzuko run`, `yuzuko repl`, and `yuzuko test`. Options are still validated.

`options` may be omitted. A present argument that is not an object, including a function or an array, throws `TypeError` `Yuzuko.autoUpdate expects an options object.` `url`, when present and not `undefined`, is a string primitive or a `URL` instance. A `URL` is read through `href`, which must be a string primitive. The text must be an absolute `http:` or `https:` URL with a host. Any other value throws `TypeError` `url must be an absolute http or https URL.` This check runs before the promise is returned, including when the process is not packaged. An omitted `url` on a packaged application rejects the promise with `InvalidStateError` `There is no update feed.` and does not open a connection. An omitted `url` when the process is not packaged still resolves without contacting a host. `publicKey`, when present and not `undefined`, must be a string primitive. The string is standard base64, with padding, of a 32-byte Ed25519 public key that is not a low-order point. Any other value throws `TypeError` `publicKey must be standard base64 of a 32-byte Ed25519 public key.` This check runs before the promise is returned, including when the process is not packaged. An omitted `publicKey` on a packaged application rejects the promise with `InvalidStateError` `There is no update trust anchor.` after the missing-feed check, and does not open a connection. An omitted `publicKey` when the process is not packaged still resolves without contacting a host. `onUpdateReady`, when present and not `undefined`, must be a function, or the call throws `TypeError` `onUpdateReady must be a function.` `interval`, when present and not `undefined`, must be a finite number from 1 through 2147483647. The fractional part is truncated toward zero. Any other value throws `TypeError` `The update interval must be a finite number of milliseconds from 1 through 2147483647.` Other fields are ignored. Extra arguments are ignored. A getter that throws rejects the call with that exception.

`url` is the feed address for that call. A call that omits `url` does not contact a default host. `autoUpdate` reads `{url}/feed.json`, inserting a slash before `feed.json` when `url` has no trailing slash. A query or fragment on `url` is not sent. Userinfo is not sent. Redirects are not followed. The address is not stored in the bundle. A later version of the application passes its own `url`.

The feed document is JSON. Unknown fields are ignored.

```json
{
  "version": "1.2.0",
  "payload": "1.2.0.yuzuko",
  "signature": "<standard base64 of the 64-byte signature>"
}
```

`version` is a string in the form in the config table. `payload` is a relative path under `url`: no scheme, no leading slash, no empty, `.`, or `..` segment, no query, and no backslash. Each path is at most 1024 bytes. `signature` is standard base64, with padding, of the 64-byte Ed25519 signature of the exact payload bytes. A missing `signature`, a signature that is not that encoding, or a payload path that is not relative rejects the call and stages nothing.

`publicKey` is the trust anchor for that call. The feed cannot supply a key. The key that verifies a payload is written as 32 raw bytes to `Updates/public-key`, beside the payload and the signature. The next launch reads that file. It does not read a key from the config, from the feed, or from a file named `yuzuko.update-key`. A config that contains `release` fails `yuzuko package` before anything is written, because that name is not a field. A later version of the application, once its tree is applied, passes its own `publicKey`. That is how the trust anchor changes.

Newer means the feed version is strictly greater than the manifest `version` under the numeric rules in the config table. `1.10` is greater than `1.9`. Leading zeros do not change a component's value. When the feed version is equal or older, the promise resolves and `onUpdateReady` is not called. When it is strictly greater, the payload is downloaded and staged in the same call. `onUpdateReady(version)` then runs with the feed version, before the promise resolves. A throw from that callback rejects the promise. The stage stays.

`interval` is the delay in milliseconds before the next check. Omitted, the call checks once. Present, the first check runs immediately, and after that check succeeds another runs when the interval elapses. The promise represents only the first check. A later check that stages a payload calls the same `onUpdateReady`. A later failure does not reject the settled promise and does not call `onUpdateReady`. The next interval still runs. A throw from a later `onUpdateReady` is reported with `reportError`, and the interval continues. A throw from the first `onUpdateReady` does not start the interval. A later `autoUpdate` call cancels the previous interval. An in-flight check still settles its own promise. Only the latest call's interval continues, and only that call's `onUpdateReady` runs. A payload already staged is not downloaded again when the stored signature is the feed signature, the stored public key is the key passed to this call, and the payload file is present. That check does not call `onUpdateReady` again.

The response must be HTTP 200. `Transfer-Encoding: chunked` is a failure. When `Content-Length` is present, end of stream before that many bytes is a truncated body. Without `Content-Length`, the body ends when the connection closes. A feed document larger than 1 MiB, or a payload larger than 512 MiB, is a failure. A response that does not finish within 30 seconds is a failure. `http:` and `https:` are both fetched. `https:` uses rustls and the webpki root set.

The signature is verified with the `publicKey` passed to this call before anything is staged. The payload is this framing. Its version line must be the same string as the feed `version` and must be strictly greater than the manifest version.

```text
YUZUKO1
<version>
<entry>
<count>
```

Then, for each of the `count` files, a `/`-separated relative path, a decimal byte length, and exactly that many bytes. `count` is at most 100000. The entry path must name one of the files. Paths follow the same rules as the feed's `payload`. There is no trailing byte. Duplicate paths are rejected. A payload that does not verify, or that does not meet this framing, is not staged.

A verified payload is written as `Updates/payload` (the exact bytes), `Updates/signature` (the raw 64-byte signature), and `Updates/public-key` (the raw 32-byte key), under `Contents/Resources` on macOS and next to the manifest in a directory bundle. A failed check does not create or replace those files and does not change `app/`.

The next launch of that same packaged executable applies a staged update before it reads the entry. It reads `Updates/public-key`, verifies the staged bytes with that key, and requires the payload version to be strictly greater than the manifest version. It then replaces the whole `app/` tree, sets the manifest `version` and `entry`, and deletes the stage, including the key. It does not replace the executable, `Info.plist`, or icons. The launch that called `autoUpdate` keeps running the entry it already loaded. A feed that is not newer does not replace the entry. A bad or missing signature, a transport failure, or a truncated body does not. When apply fails, including when the staged key is missing or not a usable Ed25519 public key, the stage is deleted and that launch runs the previous entry. The script is not told about that apply failure.

| Failure | Exception | Message |
| --- | --- | --- |
| Packaged call omits `url` | `InvalidStateError` | There is no update feed. |
| Packaged call omits `publicKey` | `InvalidStateError` | There is no update trust anchor. |
| Manifest version is not comparable | `InvalidStateError` | The packaged version cannot be compared. |
| Feed document, version, payload path, or signature encoding | `InvalidStateError` | The update feed is not valid. |
| Signature does not verify | `InvalidStateError` | The update signature is not valid. |
| Payload framing does not match | `InvalidStateError` | The update payload is not valid. |
| Status is not 200, the connection fails, the body is chunked, a limit is exceeded, or the response times out | `NetworkError` | The update could not be downloaded. |
| The connection closes before `Content-Length` bytes arrive | `NetworkError` | The connection closed before the body ended. |
| The net permission is not granted | `NotCapable` | Requires net access, run again with the --allow-net flag |

These failures reject the promise of the check that hit them. A process that is not packaged does not hit them.

## Distribution

The tag's workspace `version` is the same number without the leading `v`. A tag that does not match fails the run. The build is `cargo build -p yuzuko --release` with the default Cargo features, once for every triple in Platforms. The release build does not restore a Cargo cache. `x86_64-apple-darwin` is cross-compiled on the macOS arm64 runner. `aarch64-unknown-linux-gnu` is built on the Linux arm64 runner. The Windows binary keeps the static CRT from `.cargo/config.toml`.

## Architecture

```text
main thread
  winit event loop (N windows)     headless timer
         |                                |
         +------------ LoopDriver --------+
                        |
                   yuzuko_core
                   V8 isolate + cppgc
                   task queue, timers, microtasks
                        |
         +--------------+--------------+
         |              |              |
   yuzuko_window   yuzuko_canvas   yuzuko_webgpu
   Window           vello_gpu/cpu   wgpu WebGPU
   pointer/key/IME       \          /
                          wgpu Device
```

The main realm's isolate stays on the main thread. A dedicated worker runs on its own thread and enters only its own isolate. winit stays on the main thread. wgpu stays on the thread that created the device. Other background completions are posted to a task queue and wake that realm's event loop. Only the main thread touches winit.

There is one V8 platform per process. Posting a foreground task always hits the waker. Timer delays do not spawn an OS thread per timer.

Crates:

| Crate | Role |
| --- | --- |
| `yuzuko` | CLI. `run`, `test`, `package`, and `repl`. Calls each enabled extension's `install`. Links a feature crate only when that Cargo feature is on |
| `yuzuko_core` | Isolate, platform, event loop, module loader (`oxc_resolver`, oxc type erasure), extension trait, timers, console, exception conversion. The `fs` feature compiles the `Yuzuko` file system. The `udp` feature compiles `Yuzuko.listenDatagram`. The `tcp` feature compiles `Yuzuko.listenTcp` and `Yuzuko.connectTcp`. The `http` feature compiles `Yuzuko.listenHttp`. The `signal` feature compiles `Yuzuko.addSignalListener`. The `child` feature compiles `Yuzuko.spawn`. The `ffi` feature compiles `Yuzuko.dlopen` |
| `yuzuko_dom` | `EventTarget`, event classes, and `AbortController`. The `window` feature installs pointer and key events. The `fetch` feature installs `EventSource`. The `socket` feature installs `WebSocket`, `WebSocketStream`, and `WebTransport` |
| `yuzuko_winter` | URL, encoding, Blob, crypto, streams. The `fetch` feature compiles the HTTP client. The `socket` feature compiles `WebSocket` and `WebTransport` |
| `yuzuko_window` | `Yuzuko.Window`, winit, input mapping, IME, pointer lock, keyboard lock, fullscreen. Compiled with the `window` feature. The `accessibility` feature compiles virtual and computed accessibility nodes and links AccessKit |
| `yuzuko_image` | Decoders and `ImageBitmap` / `createImageBitmap`. Compiled with the `image` feature |
| `yuzuko_canvas` | Canvas 2D and `bitmaprenderer`. Compiled with the `canvas` feature. `OffscreenCanvas` itself is installed by `yuzuko_window` |
| `yuzuko_webgpu` | WebGPU. Compiled with the `webgpu` feature |
| `yuzuko_audio` | Web Audio. Compiled with the `audio` feature |
| `yuzuko_codec` | WebCodecs and `Yuzuko.demuxMp4`. Compiled with the `codec` feature |

`yuzuko_core` does not depend on winit or wgpu. Feature crates depend on core, and the binary assembles the feature crates.

Host objects are allocated with cppgc so V8 owns their lifetime. GPU resources that have `destroy()` are destroyed explicitly and do not wait for GC.

## Risks

- A level A path or text operation that the rasterizer cannot draw throws `NotSupportedError` on both the GPU and CPU renderers. Do not switch that operation to a second 2D library. The render target stays sRGB unorm8. A `display-p3` or `float16` backing store is not a rasterizer target.
- winit IME differs by OS by more than the specification describes. Split event-sequence tests by OS.
- The WebGPU surface is the list in this file. Behavior outside that list is not implied.
